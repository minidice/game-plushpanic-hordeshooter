# 적용 인계 — 현재 게임 미적용

기준 조사: `D:/Project/Game/game-hordeshooter`의 2026-10-22 작업 중 상태. 다른 AI가 수정 중이므로 통합 시 최신 코드를 다시 확인한다.

## 1. 모델 파일만 먼저 복사

모델의 즉시 재사용을 위한 경로는 `game/assets/outdoor-kit`이다. 원 저장소에서 다른 AI 작업이 끝난 뒤 실행한다.

```powershell
# 확인만: 아무 파일도 만들지 않음
pwsh -File ./Copy-OutdoorKit.ps1 -RepoRoot 'D:/Project/Game/game-hordeshooter'
# 위 경로에 새 모델 폴더만 복사. 이미 있으면 중단하며 덮어쓰지 않음.
pwsh -File ./Copy-OutdoorKit.ps1 -RepoRoot 'D:/Project/Game/game-hordeshooter' -Apply
```

35개 파일(32 GLB + manifest + 검수용 shader 2개)을 복사하고 SHA256을 확인한다. 기존 코드·맵·설정·문서는 수정하지 않는다. 폴더 복사 자체로 현재 맵 오브젝트가 교체되지는 않는다. Godot에서 GLB를 인스턴스화해 레벨에 배치할 수 있는 상태다.

원본을 버전 관리할 때는 이 독립 프로젝트의 `tools`, `source/outdoor-library.blend`, `preview`, `project.godot`, `gallery`와 `doc`도 `prototypes/outdoor-kit` 같은 별도 위치에 보존한다. Blender 원본의 그리드 위치는 편집 편의용이며 내보낸 GLB 루트는 원점이다. 생성 도구는 자신의 폴더를 기준으로 `pack`을 만든다.

## 2. 모델 계약

| 항목 | 계약 |
|---|---|
| 단위/축 | 미터, Godot/GLB +Y 위. Blender 원본은 Z 위 |
| 피벗 | 최하단이 y=0, 수평 중심 근처. 비대칭 부속으로 AABB 중심은 조금 다를 수 있음 |
| 기본 재질 | 불투명 PBR/색 팔레트, 외부 텍스처·베이크 조명 없음 |
| 유지 부위 | `Keep`: 줄기·기둥·하부·바닥. 일부 낮은 모델은 전부 Keep |
| 가림 후보 | `Occlude_*`: 수관 구역, 지붕, 상부 벽/난간. 이름은 manifest를 기준으로 읽음 |
| 메시 노드 | `<부위명>_Mesh`; 역할은 부모 노드에서 상속. 숫자 접미사를 부위 키로 사용하지 않음 |
| 충돌 | GLB에 물리 없음. manifest는 추천 종류/치수만 제공. compound는 배치자가 세부 프록시를 만드는 설명 |
| 지형 모듈 | 4×4m 바닥/수면, 울타리 3m, 경계석 4m. 피벗은 바닥 기준이라 윗면 높이를 맞춰 배치 |

나무 수관은 충돌을 만들지 않는다. 바닥/열린 컨테이너/창고는 진입·총알·길찾기를 별도로 설계해야 한다. 원 게임 `StageMap.Solid`/흐름장과 연결할 때 시각 메시 전체의 AABB를 그대로 장애물로 쓰지 않는다. 풀·갈대·수면에는 추천 충돌이 없다.

색 팔레트 기반 조형이며 커스텀 메시의 텍스처용 UV 아틀라스는 없다. 향후 정밀 문양/낙서/손상 데칼을 넣으려면 UV 또는 월드좌표 투영을 별도로 준비한다. 수목 바람 변형, LOD/HLOD/MultiMesh는 아직 제공하지 않는다.

## 3. 일부만 옅게 보이는 효과를 연결할 때

`pack/shaders/outdoor_preview.gdshader`와 `preview/preview.gd`는 **수동 검수 샘플**이다. `fade=0..1`, `wetness=0..1`, `snow=0..1`을 재질 인스턴스마다 사용한다. GLB 원본은 opaque 상태 그대로다.

1. 카메라→표시 대상의 가림 부위만 찾는다. 수관/지붕의 시각 가림 판정과 플레이어/총알 충돌·적 시야는 별도다.
2. 가까운 `Occlude_*` 구역만 전환하고 Keep은 유지한다. 한 나무의 변경이 같은 GLB를 쓰는 다른 나무에 번지지 않도록 인스턴스별 재질을 만든다.
3. 즉시 토글 샘플을 그대로 제품 정책으로 쓰지 말고 진입/해제 전환시간과 히스테리시스를 플레이로 결정한다. 다중 부위/다중 아군/카메라 확대도 확인한다.
4. 기존 C-23 `VisionSystem` 보임/실루엣/숨김 계약을 유지한다. 가리는 배경을 옅게 했다고 숨겨진 적을 강제로 표시하지 않는다.
5. 현재 디더 샘플은 그림자를 원형으로 유지한다. 그림자까지 옅게 할지, 숨겨진 지붕이 내부에 드리우는 그림자를 유지할지는 후속 아트 결정이다. 겹침/AA/멀티 카메라의 흔들림도 검수한다.

참고 API: [Godot Spatial shaders](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/spatial_shader.html). 현재 샘플은 Godot 4.7의 `IN_SHADOW_PASS`를 사용하며 이전 엔진 버전은 검증하지 않았다.

## 4. 시간·날씨·차량 후속

- 낮밤/석양: 원본에 색을 굽지 않았으므로 태양·환경광으로 바꿀 수 있다. 검수 프리셋은 게임의 시간/일몰 계산이 아니다. 가로등 발광 메시와 실제 Light3D/적 시야 빛 공유는 별도 연결.
- 비/눈: 젖음은 색/거칠기, 적설은 월드 상향 노멀 마스크로 표현한 샘플. 지붕 아래 차폐/누적/녹음/지면 웅덩이/눈비 입자/바람은 후속. 물은 불투명 수면이며 새 하천의 잔물결/광택은 시각 샘플이다. 물리/수영/굴절/실시간 환경 반사는 없다.
- 차량: **이번 팩에는 차량 모델/탑승/운전이 없다.** 향후 차체·바퀴·문/좌석/탑승점/배기/등화 소켓을 분리하고 실제 차폭·회전반경에 맞춰 길을 정한다. 현재 다리와 컨테이너 사이가 차량 주행 가능하다는 보장은 하지 않는다.
- 시나리오 Stage 2는 사용자 요청대로 야외를 고려한다. 실제 Stage 2 경로/목표/캠페인 연결은 제작하지 않았다. 생존/난전의 야외 선호를 시나리오 진행 규칙과 혼동하지 않는다.

## 5. 문서와 검사 병합

이 폴더의 `doc/decisions.md`, `doc/issues.md`, `doc/feature-checklist.md`는 **이번 팩 기록만** 담는다. 원 저장소 동명 파일에 덮어쓰지 않는다. 통합 시 A-7·L-13에 이번 검토/방향을 연결하고 I-80의 나무 가림 제약은 실제 통합 검사 후에만 갱신한다. 로컬 OUT-* ID는 패키지 내부 ID이며 원 저장소의 새 번호는 최신 기록을 확인한 뒤 발급한다.

게임 통합 시 코드·모델·도구와 원 저장소 decisions/issues 변경을 같은 커밋에 포함한다. 실제 통합 후 `MapCheck`, `VisionTierCheck`, 변경 맵 전용 검수와 기본/확대 카메라 렌더를 실행한다. `Start-Game.ps1 -Test`는 Integration만 실행하므로 대체 검사가 아니다. 6인/대량 나무/장시간/저사양 성능도 따로 측정한다.

## 6. 자연 하천 연결

`stream_straight`는 길이 8m, `stream_curve`는 중심선 반경 4m의 90도 굽이다. 수면 기준 y=0.24m, 둑 상단 y=0.62m. 각 `Connection_Start`/`Connection_End`의 위치·진행 방향·명목 반폭(1.45m)은 manifest에 있다. 양 끝의 수면/흙/잔디 단면은 동일하다. 연결 시 위치와 진행 방향을 함께 맞추고 동일한 높이·스케일을 사용한다.

검수 배치 예: 직선 위치 (0,0,2), 굽이 위치 (-2,0,-4) 및 Y축 90도. 양끝 연결부 외의 경사는 바위/풀과 주변 지형으로 이어 붙인다. 전체 지면을 수면보다 높게 깔면 물을 가리므로 하천 자리를 비워야 한다. 종단 마감은 별도 레벨 작업이다.

`StreamWater` 재질은 GLB의 정점색을 사용하므로 엔진 통합 시 이를 보존한다. 검수 물 셰이더도 `COLOR`를 사용한다. `preview_time`은 시각적인 잔물결 시간이며 게임 시간/유속이 아니다. 캡처에서는 0으로 고정해 비교를 재현한다. 둑의 젖은 색은 원본 팔레트이며 실제 강우/수위 반응이 아니다.
