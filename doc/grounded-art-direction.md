# 아트 방향안 — 진지한 공간 속 귀여운 동물

작성일: 2026-10-22

## 1. 사용자 의도와 문서 상태

사용자 출발점은 **덕코프의 캐릭터 느낌으로 친구들과 레포데 같은 협동 전투를 하고 싶다**는 것이다. 2026-10-22에 밝힌 선호는 **진지하지만 귀엽고, 실제 비율과 비슷한 느낌**이다.

- 이 선호와 문서 보존 요청은 사용자 발언에 근거한다.
- 아래 조형·재질·배치 방법과 제작 순서는 **제안**이다. 개별 수치와 최종 외형은 확정하지 않았다.
- 현재 게임에 적용된 변경은 없다. 모델 완성·게임 통합·성능 검증도 완료 상태가 아니다.
- 덕코프의 에셋을 가져오는 계획이 아니다. 형태·비율·재질·공간 구성 원리를 참고해 자체 모델을 만든다.
- 사용자의 “실제 비율”은 우선 **귀여운 캐릭터 체형을 유지하면서 장비와 주변 사물의 비율·구조가 납득되는 것**으로 해석했다. 실제 동물 해부학대로 바꾸라는 의미로 확정하지 않는다.

## 2. 방향과 현재 상태

**작은 동물은 담담하게 임무를 수행하고, 배경과 장비는 실제로 있을 법하게 구성한다. 귀여움은 둥근 체형과 진지한 행동의 조합에서 나온다.**

현재 거위 기본형과 군장은 상당 부분 재사용할 수 있다. 배경의 반복 형태·두께·배치·조명을 조정하는 효과가 클 것으로 판단한다. 기존 배경 규격의 “둥글고 두툼한 장난감 같은 저폴리”와는 강조점이 다르다. 기존 결정과 상세 규격은 아직 이 제안으로 대체하지 않는다.

검토한 자료는 저장 렌더 `game/output/surface-after-goose-gear.png`, `surface-after-species-pair.png`, `transition-7-forest.png`, `transition-7-yard.png`, `transition-6-arrival-close.png` 및 관련 모델 규격·애니메이션 코드다. `output/` 이미지는 재실행으로 생성하는 로컬 산출물이다. 최신 실행 화면이나 두 게임의 조작감을 직접 비교한 결과로 해석하지 않는다.

## 3. 캐릭터 변경 제안

| 항목 | 제안 | 보존할 것 |
|---|---|---|
| 기본 체형 | 대대적 교체보다 현재형을 기준으로 조정 | 둥근 몸, 짧은 팔다리, 거위·오리의 차이, 종별 윤곽 |
| 눈 | 돌출과 하이라이트를 줄인 안을 비교 | 게임 거리에서 읽히는 시선 |
| 표정 | 기본은 담담하게. 웃는 입 선과 과도한 입체 눈썹을 약화 | 랫서판다 흰 눈썹 무늬 등 종 식별 특징 |
| 부리·주둥이 | 몸과 연결되는 뿌리, 끝 두께, 광택 조정 | 거위의 좁은 부리와 오리의 넓은 부리 |
| 몸 표면 | 부드러운 무광과 절제된 명암 차이 | 명확한 색 영역과 커스텀 무늬 |
| 발 | 물갈퀴 테두리·층 두께를 정리하고 접지 확인 | 짧고 귀여운 발, 발바닥 기준점 |

털·깃털 미세 디테일, 높은 폴리곤 수, 모든 종 동시 개편은 첫 작업의 우선순위가 아니다. 현재 거위를 기준으로 다른 종의 표정 강도를 맞추는 순서가 적절하다.

## 4. 군장과 무기 변경 제안

| 대상 | 제안 | 판단 기준 |
|---|---|---|
| 헬멧 | 테두리·부착물 두께와 머리 위 착용 위치 조정 | 장식이 아닌 착용 장비로 보이는가 |
| 조끼 | 아래를 두르는 기존 형태와 어깨끈·가슴판·옆면 연결이 있는 형태 비교 | 몸을 보호하는 구조가 납득되는가 |
| 파우치 | 탄창용·보조용 크기와 간격 구분 | 같은 상자를 줄세운 느낌이 줄어드는가 |
| 배낭 | 등판 밀착과 어깨끈 연결, 몸과의 간격 조정 | 몸이 배낭 무게를 지는 것처럼 보이는가 |
| 총기 | 기존 현실 총기 윤곽 유지, 손·손잡이·몸·개머리판 관계 정리 | 실제로 잡고 지탱하는 자세인가 |
| 표면 | 천은 무광, 금속은 제한된 반사, 고무는 둔한 표면 | 같은 색이어도 재질이 구별되는가 |

흠집·때를 늘리기 전에 크기·두께·연결·착용 위치를 맞춘다. 무기 교체를 위해 총과 군장은 별도 부품으로 유지한다.

## 5. 배경 변경 제안

| 대상 | 현재 저장 화면의 인상 | 변경 제안 |
|---|---|---|
| 나무 | 두꺼운 잎 층과 반복되는 실루엣 | 줄기·가지 노출, 수관 빈틈·비대칭. 높이뿐 아니라 수관 폭·가지 시작점·기울기 변화 |
| 바위·절벽 | 비슷한 기둥이 줄지어 담장처럼 보임 | 큰 암반 중심으로 작은 돌·흙 경사를 연결. 높낮이와 매립 깊이 변화 |
| 지면 | 넓은 녹색·갈색 면 | 다져진 길·흙 가장자리·풀 밀집·맨땅 구분. 통행 흔적은 필요한 위치에 배치 |
| 시설물 | 두꺼운 판재와 깨끗한 모서리 | 철판·간판·울타리는 얇게, 콘크리트는 무겁게. 문틀·경첩·잠금 구조를 먼저 표현 |
| 소품 배치 | 개별 물건이 떨어져 진열된 느낌 | 하역장에 상자, 작업 구역에 드럼통, 울타리 밑에 풀처럼 용도와 환경에 따라 묶기 |

### 크기 관계

문·컨테이너·드럼통·방벽·캐릭터를 같은 장면에서 비교한다. 하나의 기준 크기를 잡고 상대 비율을 맞춘다. 현재 엔진의 미터 값과 화면의 설득력을 혼동하지 않는다. 캐릭터를 실물 오리 크기로 줄이는 결정을 하지 않는다.

문 통과 여유, 방벽 높이, 화물 시설의 크기를 일관되게 맞추되 협동 전투 통로·적 가독성은 확보한다. 시각 모델의 변경만으로 기존 이동·피격 캡슐과 길 폭을 자동 변경하지 않는다.

## 6. 빛·색·재질 제안

- 공터의 햇빛과 수관·시설 사이 그늘을 구분한다. 전체를 어둡게 만드는 방식으로 진지함을 대신하지 않는다.
- 발밑·소품 밑·벽과 땅의 접촉부를 자연스럽게 표현한다.
- 풀·천·철판·콘크리트가 같은 파스텔 재질처럼 보이지 않게 반사와 색을 구분한다.
- 먼 숲은 대비·채도를 줄이고 가까운 전투 공간은 읽히게 한다.
- 빨강·노랑 같은 강조색은 위험물·상호작용 대상에 집중하되 적·팀원의 식별력을 유지한다.
- 낡음은 모서리·바닥 가까운 부분·자주 만지는 곳 등 원인이 있는 위치에 배치한다.

## 7. 움직임과 카메라 — 게임 통합 이후 검토

현재 `CharacterRig.Animate`에는 발 왕복·몸 상하·뒤뚱거림·피격 변형·머리 스프링이 있다. 구조를 활용할 수 있으나 원하는 체감인지 직접 비교해야 한다.

- 이동 속도와 보폭·발걸음 주기를 맞춰 미끄러짐을 줄인다.
- 평상시 몸·머리 흔들림의 강도를 비교하고, 정지 시 짧게 안정되게 한다.
- 조준 시 자세를 안정시키고 사격 반동은 짧고 분명하게 전달한다.
- 캐릭터 화면 크기·카메라 각도·거리와 발밑 그림자를 함께 비교한다.
- 걷기 → 정지 → 방향 전환 → 조준 사격을 같은 조건에서 촬영한다.

현재 멀티플레이 작업과 분리하기 위해 이 단계의 런타임 코드 수정은 모델링 작업에 포함하지 않는다. 기존 물리 몸개그·카드 효과의 삭제나 장르 변경도 이 문서에서 결정하지 않는다.

## 8. 제작 순서 제안

1. **기준 장면:** 거위와 문·컨테이너·드럼통·나무를 같은 조명·카메라로 비교. 상대 크기를 먼저 확인한다.
2. **첫 모델 묶음:** 기존 거위 체형을 기준으로 헬멧·조끼·파우치·배낭 개선 후보를 만든다. 정면·측면·후면·실제 플레이 크기로 검토한다.
3. **숲길 한 구간:** 나무·암반·지면·소품 배치를 작은 장면에서 완성한다.
4. **확장:** 검토한 기준을 다른 종과 스테이지에 적용한다. 게임 통합은 별도 작업으로 진행한다.

세부 크기 감소율·색·폴리곤 예산은 덕코프에서 측정한 값이 아니며 아직 확정하지 않았다. 초기 모델 검토에서 비교 후 정한다. 품질 목표와 성능 예산은 [성능 목표안](performance-targets.md)을 참고하되 완성 모델의 실제 측정으로 확인한다.

## 9. 병행 작업 경계

사용자는 다른 AI가 멀티플레이 코드를 수정 중이라고 알렸다. 확인 시 `game/scripts/Net/`, `game/scripts/World/Stage.cs`, `game/tests/PartyNetCheck.*`에 작업 중 변경이 있었다. 이 목록은 시점별 상태이며 고정된 소유 목록이 아니다.

- 새 모델링 작업 위치: [`prototypes/grounded-art/`](../prototypes/grounded-art/README.md).
- 해당 폴더 밖 기존 생성기·GLB·게임 코드·설정·테스트를 모델 제작 과정에서 덮어쓰지 않는다.
- 기존 파일은 참고용으로 읽고 필요한 원본은 새 폴더에 복사한다. 복사본이 기존 파일을 출력 대상으로 참조하지 않는지 검사한다.
- 원본·생성 도구·완성 후보 GLB·manifest는 버전 관리할 위치에 둔다. 렌더와 임시 산출물은 폴더 내부 `output/`에 둔다.
- 새 모델은 검토용 후보이며 기존 `.tres`에 연결하지 않는다. 게임 쪽 자동 가져오기·빌드도 이 단계에서는 필요하지 않다.
- 별도 폴더는 파일 충돌을 줄이지만 Git 인덱스·브랜치까지 분리하지는 않는다. 전체 파일 stage, 공유 브랜치 전환, 다른 작업 변경의 되돌리기를 하지 않는다.

## 10. 검토 기준과 현재 기록

완료 판단 질문: **캐릭터를 가리면 실제로 있을 법한 숲길·시설이고, 캐릭터를 다시 보면 진지하게 무장한 모습이 귀엽게 느껴지는가?**

모델 단계에서는 고정 조명·같은 카메라의 전후 비교, 상대 크기, 피벗·축·노드·재질, 게임 크기 가독성을 확인한다. Blender 등 외부 렌더의 성공을 Godot 적용 완료로 간주하지 않는다. 통합 시에는 캐릭터 계약, 군장 분리, 손·무기 연결, 가림 처리, 실제 게임 렌더, 멀티 표시와 성능을 별도로 검사한다.

2026-10-22 문서 저장 작업은 제안과 작업 경계 보존이다. 코드·게임 동작·기능 현황은 바뀌지 않아 기존 결정 ID·이슈 ID를 새로 발급하거나 완료 처리하지 않았다. `decisions.md`와 `issues.md`를 확인했으며, 향후 실제 기능·동작 수정 시 저장소 규칙에 따라 같은 작업에서 함께 갱신한다.
