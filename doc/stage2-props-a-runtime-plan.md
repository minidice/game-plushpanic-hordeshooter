# Stage 2 묶음 A 게임 연결 계획

> 실행: `superpowers:executing-plans`로 같은 작업 폴더에서 순서대로 구현하고 마지막에 독립 코드 리뷰한다. 사용자 요청은 모델 연결과 실제 렌더 검수까지다.

**Goal:** 사다리·짚라인·곤돌라 GLB를 실제 이동 장치에 연결하고 높이·가림·6인 승하차를 검증한다.
**Architecture:** `PropLibrary`에 팩을 등록하고 기존 이동 장치가 시각 노드를 소유한다. 충돌/흐름장은 기존 지형이 소유한다. 짚라인의 줄과 탑승자는 같은 곡선을 사용한다. 곤돌라는 두 승강장과 한 객차를 가지며 도착 시 객차도 도착 위치에 놓는다. 가림은 묶음 A의 `Occlude_*`에만 적용한다.
**Tech Stack:** Godot 4.7.2 .NET, C#, Blender 5.2 Python.
**Spec:** [모델 브리프](model-briefs/stage2-landmarks.md), [높이 단](elevation-tiers.md) 5·11·14장, [자산 검수](stage2-props-a-validation.md).

## 제약과 구현 판단

- 1단 1.2m, 짚라인 도르래 `(0,3,-0.4)`, 객차 바닥 윗면 0m를 유지한다.
- 기존 Stage 2를 시안으로 바꾸거나 묶음 B/C를 만들지 않는다. 테스트는 `LayoutMap`의 실제 장치를 사용한다.
- 기존 임시 도형 위에 모델을 겹치면 바닥 중복과 줄 높이 불일치가 생기므로 도형을 교체한다. 모델 전체를 옅게 하면 바닥도 흐려지므로 `Keep`는 유지한다.
- 구현 판단: 객차 ±X 벽 중앙에 폭 1.6m 출입구를 낸다. 기존 닫힌 벽을 통과하는 외형을 피하면서 4×4m 탑승 영역을 유지한다.
- 구현 판단: 탑승 판정은 몸이 바닥 안에 들어오고 같은 바닥 높이에 있을 때만 참이다. 일회 이동 완료 후 출발 장치 재사용을 막는다.
- 기존 기본 카메라를 유지한다. 연출 중 실제 지형이 가짜 배경을 덮는지는 렌더에서 확인하고 필요하면 연출 동안만 시각을 분리한다. 멀티 동기화는 이번 완료 범위가 아니다.

## 검사에서 놓치기 쉬운 조건

다른 방향의 사다리 손잡이, 짚라인 중간 처짐과 줄/몸 간격, 다른 높이에 서 있는 생존자의 잘못된 탑승 판정, 6인 중 한 명 미탑승, 정지된 세계에서 가림 갱신/도착 후 복구를 검사한다.

## 실행 기록

- 시작 기준 `29c3121`. 기존 사용자 요청에 따라 기본 작업 폴더를 유지한다. 추적 파일 변경 없음, 첨부 폴더는 제외한다.

- 완료: 팩 미등록 실패와 배경 가시성 실패를 재현 후 수정. 최종 전용149/창 모드163·높이 단76·시안74·전환172·통합149 통과, 실제 렌더14장 검수. 독립 리뷰의 숨김 상태 유지·이동 중 제거 복구·가림 해제 제안을 검사에 반영했다.
- Ruling: 첫 게임 렌더에서 지면이 가짜 협곡을 가려 연출 중에만 주변 외형을 숨기고 복구한다. 객차 외형 +0.012m로 지면과의 깊이 충돌을 피한다. 물리/흐름장은 유지한다. 범위/경고/재현은 [검수 기록](stage2-props-a-validation.md#게임-연결-검수-2026-10-23)에 남겼다.
