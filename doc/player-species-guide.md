# 플레이어 동물 — 종별 외형과 추가 기준

> 현재 아트 목표(2026-10-25): [매끈한 데포르메 동물과 입체적인 장비](character-art-direction.md). 몸의 봉제선·솜/패딩·구슬 부품을 공통 스타일로 권하지 않는다. 기존 모델 구현과 앞으로의 스타일 보정은 구분한다.

기준일: 2026-10-20. 현재 구현된 네 종의 특징과 새 종을 만들 때의 확인 항목을 정리한다. 구체적인 조형·색 수치는 조정 가능한 현재 기본형이며 최종 아트 확정값은 아니다.

- 이 문서: 플레이어 종의 외형 정체성, 커스텀 시 보존할 특징.
- [몬스터 가이드](monster-design-guide.md): 적의 외형 테마, 공격 역할, 플레이어 모델 재사용.
- [모델 기술 규격](character-model-spec.md): GLB 노드·피벗·재질·저장·검사 계약. 구현 수치의 상세 기준은 이 문서를 따른다.

## 1. 공통 방향

- 귀엽고 우스꽝스러운 둥근 체형. 머리와 몸통은 목이 두드러지지 않는 일체형 느낌, 팔다리는 짧게 유지한다.
- 기본 쿼터뷰에서 먼저 읽히는 큰 윤곽과 색 영역을 우선한다. 확대하면 귀 테두리·주둥이·부리와 무늬 경계가 매끈하게 보여야 한다.
- 종 구분은 색 하나에 의존하지 않는다. 사용자가 색을 바꾸거나 모자를 씌워도 얼굴 윤곽·부리/주둥이·꼬리가 구분 단서를 남겨야 한다.
- 커스텀은 외형만 바꾼다. 몸 크기 슬라이더로 피격 캡슐·능력치를 바꾸지 않는다. 기본 프리셋은 종 특징이 잘 보이는 기준점으로 유지한다.
- 장비는 별도 부품이다. 총은 손잡이와 손을 연결하며, 모자·조끼·배낭을 착용한 상태에서도 얼굴과 동작이 읽혀야 한다.
- 보행·저공 도약·사격·피격·사망 변형에서 부품이 분리되거나 무늬가 깨지지 않는지 확인한다. 현재 사망 물리는 단일 캡슐 기반이며 자유로운 연체 변형을 지원한다는 의미는 아니다.

## 2. 네 종 비교

| 종 / ID | 가장 먼저 읽힐 특징 | 얼굴·귀 또는 부리 | 몸·꼬리 | 피해야 할 표현 |
|---|---|---|---|---|
| 라쿤 / `raccoon` | 옆으로 이어지는 검은 눈띠 | 관자놀이 쪽으로 올라가는 눈띠, 밝은 주둥이, 짧고 둥근 귀 | 회색 몸·밝은 배, 둥근 곡선의 줄무늬 꼬리 | 검은 원 두 개를 붙인 안경형 무늬, 납작한 귀 판, 각진 색 경계 |
| 랫서판다 / `redpanda` | 붉은 털과 넓게 연결된 흰 볼 | 흰 볼·턱, 짧은 적갈색 눈 아래 무늬, 둥근 흰 입체 눈썹, 라쿤보다 높고 삼각형에 가까운 귀 | 붉은 몸·짙은 배/앞발, 라쿤보다 긴 기본 줄무늬 꼬리 | 라쿤 눈띠 재사용, 길고 검은 눈물 자국, 눈썹 페인트와 입체 눈썹 중복 |
| 오리 / `duck` | 넓고 납작한 부리와 짧은 몸 비율 | 거위보다 넓은 부리, 둥근 얼굴, 포유류 귀 없음 | 기본 황갈색 몸·밝은 배, 날개·물갈퀴 발·짧은 깃털 꼬리 | 거위와 색만 다른 같은 윤곽, 포유류 주둥이·귀 부착 |
| 거위 / `goose` | 오리보다 세로로 긴 몸과 좁은 부리 | 얼굴부터 몸까지 이어진 세로 윤곽, 오리보다 좁은 부리, 포유류 귀 없음 | 기본 미색 몸·밝은 배, 날개·물갈퀴 발·짧은 깃털 꼬리 | 실사처럼 길고 가는 목, 오리와 부리 폭까지 같아지는 기본형 |

여기서 라쿤은 현재 코드의 `raccoon`이다. 대화에서 사용한 ‘너구리’를 별도 종으로 자동 추가하지 않는다. 실제 너구리 종을 추가하게 되면 라쿤과 다른 ID·특징표를 먼저 작성한다.

## 3. 기본 팔레트와 커스텀

현재 기준은 [AppearanceCatalog](../game/scripts/Characters/AppearanceCatalog.cs)의 `Palette`다. 아래 색은 기본값이며 사용자의 다른 색 조합을 제한하지 않는다.

| 종 | 주색 | 보조색 | 얼굴 무늬색 |
|---|---|---|---|
| 라쿤 | `#78858a` 회색 털 | `#e8e5dc` 밝은 배·얼굴 | `#30383b` 눈띠 |
| 랫서판다 | `#aa4b2c` 붉은 털 | `#382e2a` 짙은 배 | `#f3e4cb` 흰 볼·눈썹 |
| 오리 | `#bb7934` 황갈색 | `#edbd68` 밝은 배 | 없음 |
| 거위 | `#e5e1cf` 미색 | `#f5ebd0` 밝은 배 | 없음 |

- 랫서판다 눈 아래 무늬색은 주색과 보조색을 선형 공간에서 50:50 혼합한다. 고정 갈색을 덧씌우지 않는다.
- 라쿤·랫서판다는 얼굴 탭에서 무늬 경계 번짐 0~100%(기본 25%)를 편집한다. 저장 키는 `marking_softness`. 눈 간격 변경을 따라 무늬도 이동한다.
- 귀는 기본/둥근/뾰족한/접힌 모양과 크기·기울기를 편집한다. 기본 귀는 종마다 다르며 모자 착용 시 접힘을 확인한다.
- 꼬리는 기본/풍성한/길고 가는/짧고 둥근/말린 모양을 제공한다. 기본형의 종 특징과 사용자가 고른 변형을 구분해서 평가한다.
- 부리·주둥이, 눈, 체형, 발, 머리털, 장비를 편집하고 종별로 저장한다. 팔/날개 색은 몸 팔레트를 따라가며 독립 색 채널이 아니다. 상세 연결은 [모델 규격 7장](character-model-spec.md#7-종족별-커스텀-작업실)을 따른다.

## 4. 새 종 추가 순서

1. 아래 양식으로 기존 네 종과 구분되는 기본 윤곽·얼굴·꼬리를 먼저 적는다. 아직 구현하지 않은 항목은 `계획`으로 표시한다.
2. 무장하지 않은 정면·쿼터뷰·후면에서 특징을 확인하고, 실제 게임 크기로 축소해서 비교한다.
3. [모델 기술 규격](character-model-spec.md)에 따라 모델과 `.tres`를 등록한다. **목록에 등장하는 것과 커스텀 전체 지원은 별개**다. 현재 `AppearanceCatalog.IsBird`, 팔레트, 얼굴 마스크, 귀·꼬리 생성에는 종별 분기가 있으므로 새 ID의 처리를 각각 확인한다.
4. 생성기·최적화의 부품 보존, 런타임 귀/꼬리, 얼굴 셰이더, CPU 참고식, 프리셋·언어·저장을 점검한다. GLB만 복사하면 런타임 외형 보정까지 옮겨지는 것은 아니다.
5. 장비·무기 파지와 커스텀 최솟값/최댓값, 기본 복원, 종 전환, 저장·불러오기를 검사한다. 적으로 재사용하면 별도로 [몬스터 가이드](monster-design-guide.md)에 등록한다.
6. 실제 렌더와 검사 결과를 기록하고 이 문서·결정·이슈·기능 현황을 갱신한다. 새 종 등록만으로 검사가 자동으로 그 종까지 확인한다고 가정하지 않는다.

### 새 플레이어 종 작성 양식

| 항목 | 작성 내용 |
|---|---|
| 이름 / 고유 ID / 상태 | 계획·제작 중·게임 적용·검증 완료를 구분 |
| 기존 종과의 차이 | 기본 크기에서 보이는 핵심 특징 2~3개 |
| 체형 / 얼굴 / 귀·부리 / 꼬리 | 기본 윤곽, 무늬 배치, 피해야 할 표현 |
| 색 채널 | 주색·보조색·무늬색과 함께 바뀌는 부위 |
| 커스텀 / 장비 | 가능한 부위, 기본 프리셋, 장비로 가려지는 특징 |
| 구현 경로 | 정의·GLB·생성기·종별 런타임 처리 |
| 검증 / 남은 제약 | 실행한 검사·캡처 위치·미검증 상태 |

확인 경로: `CharacterSurfaceCheck`, `CustomizationToneCheck`, `ModularCustomization`, `WeaponGripCheck`, `ReloadPoseCheck`, `TailMeleeCheck`, `HitFlashCheck`. 필요한 장면과 새 종 검사 항목을 선택하며 실제 렌더를 함께 확인한다. 장전은 [무기 규격 6.1](weapon-spec.md#61-손총-장전-모션-2026-10-20)에 따라 `CaptureReloadPose`로 기본형·장비형을 비교한다. 최초 문서 정리에서는 게임 검사를 다시 실행하지 않았으며, 이후 장전 추가 검증은 I-55에 별도 기록한다.

## 2026-10-26 현행 모델 점검

[4종 실제 렌더 점검·후속 우선순위](player-art-audit-2026-10-26.md). 기본 형태/종별 정체성과 커스터마이징을 유지하면서 랫서판다의 얼굴·귀·손발부터 개선하는 안을 권고했다. 이번에는 점검만 수행했으며 새 조형 적용은 미완료다.

### 랫서판다 후속 적용 (2026-10-26)

사용자 승인으로 얼굴·귀·손발을 Blender에서 다듬어 `redpanda-clean.glb`로 연결했다. 몸/얼굴 무늬 좌표·종별 저장·귀/꼬리 선택·체형·색·장비는 보존한다. 새 손은 기존 `CharacterLionPaw` 고정 비율 손/별도 전완 경로를 사용한다. 위 점검은 수정 전 이력이며 현행 결과와 검사·한계는 [랫서판다 검수](redpanda-clean-forms.md)를 따른다.

### 라쿤 후속 적용 (2026-10-26)

다음 개선 순서로 라쿤의 짧고 넓은 주둥이·작고 둥근 오목 귀·작은 손·얇은 발목/평평한 밑면을 적용했다. `raccoon-clean.glb`와 기존 고정 비율 손 경로를 사용하며 몸 마스크 좌표·가로 눈띠·종별 저장/커스텀·장비는 보존한다. 손은 기존 라쿤 무늬색을 따른다. [제작/코드·실행 검증·한계](raccoon-clean-forms.md).

### 두 포유류 긴 꼬리 (2026-10-26)

라쿤·랫서판다의 긴 스타일0/1/2/4는 중간 부풀음을 줄이고 완만한 곡선과 끝으로 이어지는 지연 굽힘을 적용했다. 짧은 스타일3·조류, 크기/색/스타일 저장과 줄무늬 채널을 유지한다. [Blender·Studio·실제 Stage2 검증과 제약](mammal-tail-quality.md).
