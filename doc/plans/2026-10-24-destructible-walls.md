# 파괴 벽·폭발 데이터 구현 계획

> 실행: superpowers:executing-plans / 독립 모델 작업 병행. 사용자 요청에 따른 구현이며 별도 설계 승인 완료로 표현하지 않는다.

**목표:** 현재 로컬 게임 데이터로 총탄/폭발 파괴 조건과 자체 폭발 여부를 게임/Studio에 연결하고, 참고 이미지의 금 간 콘크리트 패널·붕괴 과정·잔해를 실제 맵에 배치한다.

**기준:** `git pull --ff-only`로 78f8856 → 6b284f2. 기존 C-29의 ObjectBody, BreakableBy, 네트워크 파괴 이벤트, 흐름장 해제를 확장한다. Godot C# 절차적 모델은 게임과 Studio가 같은 생성기를 사용한다. 별도 브라우저용 모델이나 외부 배포 없음.

**구현 선택:** 참고 이미지의 콘크리트 패널 벽, 중앙 큰 균열·깨진 단면·철근·바닥 잔해. 신규 벽은 폭발로만 파괴(임시 내구도60), 자체 폭발 없음. 기존 모래자루는 총/폭발·50 유지. 드럼통은 총/폭발·임시 내구도10, 기존 반경4.6/피해125/충격140/지연0.12를 데이터로 이동. 일반 방벽 무적 유지. 강도 타입과 누적 내구도를 혼동하지 않는다.

## 집중 확인

- 파괴 벽 뒤의 기존 보이지 않는 벽이 통로를 계속 막지 않는가.
- 파괴 시 흐름장 재생성과 좌우 영구 충돌이 일치하는가.
- 드럼통 연쇄 도중 컬렉션을 수정하거나 폭발이 재귀 중복되지 않는가.
- 원격 파괴/늦은 합류에 피해가 중복 적용되거나 멀쩡한 벽이 남지 않는가.
- 웹에서 미연결을 파괴 불가로 오인하지 않으며 원본 파일을 바꾸지 않는가.
