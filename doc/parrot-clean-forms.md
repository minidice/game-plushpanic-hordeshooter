# 앵무새 — 매끈한 데포르메 형태 적용

2026-10-25. 사용자 요청: 방향 정정 후 앵무새부터 작업. [현재 아트 기준](character-art-direction.md), A-25·D-5·C-31을 따른다. [1차 앵무새 검수](parrot-quality.md)는 이전 구현의 이력이다.

## 범위와 유지 계약

- 흰 눈 테두리/별도 반짝임, 좁은 목 위 둥근 머리, 봉제 배 패널, 두툼한 타원 발과 둥근 파우치를 우선 재검토한다. 매끈한 머리–몸, 작은 검은 눈, 넓고 짧은 갈고리 부리, 끝이 읽히는 볏·날개, 얇은 새 발과 입체적인 조끼를 목표로 한다.
- 색 테마와 공통 재질 채널, 노드/피벗, 무기 그립 경로, 충돌·전투 수치는 유지한다. 참고 이미지에 등장해도 투구·눈 장구류를 추가하지 않는다. 다른6종 GLB와 플레이어 모델은 보존한다.
- 현재 구현 방식인 피벗/전체 날개 변환을 사용한다. 새 스켈레톤·손가락·경사면 발 IK는 추가하지 않는다. 미술 변경이 기존 전투 판정이나 네트워크 정체성 변경으로 이어지지 않게 한다.

## 비교와 재현

이번 기준은 `8f73b44`의 앵무새 GLB이다. `prototypes/common-monsters/output/parrot-clean-forms/before.glb`와 `baseline-hashes.json`에 원본과7종 해시를 보존한다. 기존 `parrot-quality` 증거는 덮어쓰지 않는다.

Blender `review_parrot.py -- --species parrot --review-name parrot-clean-forms --label before`/`after`, `parrot_contact_sheet.py --species parrot --review-name parrot-clean-forms`. 선택 생성은 `build_common_monsters.py -- --species parrot --no-render`, 독립 검사는 `validate_common_monsters.py -- --species parrot`. Python 오류를 놓치지 않도록 Blender `--python-exit-code 1`을 함께 사용한다.

Godot import/Debug 빌드 후 `ParrotGripCheck.tscn`, Studio `STUDIO_SPECIES=parrot`의 `hunter-attacks.mjs` 및6무기 정지 렌더. 실제 게임 창은 `HunterCombatCheck.tscn -- --parrot-stage2`이며 이동·정지 렌더도 포함한다. 자동 입력/검수 위치 배치와 전체 맵 수동 완주를 구분한다.

Studio 증거는 `studio/output/parrot-clean-forms`, 실제 게임은 `game/output/parrot-clean-forms`와 `game/output/parrot-clean-*.log`. 자동 생성 산출물은 버전 관리하지 않는다.

## 현재 구현

- 머리/몸의 경계 단면과 표면 노멀을 맞추고, 머리 아래에는 안으로 숨긴125mm 연결부를 두었다. 별도 배 패널을 제거해 몸통은 하나의 닫힌 표면으로 구성한다. 보조색 채널은 꼬리에 유지한다.
- 흰 눈 테두리·별도 반짝임 구슬을 제거하고 작은 검은 눈으로 변경했다. 넓고 짧은 갈고리 부리, 큰 뾰족 볏·날개 끝, 얇고 평평한 새 발을 제작했다. 양쪽 발바닥 면적은 각각 약0.064758m², 바닥 아래 정점 없음. 정강이는 짧게 보정했다.
- 몸과 부리/발, 눈, 조끼의 재질 거칠기를 구분했다. 몸을 감싸는 조끼에 모서리를 둥글린 사각 파우치·뚜껑·여밈을 적용하고 어깨끈 끝은 조끼 안으로 넣었다. 기존 게임/Studio의 재질 색 교체 경로를 사용한다.
- 기본6,040→5,436삼각형, 조끼 포함6,900→6,684, 비활성 안경 포함7,264→7,048. GLB185,264→189,252바이트. 기본8천 미만이며 삼각형 감소를 FPS 향상으로 주장하지 않는다. 다른6종 GLB는 이번 기준 해시와 불변이다.
- 최종 SHA256: `0515e4b72dbec2f3e2e8732cb3f4b7dade3e2a60c35de4aa560b0cce22928aee`. 반복 내보내기에서 JSON/노드/재질/위치·노멀은 동일하지만 UV15개 값의 약5.96e-8 이하 반올림과 비활성 안경 삼각형 순서가 달랐다. 삼각형 구성/와인딩은 같으며 바이트 완전 결정적이라고 주장하지 않는다(`regeneration-comparison.json`). 최종 파일을 다시 import해 그립/머리 검사와 Stage2를 재확인했다.

## 확인한 문제와 보완

- 첫 Studio 시안에서 정강이가 길고 아래 부리가 검게 벌어진 인상이 보여 몸 하단/발목을 조정하고 아래 부리를 밝은 같은 부리 재질로 연결했다. 옆면에서 조끼 어깨끈 끝이 튀어나와 경로를 보정했다.
- 별도 머리 피벗의 기존 흔들림은 최대140mm 이동과 약12.8° 기울기를 허용했다. 새 연속형 목에서 이 변위를 적용한 Blender 렌더에 몸 윗면이 드러나는 큰 단차가 재현됐다. 연결부를 깊게 만드는 것만으로 가로 어긋남은 해결되지 않았다.
- `CharacterDefinition.HeadSpringScale`(0~1, 기본1)을 추가하고 앵무새 리소스만0.05로 설정했다. `CharacterRig`에서 스프링 상태 계산은 유지하고 표시되는 이동/기울기만 줄인다. 실제 가속·급반전·피격 충격 검사에서 앵무새 최대7mm/약0.64°, 독수리·사자는 기존140mm/약12.8°를 유지했다. 이 값은 아트 조정값이며 충돌·이동속도·전투 타이밍을 바꾸지 않는다.
- 최초 `ParrotMotionCheck`는 목 이동12mm 기준에 실패했고 설정/런타임 수정 뒤 통과했다. 생성 도구가 `.tres`를 다시 쓰면서 새 설정을 지울 수 있는 문제도 검토에서 발견했다. parrot 선택 생성에서만0.05를 출력하고 독립 재가져오기 검사에 설정 보존을 포함했다.

## 검증 결과

- Blender 선택 생성, 최종 GLB 독립 재가져오기69검사 통과. 같은 카메라/조명 전후22뷰와 머리 회전/이동 스트레스 렌더를 확인했다. 기존 배 패널 간격768표본 검사는 제거된 패널 대신 단일 연결/닫힌 몸 표면·목 경계·색 채널·평면 발바닥 검사로 바뀌었다. 검사 수 감소가 검증 실패를 뜻하지 않는다.
- 최종 새 머리 설정에서 `ParrotMotionCheck`9,642 반복 검증, `ParrotGripCheck`3,084, localhost ENet108 통과. HunterPose156·CommonRoster264도 통과했으며 해당2개는 머리 표시 배율 추가 전 실행했다. 머리 배율 추가 후 그립·전용 이동 검사·Stage2·Studio는 다시 실행했다.
- 실제 Stage2 창에서 추격 이동·정지·몽둥이/칼 명중·빗맞음·기절 취소·활 발사/취소와8장 렌더를 포함해38검사 통과. 입력을 자동 공급한 실제 게임 장면이며 전체 맵 수동 완주가 아니다.
- Studio 최종 황토색6무기 정지 렌더, 붉은색 수렵3무기 각12프레임·소리 API50검사 통과. 녹색 배색 추가 렌더와 기존 공통 재질 적용도 확인했다. 브라우저에서도 황토색 앵무새/나무활 공격 미리보기를 다시 생성하고 타임라인5의 준비 자세를 확인했다(`studio/output/parrot-clean-forms/browser-bow.png`). Studio용 별도 모델이나 외형 데이터는 만들지 않았다.
- Debug/ExportRelease 빌드 오류·경고0. 최종 전용/Stage2/네트워크 로그에 오류·종료 경고 없음. Blender `Material.use_nodes` 폐기 예정 안내는 남으며 정상 내보내기/검사와 구분한다. 독립 검토에서 발견한 목 단차·재생성 설정 유실을 수정했다.

## 남은 한계

머리와 몸은 스킨으로 이어진 단일 메시가 아니라 별도 피벗이다. 최대 반응의 확대 단색 렌더에는 얕은 접합선이 남지만 원래140mm 흔들림에서의 큰 노출 면은 제거했다. 날개도 기존 전체 회전·길이 조절 방식으로 개별 손가락/깃털 관절은 없다. 극단적인 외부 수동 머리 이동까지 연속 표면을 보장하지 않는다. 다른 종 스타일 전환·최종 사용자 아트 수락·전체 맵 수동 플레이·실제2PC/장시간 부하는 후속이다.
