# 프로젝트 용어 사전

> 작성·검토: 2026-10-20. 처음 읽는 사람과 AI가 같은 단위로 기획을 읽기 위한 문서.
> **확정된 범위**: 이번 레벨 길이·전투 배분·아이템 배치 추천안은 **시나리오 모드 전용**이다. 생존·서바이버 모드로 전파하지 않는다.
> **미확정 추천**: 콘텐츠 계층은 우선 **캠페인 → 스테이지** 2단계로 쓴다. 이는 이번 초안의 표기 기준이며, 출시 메뉴·저장 형식·코드 구조를 확정하거나 변경한 것이 아니다.

## 1. 먼저 구분할 것

```text
접속 방식: 싱글 / 멀티
게임 모드: 시나리오 / 거점 (Outpost, 구 생존) / 난전 (Onslaught, 구 서바이버) — 2026-10-21 이름 변경(decisions.md M-23). 코드 ID는 `Survival` / `Survivor` 그대로

시나리오 콘텐츠의 추천 계층:
캠페인 (하나의 여정)
  ├─ 스테이지 1 (출발 → 도착)
  ├─ 스테이지 2
  └─ 마지막 스테이지 (피날레)

스테이지 내부의 공간: 구역
스테이지 내부의 사건: 조우 / 웨이브 / 이벤트
```

싱글·멀티는 모드가 아니다. 시나리오를 싱글 또는 멀티로 플레이한다. 구역과 이벤트는 콘텐츠 선택 화면의 추가 계층이 아니다.

## 2. 용어와 사용 기준

| 용어 | 이 프로젝트에서의 의미 | 혼동하지 않을 것 |
|---|---|---|
| 시나리오 모드 | 출발점에서 목표를 거쳐 도착점으로 돌파하는 모드. 성장 레벨업 없는 방향(M-0b) | 캠페인 하나의 이름이 아님 |
| 거점 모드 (구 생존) | 인벤토리·파밍·거점 방어 중심의 별도 모드 계획 | 시나리오 피날레의 버티기 구간과 다름 |
| 난전 모드 (구 서바이버) | 시간 경과·레벨업·능력 선택 중심의 별도 모드 계획 | 거점 모드와 다른 모드 |
| 캠페인 | **추천 정의**: 같은 여정·주요 테마를 공유하는 여러 스테이지의 묶음. 마지막에 피날레 | 게임 전체, 시나리오 모드 전체, 한 맵을 뜻하지 않음 |
| 스테이지 | **추천 정의**: 시작·주요 목표·종료 조건이 있는 한 플레이 단위. 재시도·중간 휴식 경계를 설계하는 단위 | 실제 저장·이어하기·맵 연결 구현 여부와 별개 |
| 챕터 | **보류 용어**: 3단계가 필요해지면 캠페인 안의 여러 스테이지를 묶는 중간 단위 후보 | 현재 추천안에서 캠페인/스테이지의 동의어로 쓰지 않음 |
| 구역 | 거리·창고·야적장처럼 스테이지 안의 공간. 동선·등장·보급을 설계하는 단위 | 반드시 로딩하거나 저장하는 단위는 아님 |
| 맵 | 플레이 공간과 지형 배치. 현재 Stage 1은 한 스테이지의 맵 | Godot 장면 파일 하나와 항상 일치하지 않음 |
| 장면(Scene) | Godot의 `.tscn` 리소스. 메뉴·검사·캐릭터도 장면이 될 수 있음 | 모든 장면이 스테이지는 아님 |
| 레벨 디자인 | 공간·목표·전투·보급·페이싱 설계 | 캐릭터의 성장 레벨과 다름. 단독으로 “레벨 3”처럼 쓰지 말고 “스테이지 3” 또는 “성장 레벨 3”으로 구분 |
| 피날레 | 캠페인의 마지막 스테이지가 맡는 마무리 역할. 방어·목표 수행·탈출 등을 조합 가능 | 보스전이나 제자리 버티기와 동의어가 아님 |
| 조우 | 플레이어가 적과 마주치고 대응하는 한 상황 | 적이 많이 나오는 웨이브만 뜻하지 않음 |
| 웨이브 | 몰려오는 적 무리 또는 그 습격 단위 | “웨이브형”은 적의 반응 유형이며, 웨이브 시간 비율과 다른 개념 |
| 크레센도 이벤트 | 장치 작동·강제 돌파 등으로 의도적으로 압박을 높이는 주요 사건 | 맵마다 같은 위치·시간·방어 방식으로 반복할 의무 없음 |
| 페이싱 | 압박·이동·탐색·회복의 시간 흐름 | 적 체력·공격력 같은 난이도 수치와 구분 |
| 보급 지점 | 필요한 물자가 공간적으로 모인 장소. 선반·작업대·차량 옆 등. 데이터의 종류: 시작(세이프룸) / 주요(필수 경로) / 선택(탐색 보상) / 이벤트(큰 사건 보상) / 도착(세이프하우스, 다음 스테이지 몫) | 아이템 한 개, 무한 보급, 자동 회복을 뜻하지 않음 |
| 보급 예산 | 팀이 한 구간에서 얻을 수 있는 물자의 종류·수량·효용 | 장식 상자 개수나 배치 후보 자리 수와 다름 |
| 필수 경로 | 시작 → 주요 목표 → 출구를 잇는 진행 동선 | 선택 탐색·전투 중 후퇴와 구분. 거리 측정은 [기존 규칙](level-design-rules.md) 참조 |
| 세이프하우스 / 세이프룸 | 시나리오에서 안전하게 정비하는 공간. 기획 본문은 ‘세이프하우스’로 통일하고 기존 코드·고유 이름은 유지 | 영구 저장·체크포인트를 자동 보장하는 표현이 아님 |

## 3. 2단계면 충분한가?

| 비교 | 캠페인 → 스테이지: 현재 추천 | 캠페인 → 챕터 → 스테이지: 확장 후보 |
|---|---|---|
| 적합한 콘텐츠 | 한 여정을 여러 맵으로 끝냄 | 한 긴 여정에 서로 구분되는 지역·서사 묶음이 여럿 있음 |
| 예시(가칭) | 공장 탈출 캠페인 → 진입로 / 생산동 / 하역장 / 탈출 | 도시 탈출 캠페인 → 공장 챕터 / 주거지 챕터 → 각 챕터의 여러 스테이지 |
| 장점 | 설명과 번호가 짧고 현재 ‘스테이지 1’과 연결하기 쉬움 | 큰 콘텐츠의 중간 목표와 진행도를 묶기 쉬움 |
| 비용 | 대규모 장편에서는 묶음이 부족할 수 있음 | 선택·진행도·해금·저장 경계까지 세 단위의 역할을 설명해야 함 |
| 도입 조건 | 현재처럼 중간 묶음의 독립된 역할이 없을 때 | 복수 챕터마다 여러 스테이지가 있고, 챕터 완료가 별도의 의미를 가질 때 재검토 |

**현재는 2단계로 충분하다는 추천이다.** 한 스테이지 안에서 분위기가 바뀌는 장소는 ‘구역’으로 표현하면 된다. 챕터마다 스테이지 하나뿐이거나, 캠페인마다 챕터 하나뿐이면 중복 계층이 된다.

3단계로 확장할 때는 기존 스테이지의 의미를 유지하고 중간에 챕터를 추가한다. ‘캠페인 60~90분’을 ‘챕터 60~90분’으로 조용히 바꾸지 않는다. 총 플레이 시간·선택 화면·이어하기 정책을 함께 재검토한다.

## 4. 문서 일관성 규칙

- 이번 추천안의 “4~6개 스테이지, 60~90분”은 **캠페인 하나** 기준이다. 스테이지 시간은 별도다.
- ‘챕터’는 위 3단계 비교와 외부 레퍼런스 원문 설명에만 사용한다. L4D에서 말하는 개별 chapter는 이 초안의 ‘스테이지’에 대응한다.
- 예시는 “공장 탈출 / 스테이지 2: 생산동”처럼 쓴다. 실제 콘텐츠 ID·UI 이름을 새로 발급한 것으로 해석하지 않는다.
- 기존 기획의 “캠페인 코어 루프”는 시나리오 진행 방식을 설명하는 표현이다. 캠페인 선택·연속 진행이 이미 구현됐다는 뜻이 아니다.
- 게임 모드마다 같은 ‘스테이지’라는 단어를 쓸 수는 있지만, 시나리오의 길이·전투 비율·보급 예산을 공유한다는 뜻은 아니다.
- 확정 결정은 [결정 기록](decisions.md), 구현 여부는 [기능 체크리스트](feature-checklist.md), 숫자 추천은 [시나리오 레벨 디자인 목표](scenario-level-design.md)를 확인한다.
- 기술·장르 용어는 기존 [기획서 부록](idea.md#부록-a-용어집)도 참고한다. 콘텐츠 계층 용어는 이 문서를 기준으로 읽는다.
