# 이슈 기록 (버그 · 기술 문제)

> 지금까지 나온 버그와 기술 문제를 **원인과 해결**까지 모은 목록입니다. 같은 문제가 다시 생기면 여기서 먼저 찾아보세요.
> 기획 결정은 [`decisions.md`](decisions.md)에 있습니다.

**상태**: `해결` 고치고 검사로 확인함 · `열림` 아직 해결 안 됨 · `제약` 알고 있지만 당장 고치지 않는 한계

**새 이슈 추가 방법**
- 1장(열림·제약) 또는 2장(해결) 표에 한 줄을 추가합니다. ID는 마지막 번호 다음 번호입니다.
- 해결하면 2장으로 옮기고 "해결" 칸과 날짜를 채웁니다.
- 가능하면 회귀 검사(`game/tests/`)를 같이 추가하고, 그 검사 이름을 "검사" 칸에 적습니다.
- 재발 방지 조건과 근거 코드/상세 규격을 남깁니다. 추정 원인은 확인된 원인과 구분하고, 구현 완료·검사 통과·실제 플레이 품질을 같은 의미로 쓰지 않습니다.

**기록 갱신: 2026-10-20**. 아래 신규 해결 기록은 해당 작업 당시의 코드·전용 검사 로그·렌더와 현재 구현을 대조한 결과입니다. 최초 기록 정리에서는 게임 검사를 재실행하지 않았고, 이후 시체 정책 변경(I-39·I-40)은 별도 실행 검사와 성능 측정을 수행했습니다. 통합 검사만으로 모든 전용 검사를 실행했다고 기록하지 않습니다(3장).

### I-26 추가 검토: 시나리오 아이템 배치 (2026-10-20)

- **증상**: 사용자가 현재 아이템이 너무 널려 있어 보기 좋지 않다고 보고했다.
- **확인 / 추정 구분**: `StageOneLayout`의 여러 구역 고정 배치와 `WeaponPickup`의 링·부유·회전, 근거리 이름 표시를 코드에서 확인했다. 배치 분산·선택지 수·반복 강조가 어수선함의 원인일 가능성은 있으나, 각 영향은 렌더·플레이로 재검증하지 않았다.
- **대응 상태**: [시나리오 레벨 디자인 목표](scenario-level-design.md)에 보급 지점·선택지·물량을 구분한 미확정 추천안을 작성했다. 코드·배치 데이터는 수정하지 않았으며 **해결 전, I-26 열림 유지**다. 새 버그 ID를 중복 발급하지 않는다.
- **후속 검사 / 재발 방지**: 변경 전후 같은 위치의 기본·확대 카메라 렌더, 물자 발견·선택 가능성, 구간별 보유/소비/잉여, 사람·AI 구성별 충분성을 함께 기록한다. 초기 배치와 교체로 떨어진 무기를 구분하고, 문서 작성만으로 외형 개선·밸런스 검증 완료로 처리하지 않는다.
- **남은 제약**: 이번 검토는 시나리오 전용이다. 다른 모드의 경제·드롭률·성장 아이템에 적용하지 않는다. 게임 실행·렌더·4인 플레이 측정은 하지 않았다.
- **후속 반영 (2026-10-20, 같은 날)**: Stage 1 아이템을 보급 지점 데이터로 옮기고 첫 예산을 실험 적용(L-12, `scenario-level-design.md` 9장). 길 위 무기 13 → 4, 투척물 5 → 3, 셔터 제어판 옆 탄약 더미 제거. 전후 렌더 `output/supply-before-*` / `supply-after-*`(`SupplyCapture`), 배치 규칙은 `SupplyCheck`. **픽업 강조 표현은 바꾸지 않았고, 보급이 충분한지는 플레이로 확인하지 않아 I-26 열림 유지.**

### I-26 추가 검토: 탄약 부족 표시와 보급 지표 (2026-10-20)

- [무기 규격 6.2](weapon-spec.md#62-hud의-탄약-부족빈-탄창-표시-현재-구현-2026-10-20-확인)에 현행 HUD 조건을 기록했다. 탄창 잔탄만 확인하므로 경고가 잦다는 사실만으로 맵의 예비탄 보급 부족을 결론 내리지 않는다.
- **코드에서 확인한 한계**: 최소 기준 1발 때문에 1발 탄창은 만탄에도 ‘탄약 부족’, 예비탄 0발이어도 재장전 가능 여부와 관계없이 `[R]` 안내가 표시될 수 있다. 실제 화면 재현은 이번에 수행하지 않았다.
- **대응 / 상태**: 정의와 후속 경계값 확인 경로만 문서화했다. 문구·임계값·동작 수정은 하지 않았고 I-26 열림을 유지한다. 새 버그 ID와 해결 기록은 추가하지 않는다.
- **재발 방지**: 후속 UX 수정은 탄창 경고·예비탄 부족·AI 보급 조건을 구분하고, 임계값 양옆/0발/1발 탄창/무한 예비탄/장전 전환을 확인한다. 시나리오 보급 수치를 공용 HUD 규칙에 자동 반영하지 않는다.

#### I-68 — 감염체의 앞뒤가 동물 캐릭터보다 납작함 (해결, 2026-10-20)

- **증상/원인**: 사용자가 좀비의 앞뒤 두께 부족을 보고했다. 생성기의 머리 Z/X 반경 0.33/0.43(약 77%), 일반 몸통 0.29/0.36(약 81%)과 기존 GLB 정측면 렌더에서 확인했다. 동물 기본 몸체는 깊이/폭 86%이며, 감염체는 뒤통수·등의 볼륨이 부족했다. `CharacterRig`의 전체 모델 배율은 등방성이므로 런타임에서 앞뒤 축을 눌러 생긴 문제는 아니다.
- **해결**: `infected-models.mjs`에서 5종 `Head` 깊이를 18% 늘려 얼굴·후드·혀까지 함께 맞췄다. 인간형/끌개/덮치는 적 몸통 Z 반경 0.29 → 0.35, 토사물 적 0.34 → 0.40. 셔츠 장식과 토사물 적 배/배꼽을 새 표면에 맞췄다. 긴 크롤러 몸통은 유지했다. 게임용 GLB 5개와 보고서를 재출력하고 Godot 재가져오기를 완료했다.
- **재발 방지/재현**: 생성기 변경 후 `validate-game-roster.mjs`와 아래 전용 검사를 실행한다. `CaptureInfectedVolume.tscn`에서 장비 없는 라쿤과 5종을 동일 조건의 정면·정측면·후면·사선으로 비교해 두께, 눈·입 노출, 후드/의복 연결을 확인한다. `CaptureExpansion`으로 게임 크기도 확인한다. 재생성 명령과 수치는 [모델 규격 6.1](character-model-spec.md#61-앞뒤-볼륨-보강-2026-10-20-a-2i-68)에 있다.

## 4. 기록 운영 이력

- 2026-10-21 개편 5단계(M-26·L-13): 기능 추가라 새 버그 이슈는 없다. 작업 중 고친 것: 넣어 둔 무기의 충전이 끝나도 발사 간격 타이머가 넣어 둔 동안 줄지 않아 바로 쏠 수 없던 문제(`WeaponState.TickCooldown`이 발사 간격도 줄이게), 박격포를 든 채 화면 밖 화살표를 검사하면 카메라가 조준점 쪽으로 기울어 플레이어가 화면 가장자리에 있던 검사 준비 문제(검사에서 카메라를 플레이어에 맞춤), 화살표 목록은 그리는 순간 정해지는데 렌더가 느리면 물리 3틱이 한 그림 프레임 안에 지나 지난 목록을 읽던 검사 문제(그림 프레임을 기다리게). 모두 커밋 전.

- 2026-10-21 개편 3단계(A-17): Codex로 난전 보스 모델을 만들어 적용했다. 버그는 없어 이슈를 만들지 않았다. 확인한 한계: Codex가 넣은 `optimize_game_roster.py --boss-only`는 `--no-preview` 없이 돌리면 미리보기 단계에서 다른 모델도 불러온다(지금은 `--no-preview`로만 사용). 첫 근접 렌더는 잡몹 무리에 가려 다시 찍었다(검사 장면을 정리하고 재촬영).

- 2026-10-21 개편 2단계(T-21·M-24): 기능 추가라 새 버그 이슈는 없다. 창 모드 렌더에서 3페이즈 진입과 소환이 같은 순간이면 "페이즈 업!"과 "소환!" 글자가 겹쳐 읽히지 않아 페이즈 글자를 더 위로 올렸다(커밋 전 수정). 보스 연출의 멀티 제약은 I-77에 그대로 둔다.

- 2026-10-21 무기 개편 1단계(C-24~C-26, 관련 I-78): 기능 추가라 새 버그 이슈는 없다. 바뀐 동작에 맞춰 `Integration`의 박격포 검사가 거치 시간(0.8초)을 기다리도록 고쳤고, `NetCodecCheck`에 3번 칸 왕복을 넣었다. 프로토콜을 3으로 올려 이전 빌드와는 방 목록에서 "다른 버전"으로 잠긴다.

- 2026-10-21 생존·서바이버 1차 버전(M-22, 관련 I-77): 사용자 요청 기능 추가라 버그 이슈는 새로 만들지 않았다. 작업 중 검사 작성 실수 1건: 창 모드 `ModeCheck`에서 "내려찍기가 피해를 준다"가 실패했는데, 앞선 7초 대기 동안 보스가 스스로 한 번 내려찍어 `Slams == 1`이 스크립트 내려찍기 전에 통과한 것이 원인이었다(게임 버그 아님). 검사를 "호출 전 횟수 + 1"과 "보스가 다음 스킬 전 상태"를 기다리도록 고쳤다. `MenuCheck`·`LobbyCheck`의 "생존·서바이버는 잠김" 기대도 "열림"으로 바꿨다.

- 2026-10-21 공개 방 목록 검토(M-6, 관련 I-76): 주소를 손으로 넣지 않고 lobby.minidice.net 목록에서 방을 눌러 참가하게 했다. 새 버그는 없어 이슈를 만들지 않았다. 재발 방지: 버전이 다른 방은 목록에서 잠기고(`MenuCheck`), 같은 공유기는 LAN 주소로 들어간다(`MenuCheck`, `RoomDirectoryCheck`는 로컬 lobby 서버가 필요해 `-- --lobby=URL`로 따로 실행). 서버는 2026-10-21 설치했고 실제 게임 방장이 목록에 올라갔다가 종료 후 45초 안에 사라지는 것을 확인했다. 사용자 공유기는 UPnP로 포트를 열지 못해("no UPnP") 다른 집에서 들어오려면 UDP 24680 포트포워딩이 필요하다. 다른 집에서의 실제 접속은 아직 확인 전.

- 2026-10-21 앱 아이콘 검토(A-16, 관련 I-75): 기존 아이콘 경로가 비어 있던 상태에서 사용자 선택의 거위 PNG·ICO를 프로젝트/Windows 내보내기에 연결했다. 이는 신규 아트 적용이며 기존 버그 해결로 꾸미지 않고 새 이슈 ID를 발급하지 않는다. I-75의 C# 포함 검사와 내보내기 방식은 그대로 유지한다. 격리된 작업 공간에서 C# 빌드 경고/오류 0, Godot 가져오기·Windows 릴리스 내보내기 성공, .NET 폴더 존재, EXE 내장 6개 크기의 아이콘이 입력 ICO와 픽셀 단위로 일치함을 확인했다. 원본 ICO는 7개 크기이며 EXE에는 Godot가 24px를 제외한 16·32·48·64·128·256px를 넣는다. 최초 검사는 EXE에도 7개가 들어간다고 잘못 기대해 실패했고, 실제 리소스와 Godot의 크기 필터링 동작을 확인한 뒤 기준을 분리해 통과했다. 재발 방지: 교체 시 두 설정 파일과 PNG·ICO를 함께 갱신하고 [아이콘 규격](app-icon.md)의 재생성·내장 리소스 확인을 반복한다. 추출한 실제 아이콘 렌더를 확인했다. 원본의 배경은 유지하며, OS 배율별 작업표시줄·탐색기 캐시 및 다른 PC 표시, 실제 게임 실행은 이번에 검사하지 않았다. 매칭/게임 코드는 변경하지 않아 전투·네트워크 검사를 재실행하지 않는다.

- 2026-10-20: 사용자 요청에 따라 루트 `AGENTS.md`에 기능 추가·버그 수정 시 결정/이슈 기록을 함께 갱신하는 규칙을 명시했다. 이번 작업은 기록·저장소 구성 작업이며 게임 동작 변경은 없다. 첫 커밋에는 생성 출력물을 제외하고, 새 체크아웃의 실행 로그 디렉터리를 위해 `game/output/.gitkeep`만 포함한다. 원격 주소는 decisions T-18 참조.

- 2026-10-20: 종 특징을 [플레이어 동물 가이드](player-species-guide.md)와 [몬스터 가이드](monster-design-guide.md)로 분리 정리(A-15). I-29~I-31·I-35·I-53·I-54의 재발 방지 조건을 새 종/적 추가 확인 항목으로 연결했다. 문서만 변경했으므로 새 버그 ID는 발급하지 않으며 기존 해결 상태·실행 검사 결과를 변경하지 않는다. 링크·코드 ID·현재 팔레트·테마 구성을 대조하고 `git diff --check`로 형식을 확인한다.
