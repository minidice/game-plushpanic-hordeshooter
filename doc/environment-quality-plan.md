# Stage 1·2 공간·외곽 품질 개선 계획

> 2026-10-23. 사용자가 대화에서 수정한 범위와 단계별 실행을 승인했다. 이 문서는 실행 순서와 검수 기록이며, 예술적 최종 승인을 의미하지 않는다.
> 실행: `superpowers:executing-plans`에 따라 현재 세션에서 직접 구현한다.

**목표:** 실내 벽·출입구·파티션·갈 수 없는 설비 공간과 야외 바위·숲·물가를 개선하고 중앙의 작은 장식 소품은 후순위로 둔다.

**설계:** 이동/사격/길찾기 충돌과 외형을 분리한 A-23을 유지한다. Stage 1은 기존 벽체 위에 장소별 건축 마감, 출입구 프레임, 외곽 설비를 구성한다. Stage 2는 가까운 지형을 비대칭 큰 암반과 식생 군집으로 만들고 먼 배경 키트는 재사용한다. 가시성에 민감한 카메라 쪽 경계는 기존 낮은 높이를 유지한다.

**기술:** Godot 4.7 C#, 절차적 정적 메시, 공유 재질·셰이더, MultiMesh. 기존 GLB 자산과 물리·플로 필드를 재사용한다.

**근거:** 사용자 첨부 실내/야외 이미지, [레벨 규칙](level-design-rules.md), [시나리오](scenario-level-design.md), 결정 A-22~24·L-14, 이슈 I-91~93.

## 공통 제약

- Stage 1 세이프룸→거리→창고→야적장→세이프하우스, Stage 2 벙커→숲→개울→야적장 동선 유지.
- 문 3개의 순서·셔터 이동·상호작용·Stage 1→2 이월·네트워크 계약 유지.
- 전투 공간·보급·적 등장 좌표 변경 없음. 펜스는 기존 차단 경계에만; 배경 소품은 갈 수 없는 공간에만.
- 새 장식은 물리/시야 광원 등록 없음. 환경광 조정은 렌더만 바꾸며 인식 규칙은 유지.
- 생성 출력물은 `game/output/environment-*`에 저장하고 커밋하지 않는다.
- 수치·팔레트·미술 판단은 구현 제안값. 사용자가 승인한 것은 범위와 진행 순서다.

## 검수 초점

1. 출입구 프레임이 실제 통과 폭을 좁히거나 열린 문을 가리지 않는가.
2. 카메라 쪽 펜스/수목이 경계의 생존자와 보급을 가리지 않는가.
3. 구역 끝·모서리·해치 주변에 바닥 틈, 뜬 소품, 겹친 표면이 없는가.
4. Stage 1 공유 거점 모드와 Stage 2 전환/다리의 충돌·경로가 유지되는가.
5. 장식 추가로 메시/드로 콜·프레임 시간이 과도하게 증가하지 않는가. 실제 측정과 미측정을 구분한다.

### 1차 적용 결과 (2026-10-23)

- **기준 확보**: 수정 전 `MapCheck` 24 통과, 기본/확대 28장과 렌더 통계 저장. Stage 1 시나리오·난전 및 Stage 2 시나리오의 열린 문 플로 필드/월드 충돌 6개 해시를 저장했다. 이후 동일 계약 유지 확인.
- **Stage 1**: 4구역 벽 마감, 끝 기둥/상단·하단 마감, 출입구 4개, 셔터 구동부/케이스, 낮은 천막·금속 펜스, 외곽 설비 공간 3개, 환기구·배관·전기함, 해치/출입구 바닥 마감. 정적 장식은 재질별로 메시 결합. 중앙 전투 소품/배치와 물리는 기존 유지.
- **Stage 2**: 가까운 절벽 반복을 큰 암반/발치 돌과 침엽수 군집으로 교체. 먼 숲 줄의 높이·깊이 변화, 카메라 쪽 낮은 경계, 물가 이음·세이프하우스 벽/문틀 보완. 환경광/태양색 조정. 배경 바닥이 개울을 덮던 기존 문제는 I-104로 분리해 해결.
- **중간 실패와 수정**: 수면보다 높은 배경 바닥, 회전한 근경 바위의 통로 침범을 각각 실패하는 검사로 확인 후 수정. 독립 코드 리뷰에서 혼합 인덱스 메시 결합 시 면 누락(72개 중 12개만 유지), 셔터 상단 프레임/열린 판 간섭, 카메라 쪽 줄의 추가 흔들림 위험을 확인했다. 삼각형 스트림 통일, 프레임 +X 오프셋, 가까운 줄 기존 흔들림 복원으로 처리. 리뷰 재지적 대신 해당 실패를 재현하는 검사와 실제 렌더로 확인했다.
- **최종 검증**: 빌드 경고/오류 0, Godot 에디터 가져오기 성공. `EnvironmentGeometryCheck` 1,036개(대부분 삼각형별 비간섭 단언), `EnvironmentReview` 215개(기본 계약 21 + 바위 범위 194), `StageTransitionCheck` 164, `MapCheck` 24, `ModeCheck` 147, `Integration` 149 통과. 실제 Forward+ 1600×900 기본/확대 28장을 다시 생성하고 실내·입구·셔터·해치·낮은 경계·숲·다리·야적장·끝 거점을 검토했다. 외곽 설비는 `--services` 별도 6장으로 추가 확인했고 계약 검사 21개 통과. 총 34장 캡처.
- **종료 경고**: 최종 전환 6개·맵 4개·모드 6개·통합 4개의 ObjectDB 잔존 경고. 검사 실패와 별개이며 I-17 해결로 보지 않는다. 이번에 잔존 객체 종류는 추적하지 않았다. 새 기하 검사·기본/설비 환경 렌더·가져오기는 경고 없음.
- **렌더 통계**: 동일 28개 시점에서 Stage 1 드로 콜 +11~91, 프리미티브 +10,824~44,156. Stage 2 드로 콜 -129~+1, 프리미티브 -138,114~+19,372. 그려진 장면/그림자 포함 엔진 카운터이며 GPU 시간과 동일하지 않다. 최종 캡처의 프레임 간격은 약 250ms로 제한된 상태여서(정확한 제한 원인 미추적, 일부 캡처 중 헤드리스 검사도 병행) 변경 전 약 5.5ms와 성능 비교에 사용할 수 없다. 통계 파일은 보존하되 프레임 개선/악화 판단에서는 제외한다. 6인/저사양/장시간 실전 측정은 미완료.
- **기록**: A-7·A-23 현재 내용과 변경 이력 갱신, A-22 키트 자산/A-24 바닥 혼합 계약 검토 후 유지(자산·혼합 규칙 변경 없음). I-92 제약 갱신, 실제 수면 버그 I-104 및 개발 중 회귀 수정 기록. 기능 체크리스트와 레벨 규칙 갱신. 원격/브랜치 확인 후 생성 출력물을 제외한 코드·테스트·문서를 같은 로컬 커밋에 포함한다.

### 재현

```powershell
dotnet build game/HordeShooter.csproj
# Godot C# 실행 파일로 각각 실행. -Test 래퍼는 Integration만 실행하므로 전용 장면을 생략하지 않는다.
& $godot --headless --path game res://tests/EnvironmentGeometryCheck.tscn
& $godot --path game --resolution 1600x900 res://tests/EnvironmentReview.tscn -- --tag=after
& $godot --path game --resolution 1600x900 res://tests/EnvironmentReview.tscn -- --tag=services --services
# StageTransitionCheck, MapCheck, ModeCheck, Integration도 각각 --headless로 실행.
```

`game/output/environment-after-*.png`, `environment-services-*.png`, `environment-*-metrics.json`, 검사 로그는 로컬 재생성 산출물이다. `--baseline`은 기존 계약 파일이 있으면 덮어쓰기를 거절한다.

### 후속 미술·플레이 검수

이 체크리스트의 완료는 승인 범위의 **1차 구현·회귀 검수**다. 참조 스크린샷과 동등한 최종 품질을 달성했다는 의미가 아니다.

- [ ] 근경 바위/숲의 면 분할·반복감, 실내 설비 공간 3개의 구성 차별화와 조명 깊이 추가 조정.
- [ ] 실제 이동/조준으로 모든 출입구·벽 근접 시점의 가림과 보급 가독성 검수.
- [ ] 동일 프레임 제한/부하 조건의 성능 측정, 6인·저사양·장시간 플레이.
- [ ] 사용자 외곽 품질 검수 후 중앙 소품 밀도·구성 작업으로 이동.
