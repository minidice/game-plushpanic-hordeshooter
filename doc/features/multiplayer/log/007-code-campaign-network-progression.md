- 2026-10-29. 사용자 요청: 확인된 진행 차단을 추천 순서로 수정·검증하고 재발 방지. 기준 `7a6da8f`, I-135 → I-136 → I-137 → I-90. 구현 후 독립 리뷰에서 메시지 순서/전환 취소 문제를 추가 재현했다.

## 변경

- I-135: 모든 위치를 signed24 cm로 전송한다. 약±83km, 비정상/범위 밖 값은 예외로 거절한다. 표면 접촉 사건의 길이를 `NetWriter.PositionBytes`로 계산하고 프로토콜18→19로 변경했다. 스냅샷은 레코드를 잃지 않고1100B 이하로 나눈다. 같은 시각의 조각마다 클라이언트 시계를 여러 번 보정하지 않는다.
- I-136: 사다리·집라인 이동은 호스트가 실행하고 소유자/관전자는 전체3D 위치와 이동 종류를 따른다. 착지·취소 때 motion revision을 올리고 이전 revision 입력/스냅샷은 거절한다. 소유자가 새 revision을 되돌려 보내면 평상시 이동을 재개한다. 높은 단의 대역 Y를 버리지 않는다.
- I-137: World에 곤돌라 단계·출발 시각·탑승자 위치/revision을 포함한다. 클라이언트는 호스트의 완료를 기다리고 도착은 revision으로 보장한다. 도착 스냅샷보다 늦게 온 출발 World가 소유자를 출발점으로 돌려보내지 못한다. 운행 중/완료 후 참가자는 도착 구역에서 이어받는다.
- I-90: 지속되는 NetLobby가 현재 맵·epoch·개인별 이월 장비를 보관한다. 준비 확인 → 호스트 맵 로딩 → 참가자 로딩/준비 확인 → 전원 재개 순서다. 모든 StageNet RPC에서 이전 맵 epoch를 버린다. 전환 중 이탈/로비 복귀는 커튼과 비동기 로딩 작업을 취소한다. 새 합류는 현재 맵을 받는다.
- I-138: 캠페인1 x427/x477 컨테이너 사다리 앞에 빠진 지면을 연결했다. 이전에는 링크가 낮은 바닥→높은 바닥보다 먼저 바닥 공백을 만나 두 끝을 높이0으로 만들었다. 새 접근 영역은 각4m 폭, 기존 컨테이너/길 사이만 연결한다. 색인 예약 `f553248`을 먼저 커밋·푸시했다.

## 재발 방지와 실행

```powershell
./game/tests/Run-CampaignMultiplayerChecks.ps1 -Windowed
./game/Export-Game.ps1
```

첫 명령은 가져오기·빌드 후 전용 장면과 실제 두 프로세스 검사를 순차 실행한다. 장면은300초, 두 프로세스 묶음도300초 제한이며 실패하면 종료한다. `game/output/campaign-validation.json`에 종료 코드·엔진 오류·종료 경고·소스 SHA256 지문·Godot 버전을 남긴다. 결과를 통과할 때까지 반복해 덮어쓰는 절차가 아니다.

배포는 모든 게임 소스·설정·에셋·검사 파일의 지문, 창 모드 검사 여부와 Godot 버전이 일치한 통과 기록만 인정한다. 없거나 달라졌으면 검사를 먼저 실행하고 실패 시 내보내기를 막는다. 내보내기 중 소스 변경도 패키징 전에 차단한다. 배포 폴더에 `VALIDATION.json`을 동봉한다. 직접 Godot 내보내기 명령을 호출하는 우회 경로까지 시스템적으로 금지하는 기능은 아니다.

검사 범위: 큰 캠페인1~3/짧은 시나리오1~2의 문·경보·상호작용·모든 사다리 양방향·집라인·착지/취소·과거 입력/스냅샷 거절·곤돌라 메시지 역전·완료 뒤 합류·목적지/출구. `CampaignProgressionCheck`는 실제 별도 프로세스에서1→2→3, 장비/탄약/체력 유지, 구간2 재합류, 곤돌라 도중 이탈/재합류, 마지막 로비 복귀를 확인한다. `StageTransitionCheck`는 커튼 중 로비 복귀/호스트 단절 취소를 추가한다.
