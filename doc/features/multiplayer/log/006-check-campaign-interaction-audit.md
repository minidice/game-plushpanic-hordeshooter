## 실행과 재현

`dotnet build game/HordeShooter.csproj --nologo -v q` 후 Godot4.7.2 .NET으로 다음 장면을 **순차 실행**한다. 아래 감사 장면은 실패를 모아 출력하고 마지막에 종료1을 반환한다. 미해결 결함을 기대값으로 바꿔 녹색으로 만들지 않는다.

```text
Godot --headless --path game res://tests/CampaignInteractionAudit.tscn -- --audit-stage=1
Godot --headless --path game res://tests/CampaignInteractionAudit.tscn -- --audit-stage=2
Godot --headless --path game res://tests/CampaignInteractionAudit.tscn -- --audit-stage=3
Godot --headless --path game res://tests/CampaignInteractionAudit.tscn -- --audit-stage=1 --audit-short
Godot --headless --path game res://tests/CampaignInteractionAudit.tscn -- --audit-stage=2 --audit-short
```

검사 준비 중 빌드1회는 존재하지 않는 `TierMap.Ground` 사용으로 실패해 `GroundY`로 수정했다. 첫 실행은 Godot가 중복 Name을 자동 변경하는 것을 고려하지 않아 두 번째 사다리를 못 찾았다. 현재 검사는 prompt/좌표로 찾는다. 이어 각 시험 전 위치를 옮길 때 이전 입력이 한 프레임 먼저 도착해 다음 항목을 오염하는 것을 분리했다. 소유자 입력이 안정된 후 대역 위치를 한 번 맞추고 다시 실제 패킷을 흘려 좌표 잘림을 검사한다. 이 준비 오류로 인한 펌프 요청 실패는 독립 제품 결함으로 발급하지 않았다. 초기 로그(`campaign-audit-large-*`, `campaign-audit-final-*`, `campaign-audit-isolated-*`)는 최종 결과와 구분해 보존한다.

추가 회귀: `DestructionNetCheck`29 통과·종료0, `InteractionUiCheck`37 통과·종료0. 로그 `game/output/campaign-audit-DestructionNetCheck.log`, `campaign-audit-InteractionUiCheck.log`. 이 둘에는 종료 경고 없음. `NetSyncCheck`는 적 위치 평균0.39m/최대1.91m로 실패·종료1(`campaign-audit-NetSyncCheck.log`). 기존 I-72의 간헐 위치 오차와 같은 검사 실패이며 통과할 때까지 재실행하지 않았다. 그 실패 뒤의 항목은 이번 실행에서 검증되지 않았다.

최종 리뷰 반영본: C# 빌드 경고0·오류0·종료0(`campaign-audit-reviewed-build.log`). 아래 최종5개 로그에는 엔진 오류·종료 경고가 없고, 원래 참가자와 중간 합류 참가자 모두 해석 오류0이다. 실패 수는 같은 원인이 여러 장치에서 반복된 검사 수이며 별도 버그 수가 아니다.

| 최종 실행 | 통과 | 실패 | 종료 | `game/output/` 로그 |
|---|---:|---:|---:|---|
| 큰 캠페인1 | 89 | 25 | 1 | `campaign-audit-reviewed-large-1.log` |
| 큰 캠페인2 | 37 | 33 | 1 | `campaign-audit-reviewed-large-2.log` |

준비 위치를 안정화한 최종본에서는 큰 캠페인1~3의 참가자 크레센도 시작 요청이 모두 통과했다. 앞선 준비 오류의 실패를 별도 펌프 결함으로 기록하지 않는다. 이번 변경은 외형 변경이 없어 렌더를 새로 만들지 않았다.

## 검사 한계·후속

- 상호작용 요청은 준비 위치로 이동시킨 뒤 실제 ClientUse RPC를 보낸다. E 입력/긴 누름 UI는 별도 InteractionUiCheck에서 확인했으며 모든 실제 맵 장치의 접근 동선을 걸어 완주한 검사는 아니다. 문 검사도 상태/충돌체 검사이며 모든 문을 물리적으로 걸어 통과한 검사는 아니다. I-134의 C1 거위/오리 통과 검사는 이전 기록에 있다.
- 사다리/집라인은 실제 요청 후 이동 시간만큼 기다려 도착과 양쪽 위치를 비교한다. 높이 추종은 별도 준비로 검사한다. 일부 먼 이동 장치에서는 I-135가 먼저 요청을 막는다. 범위 안 장치의 실패로 I-136을 따로 확인했다.
- 곤돌라 검사는 전원 탑승 준비 후 호스트에서 출발하고 Arrive를 호출해 연출 시간을 단축한다. 독립 물리 월드여도 SceneTree는 공유한다. viewport는 Pausable, 검사 루트와 필요한 네트워크 처리는 Always로 두었다. 실제 두 프로세스의 pause·인터넷 지연·도중 이탈·복귀까지 검증한 것은 아니다.
- 독립 읽기 전용 리뷰에서 세 원인과 I-90을 확인했다. 리뷰 지적에 따라 원래 클라이언트의 해석 오류도 중간 합류용 클라이언트로 교체하기 전에 검사한다. 정상 전송/중간 합류와 전체 진행 성공을 구분한다.
- 우선 수정 순서: 큰 좌표 표현/프로토콜(I-135) → 사다리·집라인과 높이 소유권(I-136) → 곤돌라 탑승/연출/도착 복원(I-137) → 전원 다음 장면 로딩·장비 이월(I-90). 이 순서는 점검 결과에 따른 제안이며 새로운 게임 방향 확정 결정이 아니다.
