# 멀티플레이 — 이슈 본문

## I-133 로비에서 함께 시작하면 연결이 끊겨 메뉴로 돌아감

- 증상: 로비에서 준비한 뒤 함께 시작하는 클라이언트가 메뉴로 돌아가거나 로비 로딩 상태에 남는다. 시작 후 합류는 성공할 수 있다. 사용자 배포본 두 프로세스 관찰에서 제보했다.
- 확인된 원인: 큰 캠페인 맵 생성이 메인 스레드를 수 초 동안 막으며 ENet 패킷/응답 처리가 중단된다. 기존 연결의 신뢰 패킷 응답 대기 제한에 걸려 상대가 연결을 해제한다. 진단에서 호스트 시작2.867초→맵 완료8.690초(약5.8초), 클라이언트 맵 완료 시점12.311초에 `ServerDisconnected`, 이후3초 뒤 메뉴 복귀를 확인했다. 같은 경로에서 대기 제한만 변경한 뒤 정상화됐다.
- 해결: `NetLaunch.SetLoadingTimeout`으로 로비/로딩 중 ENet 대기를 factor32·최소30초·최대60초로 설정한다. 클라이언트 로비 진입과 호스트의 Hello 수신 시 양 끝에 적용한다. 호스트의 ClientReady 수신/클라이언트의 최초 World 수신에서 일반 최소5초·최대30초로 복구한다. 로비 복귀 시 다시 로딩 대기를 적용한다. 패킷 형식과 게임 판정은 바꾸지 않는다.
- 재발 방지: `LobbyStartCheck`는 서로 다른 두 프로세스에서 실제 MainMenu→Stage 전환·2인 동기화 유지→함께 로비 복귀→두 번째 시작을 검사한다. 기존 LobbyCheck는 장면 전환을 카운터로 대체하고, 기존 배포 EXE 검사는 시작 후 합류만 확인해 이 구간을 검증하지 못했다.
- 검사: 수정 전 세 번의 별도 프로세스 검사에서 시작 알림 미도착/메뉴 복귀를 재현했다. 수정 후 실제 큰 맵 시작, headless 두 라운드와 Forward+1280×720 두 라운드가 양쪽 종료0으로 통과했다. Lobby31·NetCodec12·NetSync32 통과. [실행 로그·남은 범위](log/002-code-lobby-loading-timeout.md).
- 남은 제약: 맵 생성 자체가 비동기화된 것은 아니다. 로딩 중 무응답 판정이 최대60초까지 늦어질 수 있으며 이를 넘는 로딩/실제 연결 단절은 보호하지 않는다. 서로 다른 두 PC·인터넷 지연/손실은 미검증이다. 위치 오차의 간헐 실패(I-72)는 별도이며 이번 수정으로 해결됐다고 처리하지 않는다.

## I-72 후속: 로컬 위치 동기화 검사 간헐 실패 (2026-10-29)

- 증상: `a5b1a49` main 병합 후 NetSyncCheck 1차에서 원격 플레이어 위치 오차0.88m(기준0.3m), 2차에서 적 추적 평균0.39m/최대1.91m(기준0.3m/1m)로 실패했다. 같은 코드·인수의 3차는32개 모두 통과했다.
- 원인: 미확정. 타이밍/실행 부하 가능성은 추정이며 이번 UI/보급 변경의 회귀 또는 기존 네트워크 결함이라고 단정하지 않는다.
- 해결: 미해결. 검사 임계값이나 네트워크 코드를 바꾸지 않았다. 재실행 통과를 해결 증거로 취급하지 않는다.
- 재발 방지·검사: 같은 장면의 원격 위치/호스트 이력 비교와 로그를 보존한다. 실제 두 PC의 지연·손실 조건에서 추가 확인해야 한다.
- 배포 EXE 두 프로세스의 로컬 접속·초기 상태 동기화는 성공했다. 이것이 이동 품질·완주를 보장하지 않는다. [실패/통과 로그와 배포 범위](../level/log/019-check-campaign-main-integration.md).
