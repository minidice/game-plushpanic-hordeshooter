# 레벨 디자인 가이드 맵

작성일: 2026-10-27 · 결정: [L-33](decisions.md#l-33-레벨은-가이드-맵을-먼저-만든다) · 근거: [레벨 디자인 참고 리서치](reference-level-design-research.md)

맵을 짓기 전에 **구역마다 무엇을 겪는지**를 먼저 적는 지도이자 체크리스트다. 큰 구역마다 새 경험을 하나 이상 주고, 앞에서 배운 경험을 다시 쓰고 섞어 경험이 쌓이게 한다. 검사기가 규칙을 확인하고, 가이드 보드와 평면도로 한눈에 본다.

## 1. 작업 순서

1. **가이드 맵 작성** — 구역 순서 · 크기 · 진행 위치 · 역할 · 새 경험 · 다시 쓰기 · 섞기 · 길 안내.
2. **검사** — `python tools/level-guide/guide.py check`. 오류(G)가 없을 때까지 고친다. 경고(W)는 이유가 있으면 남겨도 된다(가이드 `note`에 이유).
3. **사용자 확인** — 가이드 보드(`board`)로 본다.
4. **맵 짓기** — 맵 데이터(`*_layout.json`, `*_encounters.json`)를 가이드에 맞춘다. 검사기가 가이드와 맵 데이터의 구역 ID · 크기를 맞춰 본다(G6).
5. **마무리** — 못 가는 곳을 벽 · 물 · 바위 · 나무로 촘촘하게 막는다(사용자: 레벨 디자인이 어느 정도 진행된 뒤 마무리 작업). 리서치 규칙 후보 16.

## 2. 파일

| 파일 | 내용 |
|---|---|
| [`game/content/data/stages/guide/experiences.json`](../../../game/content/data/stages/guide/experiences.json) | **경험 목록**: 경험 ID · 이름 · 종류(이동 · 지형 / 장치 · 임무 / 적 / 교전 공간 / 진행 · 보상) · 상태(`built` 구현 / `planned` 계획) · 설명 · 근거. 역할 · 길 안내 종류 이름도 여기 |
| `game/content/data/stages/guide/<스테이지>_asis_guide.json` · `_plan_guide.json` | **구역별 기록** — `as-is`(지금 지어진 것을 옮긴 진단)와 `plan`(설계안). 기본 검사는 스테이지마다 설계안이 있으면 설계안만 읽는다(같은 스테이지를 두 번 세지 않게) |
| [`tools/level-guide/guide.py`](../../../tools/level-guide/guide.py) | 검사(`check`) · 가이드 보드(`board`) |
| [`tools/floorplan/render_floorplan.py`](../../../tools/floorplan/render_floorplan.py) `--guide` | 평면도에 구역별 역할 · 개수 · 새 경험 표시 |

게임은 이 파일들을 읽지 않는다(설계 · 검사용). 경험 목록에 없는 경험이 필요하면 목록에 먼저 추가한다(계획이면 `planned`).

## 3. 구역별 기록 형식

```json
{
  "stage": 1, "name": "Stage 1 도시 (큰 맵)",
  "layout": "stage1_large_layout.json",     // 맵 데이터가 아직 없으면 지워도 됨(계획 단계)
  "status": "as-is",                        // as-is = 지금 지어진 것을 옮김, plan = 설계안
  "date": "2026-10-27",
  "zones": [
    { "id": "B", "size": "large", "order": 2, "progress": 0.1, "role": "fight",
      "new": ["dormant_pack"], "reuse": [], "mix": [["alarm_trap", "narrow_passage"]],
      "wayfinding": ["light", "landmark"], "note": "왜 이렇게 했는지 · 경고를 남긴 이유" }
  ]
}
```

| 칸 | 뜻 |
|---|---|
| `order` | 걷는 순서(겹치지 않음) |
| `progress` | 스테이지 진행 위치 0~1, 순서대로 늘어남(리서치 규칙 5, Alien Swarm 필수 방 배치) |
| `role` | `safe` 안전 · `explore` 탐색 · `fight` 교전 · `peak` 정점 · `rest` 휴식 · `transit` 이동 · `finale` 피날레 |
| `new` | 이 구역에서 **처음** 겪는 경험 |
| `reuse` | 앞에서(이 스테이지 앞 구역이나 앞 스테이지) 배운 경험을 다시 씀 |
| `mix` | 배운 경험 둘 이상을 **함께** 쓰게 하는 상황. `[["a", "b"], ...]` |
| `wayfinding` | 길 안내 수단: `light` 조명 · `landmark` 랜드마크 · `sign` 표지 · `objective` 목표 표시 · `route_shape` 길 모양 · `sound` 소리 |

## 4. 검사 규칙

오류(G)는 고쳐야 하고, 경고(W)는 이유를 `note`에 남기면 된다. 스테이지 번호 순서로 읽어서 앞 스테이지에서 소개한 경험은 뒤 스테이지에서 다시 쓸 수 있다.

| 코드 | 규칙 | 근거 |
|---|---|---|
| G1 | 경험 · 역할 · 길 안내 ID가 목록에 있음 | — |
| **G2** | **큰 구역마다 새 경험 1개 이상** | 사용자 요청 |
| **G3** | **소개(new)하기 전에 다시 쓰거나 섞지 않음** | 사용자 요청(소개 → 다시 → 섞기), 리서치 규칙 11 |
| G4 | 섞기는 서로 다른 경험 2개 이상 | — |
| G5 | 순서가 겹치지 않고 진행 위치는 0~1, 순서대로 늘어남 | 리서치 규칙 5 |
| G6 | 맵 데이터가 있으면 구역 ID · 크기가 같음 | — |
| G7 | 이미 소개한 경험을 다시 "새"로 넣지 않음, 한 구역에서 새 · 다시를 겹치지 않음 | — |
| W1 | 큰 구역의 새 경험이 **3개 초과**면 "한꺼번에 너무 많음" `[임시]` | 리서치 규칙 11(하나씩 소개) |
| W2 | 소개한 경험을 이후 다시 쓰거나 섞는 곳이 없음(진행 · 보상 종류는 제외) | 사용자 요청(경험이 쌓이게) |
| W3 | 정점(`peak` · `finale`) 구역이 없음 | 리서치 규칙 6 |
| W4 | 정점 뒤 **2구역** 안에 휴식 · 안전 구역이 없음 `[임시]` | 리서치 규칙 8 |
| W5 | 큰 구역에 길 안내 수단이 없음 | 사용자 요청(길 안내), 리서치 규칙 1 · 3 · 13 |
| W6 | 스테이지에 섞기가 하나도 없음 | 사용자 요청 |
| W7 | 목적 없는 구역(새 · 다시 · 섞기 모두 빈 칸, 안전 · 이동 역할 제외) | — |
| W8 | 계획(미구현) 경험을 씀 → 만들어야 할 목록 | — |

`check --strict`는 경고도 실패로 센다. 지금은 게임 검사(Integration 등)에 연결하지 않았다.

## 6. Stage 1 현재 상태(as-is) 검사 결과 — 2026-10-27

지금 지어진 큰 Stage 1(`stage1_large_layout.json` · `_encounters.json`)을 그대로 옮긴 가이드다(`stage1_large_asis_guide.json`). 설계 목표가 아니라 **진단**이다.

- 구역 9(큰 3) · 새 경험 18 · 다시 쓰기 18 · 섞기 0 · 정점 1. **오류 1 · 경고 8.**
- **G2** F 화물 야적장: 큰 구역인데 새 경험이 없다 — B · D의 구성(잠든 · 경계형 무리, 특수 적, 사다리 · 높은 단, 드럼통)을 다시 쓸 뿐.
- **W1** B 상가 거리에 새 경험 7개, D 창고 단지에 5개가 한꺼번에 나온다 — 하나씩 소개되지 않는다.
- **W5** B에 길 안내 수단이 없다(가로등은 있으나 길 안내용 배치가 아님). 길 안내가 있는 큰 구역은 D(임무 표시) · F(크레인 랜드마크)뿐.
- **W6** 섞기가 하나도 없다 — 배운 것을 함께 쓰게 하는 상황이 없다.
- **W2** 경보 함정 · 좁은 통로 · 제어판 크레센도 · 스위치를 한 번 소개하고 다시 쓰지 않는다(Stage 2 가이드가 생기면 다시 판단).
- 데이터에서 본 공통점: Stage 1 · 2 · 3 모두 큰 구역마다 잠든 + 경계형 무리 + 특수 적 1, 두 번째 큰 구역에 셔터 · 철문 크레센도, 중간 안전 구역 → 세 번째 큰 구역이라는 같은 틀이다(사용자가 느낀 "단순함"과 맞음).

## 7. Stage 1 설계안(plan) — 2026-10-27 확정

`stage1_large_plan_guide.json`. AI 추천안을 **사용자가 2026-10-27 그대로 확정**했다("Stage 1 설계안 이대로 확정", 가이드의 `approved`). 7.3의 맵 변경은 아직 반영 전이다. 구역 구조(A ~ H, 큰 3 · 작은 6)는 지금 맵 그대로 두고, **구역마다 무엇을 처음 배우는지 · 무엇을 섞는지 · 길을 어떻게 비추는지**를 바꾼다.

### 7.1 원칙(리서치 규칙 후보에서)

- 큰 구역마다 새 경험은 **1 ~ 3개**로 하나씩 소개(규칙 11). 지금 B에 7개 · D에 5개가 몰린 것을 앞뒤로 나눈다.
- 배운 것을 바로 다음 구역에서 **둘씩 섞는다**(사용자 요청). 섞기 0 → 4.
- 정점(D 크레센도) 바로 뒤 휴식(E 초소, 규칙 8). 마지막 작은 구역(G)에 **마지막 도전**(Blueprint 8장 "스테이지를 대표하는 사건과 마지막 도전").
- 큰 구역마다 **빛으로 길 안내**(규칙 3 — L4D "어두운 게임에서 플레이어는 빛이 있는 곳으로 간다"), 휴식 · 안전 구역은 따뜻한 색(규칙 3).

## 9. 구역 테스트

구역 하나를 손으로 확인할 때는 처음부터 걷지 않고 그 구역에서 시작한다(2026-10-27, [log/008](log/008-code-zone-start.md)).

```bash
powershell -File game/Start-Game.ps1 -Zone D      # Stage 1의 D 창고 단지
powershell -File game/Start-Game.ps1 -Zone 2:D    # Stage 2의 D
```

- 메뉴 없이 큰 캠페인(`-LargeStages`와 같은 맵)의 그 스테이지로 바로 들어간다. 구역 ID는 맵의 `zones` ID(대소문자 무시, 예: `B-pharmacy`).
- 시작 자리: 주 경로(`routes.main`, 없으면 다른 경로)가 구역에 들어간 곳에서 3 m 안쪽의 빈 바닥. 경로가 지나지 않는 곁가지 구역(Stage 3 `B-tower`)은 구역 가운데에 가장 가까운 빈 바닥.
- 세이프룸 문은 열린 채, 목표는 문을 연 다음 단계로 넘어가고 몹 감독(director)이 바로 깨어난다. **무리 · 특수 적 · 경보 · 크레센도 · 보급은 맵 그대로** — 지나온 구역의 무리도 남아 있다(뒤를 돌아보면 있음).
- 기본 캐릭터 · 동료 1명 · 혼자 플레이. 해치로 다음 스테이지에 가면 그 스테이지는 평소처럼 해치 아래에서 시작한다.
- 모르는 구역 ID면 경고를 남기고 세이프룸에서 시작한다.
- 확인할 것(가이드 맵 기준): 그 구역의 새 경험이 실제로 느껴지는지, 다음 목표가 1~2화면 안에 보이는지(길 안내), 정점 뒤 숨 돌릴 틈, 헤매는 곳. 결과는 레벨 작업 기록(`check` 종류)으로 남긴다.
- 검사: `LargeStageCheck`가 세 스테이지의 모든 구역에 시작 자리가 있는지, `-Zone d`가 D 입구 · 열린 세이프룸 · 다음 목표로 시작하는지, 모르는 ID가 세이프룸으로 돌아가는지 확인한다.
