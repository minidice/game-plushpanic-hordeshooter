# 002 · code · Studio 최상단 「리소스 | md」와 문서 메뉴 (T-26)

관련: [decisions.md](../../../decisions.md) T-25 · T-26, [Studio 문서](../../../studio-prototype.md)

## 변경

- **최상단 구분**: 모든 Studio 화면의 머리글에 `리소스 | md`를 넣었다.
  - 원래 메뉴(캐릭터 · 일반 몬스터 조합 · 몬스터 도감 · 오브젝트 · 무기 · 이펙트 · 상태이상 · 사운드)는 「리소스」 아래 두 번째 줄로 그대로 둔다.
  - 나중에 「기획서」를 같은 줄에 추가할 예정이다(사용자).
- **`md` 메뉴**(`/docs`):
  - 목록: 저장소의 Markdown 문서 전부를 보여 준다. 범위는 `doc/**` · `docs/**`, `AGENTS.md` · `README.md` · `game/README.md` · `studio/README.md`.
  - 묶음: 기능 · <폴더>, 기록 색인 · 옛 기록, 규격 · 설계, 계획, 모델 지시문, 보관, 저장소 안내.
  - 전체 내용 검색: 한 줄에 모든 단어가 들어 있는 줄을 찾는다(대소문자 무시). 문서당 최대 6줄, 파일 · 줄 번호와 함께 보여 준다.
  - 읽기: 서버 밖 라이브러리 없이 작은 Markdown 렌더러를 쓴다(제목 · 문단 · 목록 · 표 · 인용 · 코드 · 링크).
    - 문서 사이 상대 링크와 제목 앵커로 이동할 수 있다.
    - 검색 결과를 누르면 그 줄로 가서 잠깐 강조한다.
    - 주소에 `?path=…&line=…`이 남는다.
- **서버**: [`studio/docs.mjs`](../../../../studio/docs.mjs)가 작업 폴더의 파일을 직접 읽는다. Godot 렌더러가 준비되기 전에도 동작하고, 읽기 전용이다.
  - 경로 검사: `doc/` · `docs/` · 위 안내 4개의 `.md`만 허용한다. `..` · 절대 경로 · 드라이브 경로 · `.md`가 아닌 파일은 400, 없는 파일은 404.
  - API: `GET /api/docs` · `/api/docs/file?path=` · `/api/docs/search?q=`.
