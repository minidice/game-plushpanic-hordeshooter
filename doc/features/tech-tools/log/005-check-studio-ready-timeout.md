# Studio 기존 실행 준비 대기 시간 초과 진단

- 확인일: 2026-10-26. 관련 결정: T-25. 사용자 요청: 실행기의 3분 대기 오류 원인 확인.
- 변경: 진단 기록만 추가. 게임/Studio 코드·데이터 변경, 프로세스 종료·재시작, 빌드/import는 실행하지 않았다.

## 확인된 증상과 원인

- `GET http://127.0.0.1:4317/api/health`는 해당 작업 폴더와 `app: plush-panic-studio`, `ready: false`를 반환했다.
- 4317 포트 소유 Node PID47408은 2026-10-25 01:44:59 시작한 기존 서버였다. 조사 시점 그 서버의 자식 프로세스는 0개여서 Godot 렌더러가 남아 있지 않았다.
- `/api/catalog`도 렌더러 준비 중 오류를 반환했다. 웹 서버 생존과 렌더러 준비 상태가 분리된 상황이다.
- `server.mjs`는 렌더러 종료/요청 시간 초과 시 ready를 false로 만들고 웹 서버는 유지한다. `Start-Studio.ps1`은 기존 서버의 ready=false를 시작 중과 실패/종료로 구분하지 않고 3분 동안 조회한다. 준비 상태를 복구할 실행 없이 기다리므로 이번 대기 오류가 발생한다.
- 렌더러가 최초로 종료된 이유는 미확정이다. 현재 renderer.log 마지막 부분에는 정상 빌드/import/Forward+ 시작 기록만 있으며 launcher stderr도 비어 있다. 외부 종료·렌더 요청 시간 초과 등을 확정 원인으로 기록하지 않는다.

## 검사 결과와 후속

- 상태/API/프로세스 확인으로 현재 비정상 상태를 확인했다. 기능 검사를 통과했다거나 복구됐다고 주장하지 않는다. 게임 테스트·종료 경고 검사는 미실행.
- 복구 경로는 기존 웹의 로컬 데이터 다시 읽기(`/api/reload`) 또는 해당 Studio 서버를 종료한 뒤 실행기 재실행이다. 이번 진단에서는 수행하지 않았다.
- 재발 방지는 시작 중/재로딩/렌더러 종료 상태의 구분과 실패 사유 전달, 실패 상태에서 대기만 하지 않는 복구 경로가 필요하다. 현재 실행기의 동시 실행/정상 준비 검사는 죽은 렌더러가 있는 기존 서버까지 검증하지 못한다.
- T-25의 로컬 전용·현재 데이터·비저장 목적은 유지한다. 새 제품 결정은 없으며, 종료 원인 확정이나 수정 검증 없이 기존 이슈 상태를 해결로 바꾸지 않는다.
