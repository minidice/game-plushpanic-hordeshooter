# 전투 — 결정 본문

## C-32 집중 보장 치명타와 조건부 확률 치명타 — 2026-10-29 후속

- 결정: 집중 완료 후 다음 한 발의 치명타 확률은100%로 유지한다. 그 외 공격에는 무기별 조건을 충족하면 확률로 치명타가 발생할 수 있는 규칙을 추가하는 방향으로 개선한다.
- 집중 용어(같은 날 사용자 명확화): 집중이 차오르는 동안은 조준만 하는 상태다. 장비의 집중 조건은 집중이 완료된 다음 한 발만을 의미한다. [상세](equipment-option-tuning.md#집중-조건-명확화-이력).
- 사용자 예시: 저격은 무기마다 정한 거리 이상이고 조준 중일 때, 집중 첫 발 이후 재집중 전까지 치명타30%처럼 설계할 수 있다. 거리와30%는 예시이며 모든 저격의 확정 수치가 아니다.
- 이유: 사용자 — 집중 다음 한 발 보장을 유지하면서 치명타가 확률로 붙는 조건들을 추가하려는 요청. 무기별 조건으로 사격 방식의 차이를 만드는 것은 AI 해석이다.
- 상태 · 날짜: `[방향 확정 / 세부 규칙 미결 / 구현 전]` · 2026-10-29. 조건 밖 기본 확률, 장비 확률의 합산·적용 조건, 집중 전 조건부 판정, 산탄/점사/관통 판정 단위, 멀티·AI 적용은 후속 설계다. 적의 치명타 공격 규칙까지 확정한 것은 아니다.
- 근거: 사용자 대화, [옵션 규격·미결](equipment-option-tuning.md), `Player.CritReady`·`SpendFocus`, `WeaponController`의 치명타 판정. 현재 코드는 집중 방식이며 새 확률 판정은 아직 없다.

### 바뀐 결정 — C-32

- 이전: 집중을 완료해야 다음 한 발이 치명타이고 발사하면 집중이0이 된다. 집중이 다시 차기 전에는 확률 치명타가 없다. 기존 본문은 [전체 결정 기록](../../decisions.md)의 C-32에 보존한다.
- 이후: 집중 다음 한 발100%를 유지하면서 조건부 확률 치명타를 추가한다. 집중 소비·재집중 체계는 유지하는 방향이며 세부 확률/조건은 아직 정하지 않았다. [기록011](log/011-doc-conditional-crits-debuff-resistance.md).

## C-1 구르기는 기본 2회 충전, 기본 무적 없음 — 2026-10-29 후속

- 결정: 기본 최대 충전 2회. 첫 동작을 끝낸 뒤 연속 사용 가능. 기본 무적 없음. 구르기 중 일반 피격은 피해를 받고 자동 달리기 대기시간을 갱신하되 구르기 동작은 끝까지 이어진다. 종료 후 걷기로 복귀한다. 최대 충전 증가 일반 장비는 만들지 않으며 치트·테스트용 확장 가능성과 난전 특수옵션 검토만 남긴다.
- 충전 회복(같은 날 사용자 확정): 한 칸씩 순서대로 회복한다. 두 번째 구르기를 사용해도 이미 진행 중인 회복은 초기화하지 않는다. 현재 칸이 회복되면 비어 있는 다음 칸을 회복한다.
- 회복 시작(같은 날 사용자 후속): 새 충전 회복은 구르기 종료 시점부터 시작한다. 이미 시작된 회복은 추가 사용 시 진행 보존 규칙을 따른다.
- 임시 수치·회복 지속(같은 날 사용자 수락): 한 칸 회복은 6초. 두 번째 구르기 동작 중에도 이미 진행 중인 회복은 멈추거나 초기화되지 않고 계속된다. 시간은 플레이하면서 조정한다.
- 이유: 사용자 — 급할 때 두 번 연속 회피할 수 있게 하되 구르기를 무적으로 보지 않는다. 달리기 조작·기력 관리를 늘리지 않는다.
- 상태 · 날짜: `[현재 구현 / 수치 임시]` · 2026-10-29. 충전 회복 6초는 사용자 수락한 테스트 기준. 구르기 피해 감소와 충전시간 단축 갑옷은 옵션 후보이며 실제 제작 확정 아님. [구현·검사](log/006-code-automatic-movement-roll.md).
- 근거: 사용자 대화, [설계 초안](equipment-movement-plan.md), `game/scripts/Player/Player.cs`의 `TryStartRoll`, `TakeDamage`. C-2 모션과 기존 옆 밀어내기·통과는 이번 결정에서 변경하지 않는다.

### 바뀐 결정 — C-1

- 이전: 5초 재사용 대기시간, 회피 중 무적(C-1, 2026-10-19). 원문과 당시 확인 기록은 [전체 결정 기록](../../decisions.md)에 보존.
- 이후: 기본 2회 충전, 무적 없음, 일반 피격에도 동작 지속·달리기 대기시간 갱신, 종료 후 걷기.
- 이유: 2026-10-29 사용자 결정. 최초 기록 당시 코드는 이전 방식이었다. 같은 날 사용자 구현 요청에 따라 `PlayerMovement.cs`의 순차 충전·일반 피해 처리·HUD·멀티 동기화를 구현했다. 특수 강제 이동/잡기 면역은 별도 미결 규칙이므로 기존 처리를 유지한다.
- 같은 날 충전 규칙 후속: 이전에는 순차/동시 회복과 두 번째 사용의 영향이 미결이었다. 이후 사용자 선택으로 한 칸씩 순차 회복·추가 사용 시 기존 진행 보존을 확정했다. 첫 회복 시작 시점과 시간은 계속 미결이다.
- 같은 날 회복 시작 후속: 위 미결 중 첫 회복 시작 시점은 사용자 선택으로 구르기 종료 시점으로 확정했다. 회복시간은 아직 미결이며 6초는 AI 제안으로만 기록한다.
- 같은 날 임시 수치 수락: 이전의 6초 제안을 사용자가 테스트 기준으로 채택했다. 두 번째 구르기 중 진행 중인 회복을 계속하고, 시간은 플레이하면서 조정한다.

## C-34 모자·갑옷 두 슬롯과 캠페인 샛길 보상

- 결정: 모자·갑옷 두 슬롯을 캠페인과 난전에 적용, 모드 2는 보류. 기능 옵션만 붙이고 당장은 내구도 없음. 캠페인 샛길 보상은 모자·갑옷·가끔 특수 무기 중 하나로 구상한다.
- 교체·옵션(2026-10-29 사용자 수락): 여분 장비를 들고 다니지 않는다. 현장에서 교체하면 기존 장비를 바닥에 내려놓는다. 우선 장비당 기능 옵션은 하나로 한다. 별도 벗기 조작은 아직 정하지 않는다.
- 협동 획득(같은 날 사용자 확정): 바닥 장비 하나를 팀이 공유하며 먼저 획득한 사람이 착용한다. 교체로 내려놓은 장비는 다른 팀원도 가져갈 수 있다. 개인별로 같은 보상을 복제하지 않는다. 보상 지점별 배치 수량과 AI 동료 획득 행동은 미결이다.
- 이유: 사용자 — 샛길을 돌아갈 메리트를 주면서 신경 써야 할 것을 더 늘리지 않는다. 캠페인은 레벨 없음·저장 최소화·일반 패턴 단순화, 보스 패턴 대응을 지향한다.
- 구현 단계(같은 날 사용자 수락): 먼저 슬롯 아이콘과 기능 효과를 구현한다. 장비 교체에 따른 캐릭터 외형 변경은 다음 단계로 분리하며 첫 단계는 기존 꾸미기 외형을 유지한다.
- 발동 조건(같은 날 사용자 확정): 치명타 확률은 상시/조준 중, 치명타 피해는 상시/조준 중/집중 완료 한 발, 탄퍼짐·반동 감소는 각각 상시/조준 중으로 나눈다. 장비당 하나의 효과·조건 조합이며 무기의 조건부 치명타가 켜질 때만 장비 효과를 적용하도록 제한하지 않는다. 집중은 완료된 다음 한 발만, 차오르는 동안은 조준 중이다. 집중 전용 확률 옵션은100% 보장으로 실효가 없어 제작 제외한다.
- 수락한 임시 수치: 치명타 확률 상시+3%p/조준+6%p, 치명타 피해 상시+10%/조준+20%/집중+30%, 탄퍼짐 감소 상시10%/조준15%, 반동 감소 상시15%/조준25%.9개 조합을 첫 테스트 기준으로 채택했으며 최종 밸런스는 미검증이다. 다른 후보의 수치는 계속 제안이다. [상세](equipment-option-tuning.md#장비-옵션의-효과와-발동-조건), [구현 계획](equipment-implementation-plan.md).
- 옵션 처리(같은 날 사용자 확정): 상태이상 저항은 피해 대상에게 디버프가 처음 부여될 때의 지속시간을 기준으로 처리한다. 소수점 피해를 정수로 처리하면서 작은 피해의 감소 효과가 사라지는 것은 정상으로 허용한다. 기존 올림 처리를 유지하며 최소 감소량이나 소수 피해 이월 보정을 추가하지 않는다. 저항률과 갱신/중첩 시 처리는 별도 미결이다.
- 상태 · 날짜: `[방향 확정 / 수치 임시 / 구현 전]` · 2026-10-29. 위9개 조합·수치는 첫 테스트 기준으로 수락했다. 나머지 후보와 보상 지점별 배치 수량·영구 저장 계약은 미결이다. 이월·슬롯 배분 등은 구현 계획의 AI 선택과 사용자 결정을 구분한다. 외형 연결은 후속 단계이며 상세 방식은 미결이다. 최초 치명타1% 예시는 이번 상시3%p/조준6%p 테스트안으로 구체화했고, 이속1%·탄창10% 등 다른 예시는 이번 수락에 포함하지 않는다.
- 근거: 사용자 대화, [설계 초안](equipment-movement-plan.md), [캠페인 방향](../direction/game-direction.md), [시나리오 상세](../../scenario-level-design.md). C-3 무기 슬롯과 별개다.

### 바뀐 결정 — C-34 교체와 옵션 수

- 첫 테스트안 수락: 사용자 「해당 안으로 진행」에 따라9개 조합·수치를 임시 테스트 기준으로 채택하고 집중 전용 확률 옵션을 제작 제외했다. 이전 제안 상태는 기록013에 보존한다. [기록014](log/014-doc-equipment-first-pass-plan.md).

- 집중 조건 후속: 차오르는 동안 포함 여부 미결→사용자가 완료된 다음 한 발만 집중으로 정의했다. 기존 집중100%는 유지하며 실효 없는 집중 전용 확률 옵션의 제작 여부는 후속 판단이다. [기록013](log/013-doc-focus-option-trigger.md).

- 발동 조건 후속: 이전에는 장비 확률의 적용 조건이 미결이고 AI는 무기 조건 충족 시 가산을 추천했다. 사용자는 무기 조건에만 한정하지 않고 상시/조준/조준 집중 옵션을 각각 두기로 했다. 조준 조건부를 더 강하게 하되 구체 수치와 집중 확률 옵션의100% 보장 중복은 확인 전이다. [기록012](log/012-doc-equipment-activation-conditions.md).

- 옵션 처리 후속: 상태이상 저항 적용 시점 미결→첫 디버프 부여 시 지속시간 기준으로 확정. 피해 올림으로 효과가 사라지는 경우에 대한 AI의 보정 검토 제안→사용자가 정상 동작으로 수락하여 기존 정수 처리를 유지한다. [기록011](log/011-doc-conditional-crits-debuff-resistance.md).

- 외형 범위 후속: 이전에는 외형 연동 시점이 미결이었다. 사용자 선택으로 첫 구현은 슬롯 아이콘·기능 효과, 캐릭터 외형 연동은 다음 단계로 분리했다. [기록009](log/009-doc-equipment-visual-scope.md).

- 이전: 획득/교체/보관 규칙 미결, 장비당 대표 옵션 하나는 AI 제안.
- 이후: 사용자 수락으로 여분 보관 없는 현장 교체·기존 장비 바닥 배출·장비당 옵션 하나를 확정했다. 신경 쓸 것을 늘리지 않는 기존 목표에 맞춘 선택이며 구현은 아직 하지 않았다. [기록007](log/007-doc-equipment-swap-single-option.md).
- 협동 후속: 이전에는 공유/개인 보상과 획득 권한이 미결이었다. 사용자 선택으로 팀 공유 장비의 선착순 획득과 내려놓은 장비의 팀원 재획득을 확정했다. 교체를 통해 팀 내 장비를 나눠 쓸 수 있으며 아직 구현 전이다. [기록008](log/008-doc-shared-equipment-pickup.md).

## C-35 자동 달리기는 이동 편의와 재배치

- 결정: 별도 달리기 조작·공용 기력을 관리하지 않는다. 조준·총 발사·피격 시 걷기, 그 상태가 끝난 뒤 일정 시간이 지나면 자동 달리기. 구르기 후 걷기 복귀. 자동 달리기도 좀비보다 느리게 해 전투 사이 이동과 잠깐 공격을 멈춘 재배치를 돕는다.
- 이유: 사용자 — 전투 전에는 교전을 피할 여지가 있지만 이미 추격당하면 싸우는 쪽이 유리해야 하며, 달리기는 이동 편의만 주려는 것.
- 상태 · 날짜: `[현재 구현 / 수치 임시]` · 2026-10-29. 사용자 수락한 임시 기준은 걷기 3.6m/s·자동 달리기 4.2m/s·자동 달리기 대기 2초이며 플레이하면서 조정한다. 모든 지형에서 절대 도망칠 수 없게 하는 규칙은 아니다. [구현·검사](log/006-code-automatic-movement-roll.md).
- 구현 판단(AI): 기존 무기·카드·상태 배율을 적용한 일반 이동에4.2m/s 상한을 둔다. SMG110%가4.62m/s로 일반 감염체4.55m/s를 넘는 것을 방지한다. 치료·장전·투척/충전·거치 공격·상호작용 중에는 자동 달리기를 막고 기존 감속을 유지한다. 양수 이동 보너스는 상한 아래에서만 유효하며 난전 카드 밸런스는 플레이 후 조정한다. 상세 계약은 [설계10장](equipment-movement-plan.md#10-이동-구현-범위와-초기-처리).
- 근거: 사용자 대화, [설계 초안](equipment-movement-plan.md), `Player.cs` 이동 및 피격 처리. 기존 C-31의 단순 걷기로 추격을 무시할 수 없다는 의도와 함께 조정한다.

## C-36 장비 옵션은 다섯 데이터 표, 게임에서는 비공개

- 결정: 장비 옵션을 데이터로 나눠 관리한다 — **효과**(치명타 피해 · 치명타 확률 · 대미지 감소 등, 허용 범위), **조건**(항상 · 조준 중 · 집중 한 발 · 집중 뒤 n초 · 피해를 입으면 n초 · 구르는 동안, 변수 종류), **완성 옵션**(효과 + 조건 + 값), **옵션 그룹**(후보 옵션 묶음), **장비**(옵션 그룹을 가짐). 옵션은 장비가 바닥에 생길 때 그룹에서 하나로 정해진다. 서로 다른 종류를 섞은 그룹도 된다("먹기 전까지 모르는 모자").
- **옵션은 게임 안에서 전부 비공개.** 일반 화면은 장비 아이콘 · 이름만 보인다. 옵션 값 · 조건 · 켜짐 표시는 **개발자 모드(M-41)에서만** 보인다. 나중에 공개 범위를 바꿀 수 있게(예: 생성 때 정해지는 랜덤 옵션 장비는 처음부터 공개) 보이는 UI와 안 보이는 UI를 둘 다 만든다.
- AI가 덧붙인 것(2026-10-30 사용자 수락): 그룹 가중치, 영문 ID + 언어 키, 효과 표의 범위는 안전 범위이고 실제 값은 완성 옵션의 고정 값, 바닥 장비 = (장비 ID, 옵션 ID) 한 쌍으로 교체 · 이월 · 동기화, 금지 조합(집중 한 발 + 치명타 확률)은 불러올 때 거름, 설명 문장 자동 생성. [설계](item-option-data.md) 2 · 3장.
- 이유: 사용자(2026-10-30) — "옵션 종류를 데이터로 분리 관리가 필요하지 않을까? 나중에 양산하고 랜덤 옵션 넣고 하려고 하면" · "옵션은 게임에서는 전부 비공개로 할까 해, 신경 쓰지 않고 먹을 수 있도록. 무기의 자세한 정보도 장착 후 사용해서 느끼는 게 다인 것처럼 … 개발자 모드일 때만 노출 … 옵션이 노출되는 UI와 노출되지 않는 UI를 둘 다 고려해서 만들긴 해야겠어".
- 상태 · 날짜: `[방향 확정 / 데이터 · 평가 구현]` · 2026-10-30. 다섯 표 · 불러오기 · 비중 고르기 · 착용 · 조건 평가([기록 017](log/017-code-equipment-data.md), `game/content/data/equipment/`, `EquipmentDatabase`)와 실제 사격 연결(치명타 확률 · 피해 · 퍼짐 · 반동, [기록 018](log/018-code-equipment-combat.md))은 구현, 줍기 · 비공개/개발자 모드 UI · 동기화는 구현 전. **옵션 값은 행마다 고정, 나오는 정도는 그룹 비중(가중치)**(사용자 "옵션값은 비중값을 두도록 진행, 모두 추천안으로 진행해줘"). 수치는 C-34의 테스트 값만 수락된 값이다.

## C-33 무기 배치는 공용(무한)과 1회 두 종류

- 결정: 놓인 무기는 두 종류. **공용(무한)** 은 스테이지 시작 기지와 큰 구역 사이 중간 보급 기지에만, **테이블 위**에 두고 집어도 남는다(사람마다 몇 번이든). **같은 총을 들고 집으면 총을 버리지 않고 탄창 · 예비탄만 채운다**("[E] 탄약 채우기 ∞"). 다른 총을 들고 집으면 바꿔 들고 내 총은 바닥에 1회 픽업으로 떨어진다(지금 규칙). **1회** 는 길 위 · 곁길 · 보상 자리, 먼저 집은 한 명. 표식: 공용은 **둥근 모서리 네모 + 이름 옆 ∞**, 1회는 지금 원, 색은 둘 다 칸 색. 기지의 탄약 더미도 무한. 투척물은 무한이 아니라 사람 수만큼 1회.
- 이유: 사용자(2026-10-28) — "레포데 보면 누가 먹어도 계속 먹을 수 있는 구조랑 한 명만 먹을 수 있는 거 나눠져 있으니 우리도 가져옴", 무한은 시작 세이프하우스 · 중간 보급소 테이블 위, 같은 총은 총알만 리필. 표식은 추천안 수락("나머지는 추천안으로"): 60° 카메라에서 테이블 + 모양이 색보다 먼저 읽히고, 색은 이미 칸에 쓰며, 여러 줄 링은 등급으로 오해됨. 근거: L4D 무기 배치(개수 · 무한 플래그 · 탄약 더미).
- 상태 · 날짜: `[확정]` 2026-10-28. **같은 날 구현**([레벨 log/013](../level/log/013-code-stage1-tutorial.md)): `WeaponPickup.MakeInfinite`(둥근 네모 · ∞ · 테이블 위), `Stage.TakeShared`, `WeaponState.FillUp`, 보급 데이터 `infinite`(작업대를 그 아래 놓음).
- 근거 코드 · 규격: [Stage 1 튜토리얼 플레이 시나리오](../level/stage1-tutorial-scenario.md) 3장, `WeaponPickup`, `Stage.PickUp`.
