# 전투 — 결정 본문

## C-1 구르기는 기본 2회 충전, 기본 무적 없음 — 2026-10-29 후속

- 결정: 기본 최대 충전 2회. 첫 동작을 끝낸 뒤 연속 사용 가능. 기본 무적 없음. 구르기 중 일반 피격은 피해를 받고 자동 달리기 대기시간을 갱신하되 구르기 동작은 끝까지 이어진다. 종료 후 걷기로 복귀한다. 최대 충전 증가 일반 장비는 만들지 않으며 치트·테스트용 확장 가능성과 난전 특수옵션 검토만 남긴다.
- 충전 회복(같은 날 사용자 확정): 한 칸씩 순서대로 회복한다. 두 번째 구르기를 사용해도 이미 진행 중인 회복은 초기화하지 않는다. 현재 칸이 회복되면 비어 있는 다음 칸을 회복한다.
- 회복 시작(같은 날 사용자 후속): 새 충전 회복은 구르기 종료 시점부터 시작한다. 이미 시작된 회복은 추가 사용 시 진행 보존 규칙을 따른다.
- 임시 수치·회복 지속(같은 날 사용자 수락): 한 칸 회복은 6초. 두 번째 구르기 동작 중에도 이미 진행 중인 회복은 멈추거나 초기화되지 않고 계속된다. 시간은 플레이하면서 조정한다.
- 이유: 사용자 — 급할 때 두 번 연속 회피할 수 있게 하되 구르기를 무적으로 보지 않는다. 달리기 조작·기력 관리를 늘리지 않는다.
- 상태 · 날짜: `[현재 구현 / 수치 임시]` · 2026-10-29. 충전 회복 6초는 사용자 수락한 테스트 기준. 구르기 피해 감소와 충전시간 단축 갑옷은 옵션 후보이며 실제 제작 확정 아님. [구현·검사](log/006-code-automatic-movement-roll.md).
- 근거: 사용자 대화, [설계 초안](equipment-movement-plan.md), `game/scripts/Player/Player.cs`의 `TryStartRoll`, `TakeDamage`. C-2 모션과 기존 옆 밀어내기·통과는 이번 결정에서 변경하지 않는다.

### 바뀐 결정 — C-1

- 이전: 5초 재사용 대기시간, 회피 중 무적(C-1, 2026-10-19). 원문과 당시 확인 기록은 [전체 결정 기록](../../decisions.md)에 보존.
- 이후: 기본 2회 충전, 무적 없음, 일반 피격에도 동작 지속·달리기 대기시간 갱신, 종료 후 걷기.
- 이유: 2026-10-29 사용자 결정. 최초 기록 당시 코드는 이전 방식이었다. 같은 날 사용자 구현 요청에 따라 `PlayerMovement.cs`의 순차 충전·일반 피해 처리·HUD·멀티 동기화를 구현했다. 특수 강제 이동/잡기 면역은 별도 미결 규칙이므로 기존 처리를 유지한다.
- 같은 날 충전 규칙 후속: 이전에는 순차/동시 회복과 두 번째 사용의 영향이 미결이었다. 이후 사용자 선택으로 한 칸씩 순차 회복·추가 사용 시 기존 진행 보존을 확정했다. 첫 회복 시작 시점과 시간은 계속 미결이다.
- 같은 날 회복 시작 후속: 위 미결 중 첫 회복 시작 시점은 사용자 선택으로 구르기 종료 시점으로 확정했다. 회복시간은 아직 미결이며 6초는 AI 제안으로만 기록한다.
- 같은 날 임시 수치 수락: 이전의 6초 제안을 사용자가 테스트 기준으로 채택했다. 두 번째 구르기 중 진행 중인 회복을 계속하고, 시간은 플레이하면서 조정한다.

## C-34 모자·갑옷 두 슬롯과 캠페인 샛길 보상

- 결정: 모자·갑옷 두 슬롯을 캠페인과 난전에 적용, 모드 2는 보류. 기능 옵션만 붙이고 당장은 내구도 없음. 캠페인 샛길 보상은 모자·갑옷·가끔 특수 무기 중 하나로 구상한다.
- 교체·옵션(2026-10-29 사용자 수락): 여분 장비를 들고 다니지 않는다. 현장에서 교체하면 기존 장비를 바닥에 내려놓는다. 우선 장비당 기능 옵션은 하나로 한다. 별도 벗기 조작은 아직 정하지 않는다.
- 협동 획득(같은 날 사용자 확정): 바닥 장비 하나를 팀이 공유하며 먼저 획득한 사람이 착용한다. 교체로 내려놓은 장비는 다른 팀원도 가져갈 수 있다. 개인별로 같은 보상을 복제하지 않는다. 보상 지점별 배치 수량과 AI 동료 획득 행동은 미결이다.
- 이유: 사용자 — 샛길을 돌아갈 메리트를 주면서 신경 써야 할 것을 더 늘리지 않는다. 캠페인은 레벨 없음·저장 최소화·일반 패턴 단순화, 보스 패턴 대응을 지향한다.
- 상태 · 날짜: `[방향 확정 / 구현 전]` · 2026-10-29. 옵션 목록·수치·보상 지점별 배치 수량·이월·외형 연결은 미결. 치명타 1%·이속 1%·탄창 10%는 사용자 예시다. 저장 세부 계약은 이번에 정하지 않는다.
- 근거: 사용자 대화, [설계 초안](equipment-movement-plan.md), [캠페인 방향](../direction/game-direction.md), [시나리오 상세](../../scenario-level-design.md). C-3 무기 슬롯과 별개다.

### 바뀐 결정 — C-34 교체와 옵션 수

- 이전: 획득/교체/보관 규칙 미결, 장비당 대표 옵션 하나는 AI 제안.
- 이후: 사용자 수락으로 여분 보관 없는 현장 교체·기존 장비 바닥 배출·장비당 옵션 하나를 확정했다. 신경 쓸 것을 늘리지 않는 기존 목표에 맞춘 선택이며 구현은 아직 하지 않았다. [기록007](log/007-doc-equipment-swap-single-option.md).
- 협동 후속: 이전에는 공유/개인 보상과 획득 권한이 미결이었다. 사용자 선택으로 팀 공유 장비의 선착순 획득과 내려놓은 장비의 팀원 재획득을 확정했다. 교체를 통해 팀 내 장비를 나눠 쓸 수 있으며 아직 구현 전이다. [기록008](log/008-doc-shared-equipment-pickup.md).

## C-35 자동 달리기는 이동 편의와 재배치

- 결정: 별도 달리기 조작·공용 기력을 관리하지 않는다. 조준·총 발사·피격 시 걷기, 그 상태가 끝난 뒤 일정 시간이 지나면 자동 달리기. 구르기 후 걷기 복귀. 자동 달리기도 좀비보다 느리게 해 전투 사이 이동과 잠깐 공격을 멈춘 재배치를 돕는다.
- 이유: 사용자 — 전투 전에는 교전을 피할 여지가 있지만 이미 추격당하면 싸우는 쪽이 유리해야 하며, 달리기는 이동 편의만 주려는 것.
- 상태 · 날짜: `[현재 구현 / 수치 임시]` · 2026-10-29. 사용자 수락한 임시 기준은 걷기 3.6m/s·자동 달리기 4.2m/s·자동 달리기 대기 2초이며 플레이하면서 조정한다. 모든 지형에서 절대 도망칠 수 없게 하는 규칙은 아니다. [구현·검사](log/006-code-automatic-movement-roll.md).
- 구현 판단(AI): 기존 무기·카드·상태 배율을 적용한 일반 이동에4.2m/s 상한을 둔다. SMG110%가4.62m/s로 일반 감염체4.55m/s를 넘는 것을 방지한다. 치료·장전·투척/충전·거치 공격·상호작용 중에는 자동 달리기를 막고 기존 감속을 유지한다. 양수 이동 보너스는 상한 아래에서만 유효하며 난전 카드 밸런스는 플레이 후 조정한다. 상세 계약은 [설계10장](equipment-movement-plan.md#10-이동-구현-범위와-초기-처리).
- 근거: 사용자 대화, [설계 초안](equipment-movement-plan.md), `Player.cs` 이동 및 피격 처리. 기존 C-31의 단순 걷기로 추격을 무시할 수 없다는 의도와 함께 조정한다.

### 바뀐 결정 — C-35 대기시간

- 이전: 대기시간 미결, 2초는 AI 제안. 이후: 사용자 수락으로2초를 임시 기준으로 채택하고 플레이하면서 조정한다(2026-10-29). 조준 해제·마지막 발사·피격·구르기 종료 중 가장 늦은 시점부터 세며 조준 중에는 달리지 않는다.

### 바뀐 결정 — C-35 이동 속도

- 이전: 걷기·자동 달리기 속도 미결. 이후: 걷기 3.6m/s·자동 달리기 4.2m/s를 사용자 수락한 임시 기준으로 채택(2026-10-29). 달려도 좀비보다 느리게 하면서 이동 편의를 주려는 목적이며 플레이 후 조정한다. 현재 코드의 기본 4.4m/s는 이번 문서 작업에서 변경하지 않았다.
- 같은 날 구현 후속: 사용자 요청에 따라 캐릭터 기본 걷기 값을3.6m/s로 변경하고 자동 달리기·대기·일반 이동 상한을 적용했다. 실제 발사(예약 추가 발사 포함)와 피해가 대기를 갱신한다. 이전 문장의 미변경 표기는 설계 기록 당시 이력이다.

## C-30 조준 표시의 의미와 강조 보강

- 결정(2026-10-28 갱신): 기존 C-30 조준·퍼짐·반동 판정은 유지한다. 중앙점은 조준 위치, 계열별 주 도형은 현재 퍼짐, 옅은 안쪽 짧은 눈금은 완전 조준 후 기준이다. 권총=꺾인 좌우, SMG=좌우 호, 소총=십자, LMG=각진 모서리, 산탄=분절 원호, 저격=가늘고 긴 눈금(DMR은 짧음). 실제 산탄 폭은 PelletSpread와 AimProgress를 읽는다. 반투명 어두운 받침·청회색 경계·흰 중심선·부드러운 번짐을 충전 UI와 통일한다.
- 이유: 사용자 요청 「타겟 조준도 개선」과 의미 없는 표시 제거/있는 정보의 인지 개선. 조준 중심/기준 퍼짐에 우선순위를 주고 Esc 조작법에서 의미를 설명한다.
- 상태 · 날짜: `[현재 구현]`, 수치는 제작값·외형 최종 수락 전 · 2026-10-27.
- 표시 의미(2026-10-28 현재): 주 눈금 가장자리의 붉은 열기는 사격 상태, 주 눈금 주황/빨강은 유효/최대사거리 경고, 대각 두 줄은 실제 내 공격 명중, 황금 원은 집중 진행과 다음 한 발 치명타 준비(C-32). 한국어/영어 `hud_reticle_legend`로 안내한다. 조준 보조나 명중 보장 규칙을 추가하지 않는다.
- 범위: 무기 데이터·사거리·퍼짐·반동·집중 타이머/소비·치명타 판정은 변경하지 않는다. 장전/충전 고정 네 점 제거는 [M-33](../menu-ui/decisions.md#m-33-장전충전-포인터와-반투명-진행-ui).
- 근거: 사용자 요청, [Hud.cs](../../../game/scripts/UI/Hud.cs), [무기 규격 8장](../../weapon-spec.md), [검사·렌더 기록](../menu-ui/log/003-code-reticle-clarity.md). 기존 C-30 원문은 [전체 결정 기록](../../decisions.md)의 표에 그대로 보존한다.

### 바뀐 결정 — 외형 강조

이전에는 주/보조 눈금이 모두14×4px였고 대각 열기/명중의 번짐은 넓은 두 선이었다. 이후 기준 눈금 크기를 유지하고 보조 눈금만 낮추며 상태 번짐과 집중 원의 재질감을 통일한다. 근거는 표시의 우선순위를 읽기 쉽게 하라는 이번 사용자 요청이다. 기존 동작의 의미는 바뀌지 않는다.

### 바뀐 결정 — 2026-10-28 무기 계열 형태

- 이전: 모든 총이 동일한 상하좌우 조준 기준 눈금과 대각 현재 퍼짐 눈금. 기준 눈금을 가장 강조했다.
- 이후: 현재 퍼짐의 계열 형태를 우선하고 완전 조준 기준은 옅은 안쪽 보조 눈금으로 남긴다. 중앙 거리색과 실제 명중 두 줄은 유지하고 사격 열기는 주 도형의 색 가장자리로 옮긴다. 집중은 주 도형 바깥, 탄창 원호보다 안쪽 황금 호다. 기존 14×4px 공통 고정 폭 대신 형태별 1.9~3.2px 중심선에 반투명 경계를 조합한다.
- 이유: 사용자 제공 디비전1 무기10개 영상의 계열 식별 특성을 우리 쿼터뷰에 적용하는 추천안을 사용자가 수락. 후속 요청은 “전체적으로 지금 충전의 UI퀄리티와 동급”, 굵기 변화·반투명·색 조합·경계선 처리.

- 근거: [설계·계획](../menu-ui/weapon-reticle-plan.md), [검사·제약](../menu-ui/log/009-code-weapon-reticles.md), `HudReticle.cs`, `Hud.DrawReticle`. 발사 방식/탄창 전환은 M-33 후속.

## C-33 무기 배치는 공용(무한)과 1회 두 종류

- 결정: 놓인 무기는 두 종류. **공용(무한)** 은 스테이지 시작 기지와 큰 구역 사이 중간 보급 기지에만, **테이블 위**에 두고 집어도 남는다(사람마다 몇 번이든). **같은 총을 들고 집으면 총을 버리지 않고 탄창 · 예비탄만 채운다**("[E] 탄약 채우기 ∞"). 다른 총을 들고 집으면 바꿔 들고 내 총은 바닥에 1회 픽업으로 떨어진다(지금 규칙). **1회** 는 길 위 · 곁길 · 보상 자리, 먼저 집은 한 명. 표식: 공용은 **둥근 모서리 네모 + 이름 옆 ∞**, 1회는 지금 원, 색은 둘 다 칸 색. 기지의 탄약 더미도 무한. 투척물은 무한이 아니라 사람 수만큼 1회.
- 이유: 사용자(2026-10-28) — "레포데 보면 누가 먹어도 계속 먹을 수 있는 구조랑 한 명만 먹을 수 있는 거 나눠져 있으니 우리도 가져옴", 무한은 시작 세이프하우스 · 중간 보급소 테이블 위, 같은 총은 총알만 리필. 표식은 추천안 수락("나머지는 추천안으로"): 60° 카메라에서 테이블 + 모양이 색보다 먼저 읽히고, 색은 이미 칸에 쓰며, 여러 줄 링은 등급으로 오해됨. 근거: L4D 무기 배치(개수 · 무한 플래그 · 탄약 더미).
- 상태 · 날짜: `[확정]` 2026-10-28. **같은 날 구현**([레벨 log/013](../level/log/013-code-stage1-tutorial.md)): `WeaponPickup.MakeInfinite`(둥근 네모 · ∞ · 테이블 위), `Stage.TakeShared`, `WeaponState.FillUp`, 보급 데이터 `infinite`(작업대를 그 아래 놓음).
