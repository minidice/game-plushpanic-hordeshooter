## 검토한 현재 상태

- 장비: C-34 · [구현 계획](../equipment-implementation-plan.md)은 코드 전이다. 계획의 Task 1이 `equipment.csv` 한 표에 효과 · 조건 · 값을 한 줄로 두고, Task 3이 HUD · 바닥 비교 안내에 조건/수치를 보이며, Task 4가 장비 ID만 동기화하게 되어 있었다.
- 보급: `game/content/data/stages/stage*_supplies.json`은 이미 레이아웃과 따로 있다. 다만 지점마다 **좌표와 내용**(무기 ID · `infinite` · `per_person`)이 함께 있고, 한 지점이 3 m 안에 여러 아이템을 묶는다(`StageSupplies.CheckLayout`). 랜덤은 없다. 레이아웃의 `supplies`는 가이드 표시 점이다.
- 무작위 · 시드: 난전 맵은 `GameSession.MapSeed`로 방 전체가 같은 맵을 짓는다. 바닥 루트(`LootPickup`)는 호스트가 만들고 알린다.

## 후속: 추천안 모두 수락 (2026-10-30)

- 사용자 "옵션값은 비중값을 두도록 진행, 모두 추천안으로 진행해줘".
- 정한 것: 옵션 값은 행마다 고정이고 나오는 정도는 그룹 비중(가중치)으로, 좌표는 맵, 개발자 모드는 저장하지 않음 · 다른 디버그 기능 묶음은 나중, 옵션은 전부 비공개, 같은 판의 같은 랜덤 결과 반복 허용. AI가 덧붙인 것도 수락으로 바꿨다.
- 바꾼 문서: [설계](../item-option-data.md)(상태 · 2 · 4 · 5장, 6장 「정한 것 · 남은 것」, 변경 이력), C-36 · M-41 · L-40 본문과 색인 줄, [구현 계획](../equipment-implementation-plan.md)(Task 4 개발자 모드 저장 안 함, 변경 이력).
- 새 결정 ID는 만들지 않았다. 미결이던 항목을 같은 결정 안에서 정한 것이라 「바뀐 결정」에도 넣지 않았다.

## 남은 제약

- 표 · 열 · 파일 이름은 구현 때 바뀔 수 있다. 실제 옵션 등급표와 비중 수치는 테스트 9종 이후에 정한다.
- 개발자 모드를 나중에 다른 방식으로 바꿀지는 사용자 고민 중이다(M-41 형태 임시).
- 코드 · 데이터 · UI는 아직 없다. 장비 구현 계획 Task 1부터 이 구조로 한다. 아이템 배치(L-40)는 레벨 작업으로 따로 한다.
