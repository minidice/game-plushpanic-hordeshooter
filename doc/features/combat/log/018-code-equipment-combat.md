# 018 · code · 장비를 실제 사격에 연결 (C-32 · C-34 · C-36, 구현 계획 Task 2)

- 작성일: 2026-10-30. 종류: code(사격 · 치명타 · 퍼짐 · 반동 · 집중 · 조준점 · 검사). 관련: C-32(집중 보장 치명타), C-34(9개 테스트 조합), C-36, [구현 계획](../equipment-implementation-plan.md) Task 2, [기록 017](017-code-equipment-data.md).
- 사용자: "Task 2 진행".

## 변경 사항

- **`Equipment/EquipmentCombat.cs`(새)**: 순수 함수 두 개.
  - `IsCritical(guaranteed, chance, sample01)`: 집중 한 발은 항상 치명타, 아니면 난수 < 확률.
  - `CritFactor(무기 배율, 모이기 카드, 장비 치명타 피해)`: 세 값을 곱한다.
- **`WeaponController`**:
  - **발사 순간 고정 `_shot`(`RollShot`)**: 발사 · 휘두름 · 특수 무기 메아리마다, 그 순간의 조준 상태로 장비를 평가해 치명타 확률 · 치명타 피해(일반 / 집중 한 발) · **치명타 난수 하나**를 정한다. 난수는 기존 `_rng`와 따로 둔 `_critRng`에서 뽑는다. 그래서 장비가 있어도 퍼짐 · 반동 난수 순서는 그대로다.
  - **멀티**: 확률 치명타는 호스트 · 혼자 할 때만(`Stage.Authoritative`) 굴린다. 클라이언트의 자기 사격은 표시용이라 확률을 굴리지 않는다(난수를 1로 두어 확률 치명타 없음). 실제 피해는 지금처럼 호스트가 정한다.
  - **치명타 판정 `Crit`**: 직사(같은 높이 · 아래 단)와 근접의 기존 세 곳을 한 함수로 모았다.
    - 집중 대상의 첫 명중은 보장 치명타(기존).
    - 첫 명중(관통 전)은 장비 확률로 치명타. 한 발에 난수 하나라서 **산탄의 펠릿은 모두 같은 결과**다.
    - **집중 한 발 전용 치명타 피해는 보장 치명타에만** 붙는다. 확률 치명타에는 일반 장비 치명타 피해만 붙는다.
    - 근접 휘두름은 한 번 굴려 닿은 모든 적에 같은 결과를 쓴다.
    - 폭발 · 로켓 · 박격포 · 지속 피해에는 새 치명타를 넣지 않았다(계획대로).
  - **퍼짐 `ShotCone(gun, fullyAimed)`**: 산탄 원뿔 계산과 장비 퍼짐 배율을 한곳에 모았다. 직사 · 산탄 · 로켓 발사와 HUD 조준점이 같은 값을 쓴다.
  - **반동**: `WeaponRecoil.Kick(def, rng, scale)`에 장비 반동 배율(조준 상태 기준)을 넘긴다. 위로 · 옆으로 차는 양만 줄고, 되돌아오는 속도와 캐릭터 밀림은 그대로다.
- **`Hud.cs`**: 조준점 원(지금 · 다 조준했을 때)을 `ShotCone`으로 그린다(장비 퍼짐 반영).
- **`Player.CritReady` · 집중**(계획의 "원격 집중"):
  - 이전에는 로컬 사람만 집중 치명타가 있어서, 호스트에서 원격 사람의 실제 사격은 치명타가 나지 않았다.
  - 이제는 사람(봇 제외)이고 "자기 PC" 또는 "호스트 · 혼자"일 때 준비된다.
  - 집중 대상 찾기에서 `IsSeen`(이 PC의 시야)은 로컬 사람에게만 쓴다. 호스트는 원격 사람이 무엇을 보는지 모르므로 그 사람이 보낸 조준점만으로 판단한다.
  - 클라이언트는 다른 사람의 집중을 판단하지 않는다.

## 검사

- 실패 먼저: 검사를 먼저 쓰고 빌드 → `EquipmentCombat` · `ShotCone` · `Kick` 인수 3개 없음으로 실패(CS0103 · CS1061 · CS1501) 확인.
- 이 작업 폴더의 Godot 가져오기가 두 번 도중에 꺼졌다(segfault, 첫 번째는 26%, 두 번째는 효과음 다시 가져오기 중). 세 번째에 종료 0으로 끝났다. 그 전 첫 실행은 자원이 없어 장면이 시작 전에 실패했다(검사 내용과 무관).
- `EquipmentCombatCheck`(새, 헤드리스) 첫 결과:
  - 산탄 검사 실패 — 16발 중 1발은 펠릿 하나만 맞았다(넉백으로 표적이 밀림). "15발 중 14발이 2개 이상"으로 조건을 고쳤다.
  - 원격 집중 검사 실패 — 시야가 매 프레임 `IsSeen`을 다시 켜서, 원격 판정이 호스트 시야와 무관하다는 것을 실제로 시험하지 못하고 있었다. 이 부분 동안 시야를 멈추고 `IsSeen`이 꺼진 채인지 먼저 확인하게 고쳤다.
- 최종: 종료 0, 실패 0, 누수 0, **`EQUIPMENT_COMBAT_PASS 25`**.
  - 순수 판정: 3%에서 0.029 / 0.031, 보장 · 확률 0, 반동 0.75배.
  - 실제 M4 피해 비율:
    - 장비 없음: 집중 ×2.5.
    - 집중 머리띠: 집중 ×3.25, 일반 사격은 그대로.
    - 확률 100% 장비: 확률 치명타 ×2.5(머리띠 보너스 없음), 집중 ×3.25.
    - 사냥꾼 모자: 비조준 ×2.5, 조준 ×3.0.
    - 조준 전용 확률: 조준을 풀면 꺼짐.
  - 산탄 R870 · 확률 50%: 15발 중 9발 치명타. 한 발의 펠릿은 모두 같은 결과.
  - 퍼짐: 안정 조끼 6° → 5.4°. 같은 총의 분대원은 그대로. 사수 조끼는 비조준 그대로, 다 조준한 원뿔과 실제 조준 원뿔은 0.85배.
  - 반동: 견착 멜빵은 조준 중 한 발에 위로 0.75배, 비조준은 그대로.
  - 원격 집중: 호스트 시야 밖에서도 원격 사람은 조준점으로 집중 준비, 호스트 자신은 시야 필요, 분대원은 집중 없음.
- 회귀(헤드리스, 모두 종료 0 · 실패 0 · 누수 0 · 오류/경고 줄 0):
  - `EquipmentCheck` 51
  - 사격 · 이동: `WeaponAimCheck` 32 · `WeaponHandlingCheck` 36 · `MovementEchoCheck` 1 · `MovementCheck` 22
  - `SquadCheck` 52
  - 네트워크: `NetSyncCheck` 32 · `PartyNetCheck` 37 · `MovementNetCheck` 12
  - `Integration` 149
- 렌더: 장비가 없으면 조준점은 이전과 같은 값이다(`ShotCone` = 기존 식 × 1). 게임 안에서 장비를 얻을 길(Task 3)이 아직 없어 화면 변화가 없으므로 렌더는 Task 3에서 한다.

## 남은 제약

- 실제 두 PC · ENet에서 원격 사람의 집중 · 확률 치명타 · 표시가 호스트와 맞는지는 Task 4에서 확인한다.
  - 호스트는 원격 사람의 시야를 몰라, 그 사람 화면에서 안 보이는 적에게도 집중이 찰 수 있다(드묾).
  - 클라이언트 자기 화면의 "CRIT!" · 조준점 표시는 집중 치명타만 미리 보여준다. 확률 치명타는 호스트 결과가 와야 보인다.
- 수치는 C-34 테스트 값이다. 최종 체감은 사용자 플레이 후 정한다. HUD의 장비 칸 · 일반/개발자 모드 표시는 Task 3이다.
