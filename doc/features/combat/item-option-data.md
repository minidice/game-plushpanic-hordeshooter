# 아이템 옵션 · 배치 데이터 설계

2026-10-30. 관련: **C-36**(옵션 데이터 · 비공개), **M-41**(개발자 모드), **L-40**(아이템 배치 데이터), C-33(공용 · 1회 무기), C-34(모자 · 갑옷 두 슬롯), [장비 구현 계획](equipment-implementation-plan.md), [기록 016](log/016-doc-item-option-data.md).

상태: **사용자 확정(2026-10-30, AI 추천안 모두 수락), 구현 전.** 사용자가 처음 정한 것과 AI가 덧붙여 수락받은 것을 나눠 적는다. 표의 열 이름 · 파일 이름은 구현 때 바뀔 수 있는 초안이다. 예시 수치는 C-34에서 수락한 테스트 값만 실제 값이다.

## 1. 사용자 요청

- 옵션 종류를 데이터로 나눠 관리한다. 나중에 장비를 양산하고 랜덤 옵션을 붙이기 위해서다.
  - **옵션(효과)**: 치명타 피해 · 치명타 확률 · 대미지 감소 등. 각 값은 몇부터 몇까지 가능한지 정한다.
  - **조건**: 조준 시 · 항상 · 집중 시 · 집중 뒤 n초 동안 · 피해를 입으면 · 구르는 동안. 변수가 어떤 값을 갖는지, 변수가 없을(null) 때 어떻게 동작하는지 정한다.
  - **완성 옵션**: 예를 들어 A1 = 항상 치명타 피해 1%, A2 = 1.5%, A3 = 2%.
  - **옵션 그룹**: "항상-치명타피해증가-1" 그룹은 A1 · A2를, "-2" 그룹은 A2 · A3를 가진다.
  - **아이템**: 옵션 그룹을 들고 있다. 필드에 생성될 때 그룹 안에서 하나가 정해진다. 전혀 다른 종류를 섞은 그룹도 된다("먹기 전까지 무슨 옵션이 붙는지 모르는 모자").
- 아이템 배치:
  - 캠페인의 세이프하우스와 중간 거점은 지정된 무기를 준다.
  - 샛길에서 벗어나 찾아가면 발견하는 아이템은 랜덤이다. 단, 정해진 후보 안에서만 고른다.
  - 맵에 아이템을 직접 쓰지 않고 자리 코드만 쓴다(예: `S1-1`). 아이템 배치 데이터가 그 코드에 무엇을 놓을지 정한다(예: `S1-1` = 권총 A, 모두 집을 수 있음 true).
  - 랜덤 타입 데이터: `SR1-1` = 투구 1 · 투구 2 · 알라봉 중 하나. 판마다 바뀐다.
  - 맵 정보와 아이템 드랍 정보는 성격이 달라서 나눈다.
- 후속(2026-10-30) **옵션 비공개**:
  - 게임 안에서 옵션은 **전부 비공개**로 한다. 신경 쓰지 않고 먹도록, 무기의 자세한 정보도 써 보며 느끼는 것처럼 둔다.
  - 옵션은 **개발자 모드일 때만** 보인다. 개발자 모드는 일단 게임 설정(로비 → 게임 들어가는 곳)의 체크박스이고, 멀티는 방장 설정을 따른다.
  - 나중에 공개하는 구조로 바뀌더라도, 랜덤 옵션 아이템은 처음부터(생성될 때 정해지므로) 옵션을 보여도 괜찮다.
  - 그래서 옵션이 보이는 UI와 보이지 않는 UI를 **둘 다** 고려해 만든다.

## 2. 옵션 데이터 (C-36)

다섯 개 표로 나눈다. 앞의 네 개는 사용자 구조이고, 마지막 장비 표가 아이템에 해당한다. 카탈로그 성격이라 기존 `weapons.csv`처럼 CSV로 두고, 둘째 줄에 한국어 설명 주석 줄을 둔다(AI 제안).

| 파일(초안) | 사용자 이름 | 한 줄의 뜻 | 열(초안) |
|---|---|---|---|
| `option_stats.csv` | 옵션 | 조정할 수 있는 수치 하나 | `id`, `name_key`, `unit`(pp · pct), `apply`(add · mult), `min`, `max`, `slots` |
| `option_conditions.csv` | 다른 조건 | 발동 조건 하나 | `id`, `name_key`, `param`(none · seconds), `param_min`, `param_max` |
| `options.csv` | 완성 옵션 | 효과 + 조건 + 값 | `id`, `stat`, `condition`, `param`, `value`, `grade` |
| `option_groups.csv` | 옵션 그룹 | 그룹 안의 후보 하나 | `group`, `option`, `weight` |
| `equipment.csv` | 아이템 | 장비 하나 | `id`, `slot`, `name_key`, `icon`, `option_group` |

예(값은 C-34 테스트 값과 AI 예시):

```
option_stats.csv       crit_damage, name_stat_crit_damage, pct, mult, 0, 100, head|armor
option_conditions.csv  always, name_cond_always, none
                       after_hurt, name_cond_after_hurt, seconds, 1, 10
options.csv            crit_dmg_always_1, crit_damage, always, , 10, 1
                       crit_dmg_always_2, crit_damage, always, , 15, 2
                       crit_dmg_focus_1, crit_damage, focused_shot, , 30, 1
option_groups.csv      crit_dmg_t1, crit_dmg_always_1, 3
                       crit_dmg_t1, crit_dmg_always_2, 1
                       mystery_head, crit_dmg_always_1, 1
                       mystery_head, recoil_aim_1, 1
equipment.csv          red_cap, head, name_gear_red_cap, res://…, crit_dmg_t1
                       mystery_cap, head, name_gear_mystery_cap, res://…, mystery_head
```

**AI가 덧붙인 것**(2026-10-30 사용자 수락):

- **그룹 가중치.** 같은 옵션을 여러 줄 넣어 확률을 맞추는 대신 `weight` 한 칸으로 정한다. 사용자 예의 "그룹 → 옵션 여러 줄"은 그대로 이 표의 줄이 된다.
- **영문 ID + 언어 키.** "항상-치명타피해증가-1" 같은 이름은 화면 문구다. ID는 `crit_dmg_t1`처럼 영문으로 두고, 이름은 `content/lan/<언어>/`에서 가져온다(무기 데이터와 같은 방식).
- **범위는 두 곳.** 효과 표의 `min`~`max`는 잘못 들어간 값을 거르는 안전 범위다. 실제로 붙는 값은 완성 옵션의 고정 `value`다. 사용자 예(A1 1% · A2 1.5%)도 고정 값 행이다. 고정 값이면 멀티 동기화 · 이월 · 저장이 옵션 ID 하나로 끝나고, 밸런스 표를 그대로 읽을 수 있다. 행마다 범위를 두고 생성할 때 굴리는 방식은 쓰지 않는다. **확정**: 옵션 값은 행마다 고정, 어떤 값이 얼마나 잘 나오는지는 그룹의 비중(가중치)으로 정한다(사용자 "옵션값은 비중값을 두도록 진행, 모두 추천안으로 진행해줘").
- **조건 변수.** `param`이 `none`인 조건(항상 · 조준 중 · 집중 한 발 · 구르는 동안)은 `options.csv`의 `param` 칸을 비운다. `seconds` 조건(집중 뒤 n초 · 피해를 입으면 n초)은 칸이 비면 불러오기 오류로 거른다(조용히 기본값을 쓰지 않음). 조건의 동작 자체(언제 켜지고 꺼지는지)는 코드에 있고, 데이터는 고르고 변수를 줄 뿐이다. 새 조건은 코드 추가가 필요하다.
- **금지 조합은 불러올 때 거른다.** 집중 한 발 + 치명타 확률(C-34, 이미 100%라 제작 제외), 효과의 `slots`에 없는 슬롯의 장비에 붙는 옵션.
- **설명 문장은 자동.** 효과 문구와 조건 문구를 이어 붙여 만든다(예: "조준 중 · 치명타 피해 +20%"). 옵션마다 손으로 쓰지 않는다. 개발자 모드 표시에 쓴다.
- **같은 효과가 겹칠 때.** 랜덤 그룹이면 모자와 갑옷에 같은 효과가 붙을 수 있다. 구현 계획의 합산 규칙(같은 효과는 더한 뒤 범위 제한)을 그대로 쓴다.
- **등급 `grade`.** 사용자 예의 "치명타 1등급"을 옵션 행의 숫자로 둔다. 지금은 표시 · 정렬용이고 규칙에 쓰지 않는다.

## 3. 바닥 장비 한 개 = (장비 ID, 옵션 ID)

- 옵션은 장비가 **바닥에 생길 때** 그룹에서 한 번 정한다(사용자). 멀티에서는 호스트가 정해 두 ID를 보낸다.
- 장비를 주우면 착용 상태가 두 ID를 가진다. 교체로 내려놓은 장비도 **같은 옵션 그대로**다. 다시 굴리지 않는다(AI, C-34의 "내려놓은 장비를 팀원이 다시 가져감"과 맞춤).
- 다음 스테이지 이월 · 늦은 합류 · 스냅샷은 장비 ID와 옵션 ID를 함께 보낸다. 구현 계획 Task 4가 장비 ID만 보내던 것을 고친다.
- 그룹 없이 옵션 하나만 가진 장비는 후보 한 줄짜리 그룹으로 쓴다(AI). 지금 테스트 9종은 9개 장비가 각자 한 줄 그룹을 갖는 꼴이다.

## 4. 옵션 비공개와 개발자 모드 (C-36 · M-41)

- **일반 화면**: 장비의 아이콘 · 이름만 보인다. 옵션 값 · 조건 · "지금 켜짐" 표시 · 바닥 비교 안내의 효과 문구는 보이지 않는다. 바닥 안내는 "[E] 착용 · 지금 장비는 바닥에" 정도만 둔다(AI 문구).
- **개발자 모드**: 같은 자리에 옵션 문장과 켜짐 여부를 더 보인다. 바닥 장비의 비교 안내에도 지금 장비와 바닥 장비의 옵션을 보인다.
- 표시 코드는 "옵션을 보이는가" 한 가지 판단(`GearInfoVisible`, 초안)으로 갈라서, 나중에 공개 범위를 바꿀 때(예: 랜덤 장비만 공개) 그 판단만 고친다(사용자 "둘 다 고려해서 만들기").
- 개발자 모드 체크박스는 M-39의 게임 설정 패널에 둔다. 싱글은 자기 값, 방은 방장 값을 참가자에게 보낸다(사용자). 개발자 모드는 **저장하지 않는다**(게임을 켤 때마다 꺼진 채로 시작, 필요할 때 체크). F8 끌림 탈출 같은 다른 디버그 기능은 **지금 묶지 않고** 나중에 정한다(추천안 수락).

## 5. 아이템 배치 데이터 (L-40)

**지금 상태**: 보급은 이미 맵(`*_layout.json`)과 따로 `*_supplies.json`에 있다. 다만 한 파일에 **좌표와 내용**(무기 ID · `infinite` · `per_person`)이 함께 있고, 한 보급 지점이 3 m 안에 여러 아이템을 묶는다. 랜덤은 없다. 레이아웃의 `supplies` 칸은 가이드 표시용 점이다.

**사용자 구조로 나누면**(열 이름 · 파일 이름은 AI 초안):

- **맵(레이아웃)**: 자리 코드 · 좌표 · 자리의 역할만.
  ```json
  "item_spots": [{"id": "S1-1", "pos": [-112, 0], "role": "main"}, {"id": "SR1-1", "pos": [69, -52], "role": "optional"}]
  ```
  역할(시작 · 길 · 샛길 · 이벤트 · 도착)은 레벨 설계 정보라 맵에 둔다(AI).
- **배치 표** `stageN_items.csv`: 자리 → 고정 아이템 또는 랜덤 표. 둘 중 한 칸만 채운다.
  ```
  spot, item, table, infinite, per_person
  S1-1, glock17, , true,
  SR1-1, , sidepath_t1, ,
  ```
  사용자의 "모두 집을 수 있음 true"는 지금의 `infinite`(C-33, 기지 테이블의 무한 무기)다. 같은 이름을 쓴다.
- **랜덤 표** `loot_tables.csv`: `table, item, weight`. 예: `sidepath_t1, helmet_1, 2` · `helmet_2, 1` · `baton, 1`. 고른 것이 장비면 장비가 다시 옵션 그룹에서 옵션을 정한다(2단).
- S / SR 접두어로 고정 · 랜덤을 나누기보다 배치 표의 `item` / `table` 칸으로 나누는 편을 권한다(AI). 코드 이름은 사람이 읽기 쉬운 대로 자유롭게 둔다.

**AI가 덧붙인 것**(2026-10-30 사용자 수락):

- **자리 하나에 아이템 하나.** 지금처럼 여러 아이템을 묶은 보급 지점은 자리 여러 개로 쪼갠다. 3 m 묶음 검사는 맵 좌표와 배치 표를 합쳐서 한다.
- **판마다 다른 결과는 호스트가 정한다.** 혼자 할 때는 판마다 새로 굴린다. 검사용으로 시드를 고정하는 실행 옵션을 둔다.
- **불러올 때 거를 것**: 맵에 있는데 표에 없는 자리 · 표에만 있는 자리 · 없는 아이템 ID · 없는 랜덤 표 · 가중치 0 이하 · 장비(모자 · 갑옷)가 샛길 · 이벤트가 아닌 자리에 놓인 경우(C-34의 샛길 보상 방향).
- **함께 고칠 것**: `StageSupplies`(읽기 · 검사), Studio 레벨디자인 화면(자리 코드 표시), 레벨 가이드 도구.
- **좌표는 맵에 둔다**(추천안 수락). 맵에는 좌표 · 자리 코드 · 역할, 배치 표에는 내용만. 지금처럼 보급 파일에 좌표까지 두는 방법은 맵 정보와 드랍 정보를 나누려는 목적에 맞지 않아 쓰지 않는다.

## 6. 정한 것 · 남은 것

2026-10-30 사용자 "옵션값은 비중값을 두도록 진행, 모두 추천안으로 진행해줘"으로 아래 추천안을 모두 수락했다.

| 질문 | 정한 것 |
|---|---|
| 옵션 값: 행마다 고정 값 / 행마다 범위를 두고 굴림 | **고정 값 + 그룹 비중(가중치)** |
| 좌표 위치: 맵 / 보급 파일 | **맵** |
| 개발자 모드 저장 여부, 다른 디버그 기능을 묶을지 | **저장하지 않음**(켤 때마다 꺼진 채 시작), 묶음은 나중에 |
| 랜덤 장비만 먼저 공개할지 | 지금은 **전부 비공개**, 표시 판단 한 곳만 바꾸면 되게 만든다 |
| 같은 판에서 같은 랜덤 결과가 반복될 때 | 처음에는 **허용** |

남은 것: 표 · 열 · 파일 이름(구현 때), 실제 옵션 등급표와 비중 수치(테스트 9종 이후), 개발자 모드를 나중에 다른 방식으로 바꿀지(사용자 "나중에 어떻게 할지 고민").
