# 사망 체액 고임과 건조 표현

관련 **A-19**, [설계·계획](../body-fluid-plan.md), [현재 결정·변경 이력](../decisions.md#a-19-사망-체액-흔적-후속), [표시 계약](../../../vfx-quality.md#사망-체액-흔적--2026-10-27).

## 요청과 변경

사용자가 사망 때 남는 원색의 원판이 어울리지 않으며, 초록/파랑/노랑 피라도 짙은색과 점성이 느껴지는 고임이어야 한다고 제안했다. 모델/이미지 대신 코드·셰이더로 먼저 구현하는 추천안을 승인했다. 기존 `hud-light-polish` 워크트리를 최신 원격 main `eedab6d`까지 fast-forward하여 병합된 영역 효과 작업을 포함한 상태에서 진행했다.

- `BodyFluidSplat`: 공유 평면/셰이더에 비대칭 고임·짧은 늘어짐·가까운 방울5개. 중앙은 짙고 불투명, 일부에만 젖은 반사와 얇은 두께 표현. 첫0.4초에 조금 퍼지고2~25초에 반사가 사라지며 어두워진다.25초 후 갱신 중단.
- 일반/Common·독 공격 계열은 올리브, 황소/보스/포획/도약/총격 계열은 남청, 풍선은 황토. 새로운 상태/피해 구분이 아닌 제작 배색이며 색/모양은 사용자 최종 수락 전이다.
- `Effects.DeathSplat`을 일반/풍선 사망에 연결. 작은 낮은 방울6개/0.32초를 추가하고0.5초에 제거한다. 기존 솜 파편·시체·사망 섬광은 유지한다.
- 폭발/보스 내려찍기의 기존 `PaintSplat`은 중립색 건조 흔적으로 대체한다. 죽음이 없는 곳에 체액이 생기지 않도록 같은 API를 분리했다. 기존 A-27/A-28/A-29의 승인된 폭발/화염/독/연무 생성기·프로필·에셋은 수정하지 않았다.
- 바닥 흔적은 기존 큐/최대160개/오래된 순 제거 유지, 발생점의 층 지면 높이를 사용한다. 전투/사망 판정·네트워크 메시지·시간·피해는 변경하지 않았다. 외부 이미지/GLB/의존성을 추가하지 않았다.

## 검사·렌더

Godot4.7.2 .NET / Windows. 동일 워크트리의 빌드/가져오기/실행은 순차. `game/output/`의 로그·렌더는 생성 산출물로 커밋하지 않는다.

| 검사 | 결과 | 로그 |
|---|---|---|
| 기존 사망 색 검사 | 의도한 실패: 밝은 페인트 색 | `body-fluid-red.log` |
| 최종 Debug 빌드 | 통과, 오류0·경고0 | 명령 출력 |
| editor import | 정상 종료0, 오류·경고 없음 | `body-fluid-import-final.log` |
| 최초 전용 headless / 실제 렌더 | 각각10/13 통과 | `body-fluid-BodyFluidCheck.log`, 당시 `body-fluid-render.log` |
| 검사 보완 후 headless, 최대144fps | **11 통과** | `body-fluid-final-headless.log` |
| 검사 보완 후1600×900 실제 렌더 | **14 통과**, 오류·경고 없음 | `body-fluid-render.log` |
| `DestructionNetCheck` | **29 통과**, 늦은 참가/폭발 중복 방지·흔적 개수 유지 | `body-fluid-DestructionNetCheck.log` |
| `Integration` | **149 통과**, 실제 사망·폭발·투척·플레이 흐름 | `body-fluid-Integration.log` |

마지막 두 회귀 검사는 최종 제품 코드에서 실행했으며 이후 제품 변경 없이 전용 검사/문서만 보완했다. 최종 로그에 `ERROR`·`WARNING`·실패·종료 누수 없음. 전용 검사는 사망 색/계열, 풍선4개, 방울 만료, 건조 후 갱신 중단, 폭발의 건조 흔적, 높은 층,160개 상한, 살아 있는 흔적의 장면 삭제를 확인한다.

실제 확인 이미지:

- `body-fluid-stage-wet.png`: 실제 창고 바닥의 일반/황소/풍선 사망. 기존 HUD·시체·솜과 함께 확인.
- `body-fluid-palette-wet.png`: 밝은/어두운 바닥에서3색의 고임·방울·국소 반사 비교.
- `body-fluid-palette-dry.png`: 같은 윤곽이 마른 뒤 광택 감소/어두워짐 확인.

최초 렌더는 깊이 마스크가 작은 덩어리마다 달라져 구름처럼 비쳤다. 중심 색을 연속적으로 만들고 불투명도를0.96으로 높였으며 얇은 반사 가장자리를 추가해 최종 렌더에서 수정했다. 새 이미지 생성 도구는 사용하지 않았다.

재현: `dotnet build game/HordeShooter.csproj --nologo -v q` 후 Godot에 `--path game --max-fps 60 res://tests/BodyFluidCheck.tscn`을 전달. headless는 `--headless`, 창은 `--resolution 1600x900`. 회귀는 각 전용 `.tscn`을 별도 실행한다. `Start-Game.ps1 -Test`는 Integration만 실행한다.

## 검사 작성·검토 중 수정

- 최초 구현 빌드에서 풍선 `Pop` 메서드에 존재하지 않는 `direction`을 참조해 실패했다. 풍선 파열의 위쪽 방울 방향으로 수정 후 최종 빌드 경고/오류0.
- 읽기 전용 코드 리뷰에서 제품 결함은 발견되지 않았다. 검사2건 지적:30프레임만 기다리면 고주사율에서0.5초 제거를 충분히 기다리지 못함, 장면 삭제 검사가 이미 상한 제거된 노드를 참조함. 전자는 SceneTreeTimer0.6초+삭제2프레임으로, 후자는 상한 처리 뒤 생존 노드의 삭제 전/후 상태를 검사하도록 수정했다. 수정본을144fps headless와 창 모드로 재실행했다.
- 최초 리뷰 요청은 에이전트 사용량 제한으로 실행되지 않았고, 사용자가 한도 초기화를 알린 뒤 재요청하여 검토했다. 이 실패는 게임 검사 실패와 구분한다.

## 기록 검토와 남은 범위

A-19의 기존 페인트 표현을 바꾼 후속이므로 현재 결정/바뀐 결정, 전체 색인, 효과/캐릭터 규격, 체크리스트·기능 색인을 갱신했다. 요청된 외형 개선이며 새 전투 규칙/확정 제품 결함을 발급할 근거가 없어 새 결정·이슈 ID를 만들지 않았다. 검사 도구의 보완 사항은 위에 기록했다.

세부 배색/종류 연결/점성의 최종 미술 수락은 남는다. 단일 평면이라 경사/단차 전체에 밀착 투영되지 않으며 작은 순간 방울은 충돌 시뮬레이션이 없다. 자국 위치/윤곽은 시각 전용이고 피어별로 같음을 보장하지 않는다. 실제2PC·저사양/160개 동시 표시 장시간 GPU 성능·전체 내보내기는 미검증. 기존 시체/오디오 이슈의 해결을 주장하지 않는다.
