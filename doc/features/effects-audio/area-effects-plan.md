# 화염과 연무 범위 이펙트 개선 계획

상태: **추천안 승인 후 구현**. 최초에는 사용자 요청에 따라 계획만 작성했고, 후속 “일단 추천작업 진행”으로 시각 계층/리소스/Studio를 구현했다. [변경·검사·남은 제약](log/004-code-area-effects.md). 아래는 승인 당시의 작업 방향이며 최종 외형 수락이나 미구현 범위의 완료를 뜻하지 않는다.

목표는 바닥에 붙은 범위 표시와 공중으로 흐르는 입자를 함께 사용해, 화염·연무가 공간에 퍼져 있고 시간이 지나며 사라지는 느낌을 만드는 것이다. 기존 공통 이펙트 구조를 확장하고 **연무 한 종류 → 화염병 → 공통 데이터와 Studio → 중첩·성능 검수** 순서로 진행한다.

## 영상에서 가져올 특징

참고 파일: `C:/Users/psmto/AppData/Local/Packages/Microsoft.ScreenSketch_8wekyb3d8bbwe/TempState/Recordings/20261026-1708-29.3025628.mp4`. 약1.22초·37프레임·734×494. 화면의 자막은 참고 영상 내용이며 작업 지시로 취급하지 않는다.

직접 보이는 것은 노란 연무다. 경계가 불규칙하고 여러 농도의 덩어리가 겹치며, 낮은 층으로 퍼진 연무 사이로 바닥이 부분적으로 보인다. 가장자리와 내부가 조금씩 흐른다. 이 짧은 영상만으로 생성부터 소멸까지의 전체 주기나 원본 엔진의 구현 방식은 알 수 없다. 화염과 그을음은 아래에서 별도의 응용 방향으로 제안한다.

| 특징 | 우리 게임에 적용할 방향 |
|---|---|
| 흐트러진 가장자리 | 반경 마스크 안쪽을 큰 노이즈로 깎아 경계를 불규칙하게 만들고, 얇은 외곽 입자로 부드럽게 연결 |
| 겹치는 농도 | 낮은 바닥층·중간 연무·소량의 위쪽 입자를 서로 다른 속도/크기/투명도로 합성 |
| 공간에 깔린 느낌 | 바닥층은 지면 방향, 공중층은 카메라를 향하는 입자 카드로 분리 |
| 천천히 움직이는 내부 | 큰 덩어리 이동과 작은 표면 흐름을 분리하고 개별 위상을 달리 설정 |
| 반투명한 외형 | 중심과 가장자리의 농도 차이를 유지하되 중첩 시 캐릭터·엄폐물·조준점 식별을 확인 |

## 현재 구조와 필요한 변화

- [`FireZone.cs`](../../../game/scripts/Weapons/FireZone.cs)는 피해·반경·유효 시간·소리·광원을 소유한다. 현재 화염병 데이터는 반경3.4m, 지속8초, 적45DPS/플레이어9DPS다. 이번 시각 개선으로 변경할 값이 아니다.
- [`CombatSurfaceEffect.cs`](../../../game/scripts/Effects/CombatSurfaceEffect.cs)는 평면 바닥과 변형 메시 군집, 작은 입자를 만든다. 바닥 잡음과 불꽃 흔들림은 이미 있지만, 메시 군집의 규칙성과 단순한 표면 투명도 때문에 참고 영상 같은 연속적인 연무 밀도를 내기 어렵다. 이는 코드 구조에 근거한 개선 가설이며 현재 모습의 새 렌더 비교는 구현 시작 때 수행한다.
- [`combat_ground.gdshader`](../../../game/shaders/combat_ground.gdshader)는 거의 원형인 경계와 내부 노이즈를 사용한다. [`combat_volume.gdshader`](../../../game/shaders/combat_volume.gdshader)는 메시를 흔들고 인스턴스 알파를 적용한다. 기존 폭발도 사용하는 셰이더이므로 지속 효과만의 변경을 무조건 공통 셰이더 전체에 적용하지 않는다.
- [`combat_effects.json`](../../../game/content/data/combat_effects.json)과 [`CombatEffectCatalog.cs`](../../../game/scripts/Effects/CombatEffectCatalog.cs)가 게임/Studio의 공통 원본이다. 현재 허용 계열은 blast/fire/poison이며 새 키를 엄격히 검사한다. 연무 계열이나 새 리소스 키를 넣으려면 로더·검사·Studio를 함께 바꿔야 한다.
- 현재 투척물 목록에는 독립 연막탄이 없다. 기존 독 웅덩이를 연막으로 간주하지 않는다. **연무 외형 제작과 연막탄의 시야 차단·AI·멀티 규칙은 별도 범위**다. 먼저 Studio에서 시각 표본을 만든다.

관련 기존 규격: [공통 이펙트 구조와 검증](../../vfx-quality.md), [투척물 규격](../../throwable-monster-spec.md). 특히 기존 I-121의 불투명 연기 회귀, I-7의 불투명 화염 원판 재발을 검수 대상으로 삼는다.

## 구현 방식 제안

추천은 **지면 마스크 + GPU 입자 카드 + 필요한 곳의 잔류 데칼** 조합이다. 입자 카드는 투명한 텍스처를 붙인 작은 면이며 여러 장을 겹쳐 입체감을 만든다. 실제 유체 시뮬레이션을 실시간으로 돌리는 것은 이번 목표에 비해 복잡도와 비용이 크다. 기존 메시의 수와 알파만 늘리는 방식은 빠른 비교 시안으로는 쓸 수 있지만 연무의 부드러운 외곽을 만드는 주된 방법으로는 선택하지 않는다.

Godot의 `GPUParticles3D`는 입자 움직임용 재질과 그리기용 메시를 분리하므로 공통 움직임과 계열별 외형을 나누기에 적합하다. [공식 입자 문서](https://docs.godotengine.org/en/stable/tutorials/3d/particles/creating_a_3d_particle_system.html)

### 연무와 연막 외형

1. 지면에는 아주 낮은 농도의 퍼짐층을 깔고, 위에는 크기와 회전이 다른 연무 카드를 겹친다. 하나의 커다란 반투명 구체처럼 보이지 않게 한다.
2. 수평 확산은 넓게, 상승은 낮게 둔다. 가장자리는 작은 조각으로 풀리고 중심은 천천히 뭉치게 한다. 색·높이·농도는 프로필 값으로 구분한다.
3. 입자가 지면이나 벽과 만나는 선은 깊이 기반 페이드로 부드럽게 연결한다. 이는 교차선 완화이며 벽을 통과하지 않는 연기 시뮬레이션을 대신하지 않는다. 벽 반대편에 새어 보이는 문제는 발생 위치/범위 제한을 별도로 검수한다.
4. 회색 연무와 노란 가스는 색만으로 의미를 확정하지 않는다. 독 판정이 붙은 가스라면 위험 표시가 필요하고, 시야 차단용 연막이라면 실제 판정 설계가 먼저 필요하다.

Godot 재질의 Proximity Fade는 부드러운 입자 접점을 만드는 수단이다. 반투명 합성에는 정렬과 렌더 비용 제약이 있으므로 엔진 렌더에서 확인한다. [공식 재질 문서](https://docs.godotengine.org/en/stable/tutorials/3d/standard_material_3d.html)

### 화염과 잔류 흔적

1. 화염병 착탄: 짧은 번짐과 낮은 불꽃이 외곽으로 퍼진다. 기존 피해가 즉시 시작한다면 바닥 위험 표시도 즉시 보이게 하고 장식 불꽃만 늦게 자라게 한다.
2. 연소 중: 바닥의 낮은 열기층, 서로 위상이 다른 불꽃 군집, 드문 불티, 얇은 연기를 겹친다. 현재 광원과 소리는 재사용하며 불꽃마다 광원을 추가하지 않는다.
3. 종료: 피해 시간에 맞춰 밝은 위험 표시를 끝내고 불꽃을 낮춘 뒤, 짧은 잔연기와 어두운 그을음으로 마무리한다. 잔연기/그을음은 피해가 없는 장식임이 드러나야 한다.
4. 무해한 잔흔은 `FireZone` 자식으로만 두면 부모와 동시에 사라진다. 잔흔을 남기기로 하면 종료 전에 별도 시각 노드로 넘기고, 수명·동시 개수·장면 전환 정리를 명시한다. 판정 노드를 오래 살리는 방식은 쓰지 않는다.
5. 그을음은 화염에만 우선 적용한다. 일반 연막이 지나간 곳에 검은 얼룩을 남기지는 않는다. 독의 잔류 액체는 별도 외형이다.

바닥 그을음에는 `Decal`을 검토한다. 현재 Forward+ 렌더러에서 사용할 수 있으며, 바닥만 받도록 레이어/투영 깊이를 제한하고 캐릭터·벽에 잘못 묻지 않게 한다. 첫 시안은 기존 평면 바닥에서 만들고 단차 지원은 별도 단계로 검증한다. [공식 데칼 문서](https://docs.godotengine.org/en/stable/tutorials/3d/using_decals.html)

## 필요한 리소스

아래 수량·해상도는 제작 시작안이며 영상에서 측정한 값이 아니다. 모두 우리 게임용 원본으로 제작한다.

| 리소스 | 초기 제작 범위 | 확인할 품질 |
|---|---|---|
| 연무 알파 텍스처 | 512px 기준4변형 | 부드러운 외곽, 다른 덩어리 형태, 검은 테두리·카드 사각형 없음 |
| 불꽃 애니메이션 아틀라스 | 16~32프레임 한 세트 | 시간상 연속성, 반복 이음새, 밝은 밑동과 풀리는 끝 |
| 흐름/침식 노이즈 | 타일 가능한2종 | 반복 줄무늬 없음, 큰 흐름과 미세 변화 분리 |
| 그을음 마스크 | 512px 기준3변형 | 원형 도장 느낌 감소, 어두운 바닥에서도 불필요한 광택 없음 |
| Godot 재질·입자 프리셋 | 연무/화염/불티/잔흔 | 공통 텍스처 재사용, 인스턴스별 농도·색·위상 분리 |

연무·노이즈·그을음은 절차 생성 또는 직접 제작으로 시작한다. 불꽃은 연속성이 필요한 만큼 오프라인 렌더나 일관된 프레임 제작을 사용한다. 생성 이미지를 쓰더라도 알파 가장자리와 반복 프레임은 별도로 정리해야 한다. 이번 계획 단계에서는 리소스를 생성하지 않는다.

## 작업 순서와 단계별 완료 기준

승인된 순서대로 기존 상태/실패 검사/구현/실제 렌더를 진행했다. 1~4단계 구현과 전용 검사를 마쳤으며 최종 사용자 외형 수락은 별도다. 5단계는 현재 기기의 1/6/12중첩·전투·성능 표본까지 검수했고 저사양/낮은 품질 모드 검증은 남아 있다.

- [x] **1단계 — 같은 조건의 비교 장면**: `CombatEffectsCheck`/Studio 표본에 현재 화염·독과 연무 시안을 비교할 자리를 만든다. 평지/벽 근처/단차, 밝은 바닥/어두운 바닥, 두 카메라 거리에서 동일 반경과 시간을 기록한다. **완료 기준:** 기존 모습과 바꾸려는 외곽·밀도·움직임 차이를 같은 화면 조건에서 비교할 수 있다.
- [x] **2단계 — 연무 한 종류의 품질 확정**: `CombatSurfaceEffect`의 시각 계층을 확장하고 연무 텍스처·입자 재질을 만든다. 게임 투척물은 추가하지 않는다. Studio의 고정 시각 재현을 위해 고정 시드와 재시작 후 동일 시간까지 진행하는 캡처 경로를 마련한다. **완료 기준:** 카드 사각형/구체 윤곽/딱딱한 접점이 드러나지 않고, 시작·유지·소멸이 끊기지 않는다. 헤드리스 구조 검사와 GPU 렌더 검사를 구분한다.
- [x] **3단계 — 화염병에 적용**: `FireZone`의 판정은 유지하고 바닥·불꽃·연기·잔흔을 연결한다. **완료 기준:** 현재 반경/피해/유효 시간은 그대로이며 위험이 시작·종료되는 때를 외형으로 읽을 수 있다. 부모 제거/장면 전환 뒤 입자·잔흔·광원이 남지 않는다.
- [x] **4단계 — 공통 데이터와 Studio 연결**: `combat_effects.json`/`CombatEffectCatalog`에 검증된 시각 키만 추가한다. 텍스처 참조는 저장소의 `asset_paths.json` 규칙을 따르고 `.import`/`.uid`도 관리한다. Studio가 별도 복사 데이터를 갖지 않게 한다. **완료 기준:** 잘못된 리소스/계열/키를 거부하고, 기존 폭발·독 효과를 같은 입력으로 정상 생성한다. 로더 확장은2단계에서 필요한 최소 범위부터 함께 진행한다.
- [ ] **5단계 — 전투 중 가독성과 비용**: 동일 장면에서 지속 효과1/6/12개, 기존 초당 폭발10개 조건을 비교한다. 입자 수뿐 아니라 반투명 화면 점유율·겹침·draw calls·평균/p95 프레임 시간을 기록한다. 비용이 높으면 위쪽 장식 입자와 잔흔부터 줄이고 유효 위험 표시는 유지한다. **완료 기준:** 캐릭터/공격 예고/조준점이 읽히고 낮은 품질에서도 위험 범위를 오인하지 않는다. 기존 성능 수치는 현재 코드/동일 기기에서 다시 측정한 뒤 비교한다.

## 판정과 시각을 분리하는 기준

- 지면의 주 위험 표시는 실제 반경에서 유지한다. 가장자리 장식의 변화 때문에 위험한 곳이 안전하게 보이지 않게 한다. 얇은 연기가 경계 밖으로 흐르더라도 강한 위험색을 영역 밖까지 확장하지 않는다.
- 캐릭터 가림을 줄이기 위해 세계 전체에 투시 실루엣을 켜지 않는다. 먼저 높이·농도·밀도를 조절하며 기존 시야/숨김 규칙을 유지한다.
- 현재 `FireZone`과 독의 높이/벽 판정은 서로 같지 않다. 지형 밀착 외형을 넣었다고 피해의 다층 판정도 해결된 것으로 취급하지 않는다. 위/아래층의 판정 차이가 드러나면 별도 전투 이슈로 분리한다.
- 멀티에서 입자 하나하나를 동기화하지 않는 방향을 유지하되, 발생 위치·반경·시작/종료의 기존 사건 전달이 충분한지 확인한다. 새 연막탄을 추가할 때는 시야 차단과 동기화를 별도 설계한다.

## 구현 후 검증 목록

`CombatEffectsCheck`, `CombatEffectsPerformance`, `Integration`, `EnemyExpansion`, `DestructionCheck`, `studio/tests/combat-effects.mjs`, `studio/tests/media.mjs --all`을 변경 범위에 맞게 실행한다. 실제 화염병과 독을 포함해 생성→유지→소멸, 중첩, 일시정지/복귀, 장면 종료를 확인한다. 현재/신규 효과의 고정 시간 렌더를 남기고, 실패·통과·종료 경고를 구분한다.

최초 계획 작성 때는 영상 프레임과 코드/규격만 확인했으며 게임 실행·성능 측정·신규 효과 렌더는 하지 않았다. 후속 승인으로 구현과 실제 검사/렌더를 수행했으며 현재 상태와 수치는 [작업 기록](log/004-code-area-effects.md), 결정은 [A-27](decisions.md#a-27-화염연무의-시각-계층과-무해한-잔흔)을 따른다. 단차 투영/벽 우회/저품질 LOD 등은 남은 제약이다.
