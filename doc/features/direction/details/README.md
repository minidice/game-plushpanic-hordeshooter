# 세부 방향성

[방향 지침](../game-direction.md)의 **핵심 목표가 아닌** 방향을 주제별로 모은 곳이다. 항목마다 **왜 이 방향인지**, 다른 선택지와 장단점, 참고작의 특성, 바뀐 이력을 함께 남겨 나중에 "왜 이렇게 했지?"를 되짚을 수 있게 한다.

## 문서들의 역할

| 문서 | 담는 것 | 바뀌는가 |
|---|---|---|
| [방향 지침](../game-direction.md) | 핵심 목표만(이 게임이 무엇을 향하는가) | 사용자 결정으로만. 완료돼도 지우지 않음 |
| **세부 방향성(이 폴더)** | 핵심이 아닌 방향 · 이유 · 선택지 비교 · 참고작 특성 · 히스토리 | 항목 추가 · 상태 변경. 내용은 지우지 않고 히스토리에 쌓음 |
| [Blueprint](../campaign-onslaught-blueprint.md) | 진행도: 현재 구현 대비 · 측정 · 우선순위 | 진행에 따라 |
| [결정 색인](../../../decisions.md) · [방향 결정 본문](../decisions.md) | 확정된 것만 ID · 한 줄 · 상태 | 결정이 날 때 |

세부 방향성 항목이 **수락**되어 규칙이 되면 D-ID를 받고, 결정 색인 한 줄이 이 항목을 가리킨다. 같은 내용을 두 곳에 길게 쓰지 않는다(근거는 여기, 결정 사실은 색인).

## 항목 양식

모든 항목은 아래 칸을 쓴다. 모르는 칸은 "미정"으로 둔다(비워 두지 않음).

```
## 항목 이름
- 방향: 무엇을 하려는가
- 이유: 왜 이 방향인가 (항상 작성)
- 출처: 사용자 목표(원문 인용) / AI 제안(어느 문서 · 수락 여부)
- 선택지 비교:
  | 안 | 내용 | 장점 | 단점 |
- 참고작 특성: 그 게임은 어떻게 했고 무엇이 좋고 아쉬운가
- 상태: 목표(사용자) · 제안 · 수락 · 보류 · 폐기 (+ 결정 ID)
- 히스토리: 날짜 · 무엇이 · 왜 (지우지 않고 아래로 쌓음)
```

## 규칙

- **이유는 항상 쓴다.** 이유 없는 방향은 항목으로 만들지 않는다.
- **출처를 섞지 않는다.** 사용자 목표는 원문을 인용하고, AI 제안은 "제안"으로 표시해 사용자가 수락하기 전까지 목표처럼 쓰지 않는다.
- **지우지 않는다.** 방향이 바뀌거나 폐기되면 상태를 바꾸고 히스토리에 이전 · 이후 · 이유를 남긴다.
- **장단점 · 참고작 특성은 분석이다.** 처음 작성은 AI 분석(2026-10-27)이며 사용자 확인 전이다. 참고작 특성은 널리 알려진 설계 특징만 적고, 세부 수치는 출처 없이 쓰지 않는다.
- 진행도(구현했나, 측정값, 할 일)는 여기에 쓰지 않고 [Blueprint](../campaign-onslaught-blueprint.md)에 쓴다.
