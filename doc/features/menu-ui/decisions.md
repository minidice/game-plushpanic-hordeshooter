# 메뉴 · UI — 결정 본문

## M-33 장전/충전 포인터와 반투명 진행 UI

- 결정: 평상시 조준 눈금은 장전/발사 준비/재충전 진입 시 제자리에서 사라지고 진행 링으로 바뀐다. 링 주변 고정 네 점은 제거한다. 하단에 동일 진행률의 퍼센트와 둥근 게이지를 보여 준다. 어두운 반투명 트랙, 선명한 청백색 중심과 부드러운 청색 번짐을 사용한다. 장전/재충전 중 탄약 영역 문구는 작은 중립색으로 표시하고 평상시 부족탄 경고는 유지한다.
- 이유: 사용자 제공 `장전.mp4` 5–7초의 전환과 깨끗한 반투명 외형을 참고하여 지금 총을 쓸 수 없는 이유와 남은 진행을 알기 쉽게 한다.
- 상태 · 날짜: 사용자 요청 방향으로 구현, 외형 최종 수락 전 · 2026-10-27. 0.16초 진입/0.20초 복귀, 반경19px, 248×22px 막대와 알파값은 제작자 선택이며 사용자 확정 수치가 아니다.
- 구조: Godot `Paint`, 안티앨리어싱 도형, 공유 `StyleBoxFlat` 리소스. 별도 이미지/셰이더 없이 해상도에 맞춰 그린다. 무기 타이머를 읽고 UI는 전환 가중치만 보간한다. `WeaponState.ReloadCompleted`로 실제 완료와 취소를 구분한다.
- 근거 코드 · 규격: [HudWeaponAction.cs](../../../game/scripts/UI/HudWeaponAction.cs), [Hud.cs](../../../game/scripts/UI/Hud.cs), [WeaponState.cs](../../../game/scripts/Weapons/WeaponState.cs), [상세 규격](../../weapon-spec.md#64-장전충전-진행-ui-m-33), [관찰·설계](reload-ui-design.md), [검사 기록](log/001-code-reload-progress-ui.md).
- 빛 표현 보강: 점프 게이지에도 같은 발광 호를 사용하고 비선택 HUD 테두리를 낮춘다. [HudDock.cs](../../../game/scripts/UI/HudDock.cs), [이번 범위·계획](hud-light-polish-plan.md), [검사·렌더 기록](log/002-code-hud-light-polish.md).
- 기존 결정과 관계: C-30의 평상시 조준 퍼짐/거리 색, C-32의 집중 치명타 규칙은 유지한다. 기존 장전 중 이동 막대와 발사 준비 사각 막대만 대체한다. 액티브 리로드나 새 취소 조작은 추가하지 않는다.

### 바뀐 표시

아래는 최초 구현 당시 기록이다. 현재 네 점 제거 결정은 아래 「조준 표시의 의미 정리」를 따른다.

기존에는 장전 중 눈금이 회색으로 남고 커서 아래 검은 막대 위에서 선 하나가 이동했다. 이제 눈금을 네 점으로 전환하며, 원형/하단 게이지가 실제 진행률로 함께 찬다. 난전 특수무기 재충전에도 같은 UI가 적용되며 명중 표시는 계속 보인다.

### 바뀐 결정 — 2026-10-27 외형 보강

- 이전: 248×16px, 트랙 테두리와 반투명 하늘색 채움·상단 선, 작은 원판 위 얇은 호. 장전 중에도 탄수가 적으면 큰 빨간 문구가 나왔다.
- 이후: 248×22px, 테두리 없는 트랙과 알파0.98 밝은 채움·청색 그림자. 가운데가 뚫린 어두운 고리 위 흰 중심과 여러 겹의 청색 호. 장전/재충전 문구는18px 중립색, 정상 탄약 숫자는28px 및 기존 부족탄 경고를 유지한다.
- 이유: 사용자 첨부 UI의 깔끔한 느낌을 반영하라는 요청. 밝은 정보와 어두운 바탕의 역할을 분리하고 중복 경고의 강조를 낮춘 제작안이다. 사용자에게 색/치수/구현 방식이 최종 확정됐다고 해석하지 않는다. 타이머·전환 계약은 그대로다.

### 바뀐 결정 — 2026-10-27 조준 표시의 의미 정리

- 이전: 일반 조준 눈금을 대각으로 회전/축소해 장전 링 주위의 고정 네 점으로 유지했다. 참고 외형을 따랐으나 그 점은 퍼짐·탄수·진행률을 표시하지 않았다.
- 이후: 눈금/중앙점은0.16초에 제자리에서 사라지고 진행 링만 남는다(명중 피드백은 별도 유지). 완료/취소 시0.20초에 원래 조준으로 복귀한다. 충전/재충전에도 동일하다.
- 이유: 사용자 피드백 「의미가 없다면 없는 것만도 못하고 의미가 있다면 인지가 필요」. 링이 위치와 진행을 이미 표현하므로 네 점에 새 의미를 붙이지 않고 제거했다. 원작 게임의 네 점 의도는 확인되지 않았으며 우리 구현의 기능 부재를 근거로 했다.
- 상태: 사용자 요청 방향으로 구현, 외형 세부 수치 최종 수락 전. 일반 조준의 의미/강조 보강은 [C-30](../combat/decisions.md#c-30-조준-표시의-의미와-강조-보강)을 따른다. [계획](reticle-clarity-plan.md), [검사·렌더 기록](log/003-code-reticle-clarity.md).

새 결정은 여기 ID 아래에 쓰고, [전체 색인](../../decisions.md)에는 ID · 한 줄 요약 · 상태 · 날짜 · 링크만 한 줄로 적는다. 결정 ID는 지금처럼 영역 접두사(D · M · C · T · L · A · Q)를 쓴다.
