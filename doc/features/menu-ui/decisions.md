# 메뉴 · UI — 결정 본문

## M-33 장전/충전 포인터와 반투명 진행 UI

- 결정(2026-10-28 갱신): 평상시 조준점 오른쪽 아래에 탄창 잔량(Mag/MagSize) 원호와 언어 독립 발사 방식 도형을 둔다. 잔량은 원호 끝점에 붙여 그리고 시작점부터 소모한다. 기본 오른쪽 아래 배치에서는 위에서 아래로 줄어든다. 단발 한 획, n점사 n획, 자동 두 꺾쇠이며 탄수처럼 줄지 않는다. 장전/발사 준비/재충전 때 원호가 중앙 진행 링으로 전환하며 일반 조준과 방식 도형은 사라진다. 완료·취소하면 실제 남은 탄창 원호로 복귀한다. 하단 퍼센트·게이지, 장전 링 주변 고정 장식 네 점 제거는 유지한다. 반투명 어두운 트랙, 선명한 청백색 중심과 부드러운 청색 번짐을 공통으로 사용한다.
- 이유: 사용자 제공 `장전.mp4` 5–7초의 전환과 깨끗한 반투명 외형을 참고하여 지금 총을 쓸 수 없는 이유와 남은 진행을 알기 쉽게 한다.
- 상태 · 날짜: 사용자 요청 방향으로 구현, 외형 최종 수락 전 · 2026-10-27. 0.16초 진입/0.20초 복귀, 반경19px, 248×22px 막대와 알파값은 제작자 선택이며 사용자 확정 수치가 아니다.
- 구조: Godot `Paint`, 안티앨리어싱 도형, 공유 `StyleBoxFlat` 리소스. 별도 이미지/셰이더 없이 해상도에 맞춰 그린다. 무기 타이머를 읽고 UI는 전환 가중치만 보간한다. `WeaponState.ReloadCompleted`로 실제 완료와 취소를 구분한다.
- 근거 코드 · 규격: [HudWeaponAction.cs](../../../game/scripts/UI/HudWeaponAction.cs), [Hud.cs](../../../game/scripts/UI/Hud.cs), [WeaponState.cs](../../../game/scripts/Weapons/WeaponState.cs), [상세 규격](../../weapon-spec.md#64-장전충전-진행-ui-m-33), [관찰·설계](reload-ui-design.md), [검사 기록](log/001-code-reload-progress-ui.md).
- 빛 표현 보강: 점프 게이지에도 같은 발광 호를 사용하고 비선택 HUD 테두리를 낮춘다. [HudDock.cs](../../../game/scripts/UI/HudDock.cs), [이번 범위·계획](hud-light-polish-plan.md), [검사·렌더 기록](log/002-code-hud-light-polish.md).
- 기존 결정과 관계: C-30의 평상시 조준 퍼짐/거리 색, C-32의 집중 치명타 규칙은 유지한다. 기존 장전 중 이동 막대와 발사 준비 사각 막대만 대체한다. 액티브 리로드나 새 취소 조작은 추가하지 않는다.

### 바뀐 표시

아래는 최초 구현 당시 기록이다. 현재 네 점 제거 결정은 아래 「조준 표시의 의미 정리」를 따른다.

기존에는 장전 중 눈금이 회색으로 남고 커서 아래 검은 막대 위에서 선 하나가 이동했다. 이제 눈금을 네 점으로 전환하며, 원형/하단 게이지가 실제 진행률로 함께 찬다. 난전 특수무기 재충전에도 같은 UI가 적용되며 명중 표시는 계속 보인다.

### 바뀐 결정 — 2026-10-27 외형 보강

- 이전: 248×16px, 트랙 테두리와 반투명 하늘색 채움·상단 선, 작은 원판 위 얇은 호. 장전 중에도 탄수가 적으면 큰 빨간 문구가 나왔다.
- 이후: 248×22px, 테두리 없는 트랙과 알파0.98 밝은 채움·청색 그림자. 가운데가 뚫린 어두운 고리 위 흰 중심과 여러 겹의 청색 호. 장전/재충전 문구는18px 중립색, 정상 탄약 숫자는28px 및 기존 부족탄 경고를 유지한다.
- 이유: 사용자 첨부 UI의 깔끔한 느낌을 반영하라는 요청. 밝은 정보와 어두운 바탕의 역할을 분리하고 중복 경고의 강조를 낮춘 제작안이다. 사용자에게 색/치수/구현 방식이 최종 확정됐다고 해석하지 않는다. 타이머·전환 계약은 그대로다.

### 바뀐 결정 — 2026-10-27 조준 표시의 의미 정리

- 이전: 일반 조준 눈금을 대각으로 회전/축소해 장전 링 주위의 고정 네 점으로 유지했다. 참고 외형을 따랐으나 그 점은 퍼짐·탄수·진행률을 표시하지 않았다.
- 이후: 눈금/중앙점은0.16초에 제자리에서 사라지고 진행 링만 남는다(명중 피드백은 별도 유지). 완료/취소 시0.20초에 원래 조준으로 복귀한다. 충전/재충전에도 동일하다.
- 이유: 사용자 피드백 「의미가 없다면 없는 것만도 못하고 의미가 있다면 인지가 필요」. 링이 위치와 진행을 이미 표현하므로 네 점에 새 의미를 붙이지 않고 제거했다. 원작 게임의 네 점 의도는 확인되지 않았으며 우리 구현의 기능 부재를 근거로 했다.
- 상태: 사용자 요청 방향으로 구현, 외형 세부 수치 최종 수락 전. 일반 조준의 의미/강조 보강은 [C-30](../combat/decisions.md#c-30-조준-표시의-의미와-강조-보강)을 따른다. [계획](reticle-clarity-plan.md), [검사·렌더 기록](log/003-code-reticle-clarity.md).

### 바뀐 결정 — 2026-10-28 탄창 잔량과 발사 방식

- 이전: 일반 조준에서 장전 링으로 페이드, 평상시 탄창 원호/발사 방식 없음. 커서 아래 잔탄 부족/빈 탄창 문구가 있었다.
- 이후: 오른쪽 아래 짧은 원호는 실제 탄창 비율이며 예비탄 무한과 무관하다. 한 획/실제 점사 수의 획/두 꺾쇠는 폰트를 쓰지 않는 도형이다. 원호 반경·시작각·길이가 같은 중심의19px 진행 링으로0.16초에 변하고0.20초에 복귀한다. 진행 수치는 기존 타이머를 읽어 장전 시작은0%, 취소는 성공 표시 없이 실제 잔탄으로 돌아간다. 한 발씩 장전은 삽입 주기마다 진행한다. 교체 시 이전 무기 진행은 즉시 초기화한다.
- 잔량 트랙은 채움이0이어도 남으며 글리프는 탄약 소모로 바뀌지 않는다. 커서의 잔탄 경고 문구는 제거해 심볼 공간을 확보했다. 하단 탄수·부족탄 경고는 유지한다. 일반 총기·로켓·박격포·레일건에 적용하고 근접·꽥·고무오리에는 총기 잔량/모드 표시를 붙이지 않는다. 투척 조준/공격 불가/메뉴 우선순위는 유지한다.
- 이유: 사용자 정정 “디비전 주변부 게이지가 총알잔량%”, 제안 “자연스럽게 탄창…장전커서로 변경되고 다시 돌아오고”, 이후 추천 방향 진행 승인. 디비전의 해당 게이지 의미는 사용자 설명을 근거로 기록한다.
- 상태: 방향 확정·구현, 최종 외형 수락 전. 평상시 최소 반경66px·주 눈금 반경+52px, 원호 약63도, 글리프 위치/굵기/알파는 제작값이다. 오른쪽·아래 가장자리에서는 보조 표시만 화면 안쪽 사분면으로 옮기고 조준 중심은 유지한다. 색은 장전 청백색/집중 황금색/잔량 흰색·청회색으로 나눈다.
- 근거: [설계·계획](weapon-reticle-plan.md), [검사·렌더·제약](log/009-code-weapon-reticles.md), `HudReticle.cs`, `HudWeaponAction.cs`. 새 탄약 규칙·수동 발사 방식 전환·액티브 리로드는 추가하지 않는다.


### 바뀐 결정 — 2026-10-28 잔탄 감소 방향

- 이전: 원호 시작점 고정, 끝점이 되감겨 기본 오른쪽 아래 배치에서 아래→위로 줄었다.
- 이후: 끝점 고정, 시작점부터 지워져 위→아래로 줄어든다. 가장자리 보정에서도 같은 각도 구간의 반대쪽부터 소모한다. 장전/충전 진행 방향과 전환 타이머는 유지한다.
- 이유·상태: 사용자 피드백 “총알 감소방향은 반대로…아래에서 위로 올라가는 느낌”에 따른 방향 수정·구현(2026-10-28).
- 근거: `HudReticle.cs`의 `DrawMagazineAction`, [검사·렌더 기록](log/011-code-ammo-drain-direction.md), [무기 규격](../../weapon-spec.md#64-장전충전-진행-ui-m-33).

## M-36 공격할 수 없을 때 조준점이 바뀐다

## M-37 개인 그래픽 품질과 명시적 환경 분류

- 결정: ESC와 메인 메뉴 설정에서 별도 그래픽 화면을 연다. 그림자/표면 품질은 높음·낮음 두 선택지를 항상 표시하고 선택된 쪽에 체크·밝은 글자·테두리를 사용한다. 즉시 반영·개인 설정 저장, 기존 소환수 품질도 같은 화면에 모은다.
- 이유: 사용자(2026-10-28)가 저사양용 단순 그림자와 현재 설정을 알아보기 쉬운 UI를 요청했다. 현재 환경은 이미지 텍스처보다 절차적 재질이 많아 이름은 표면 품질로 정한다. 이미지 해상도/VRAM 절감 옵션으로 오인시키지 않는다.
- 구현: 높음은 기존 그림자·SSAO·세부 재질 유지. 낮은 그림자는 실제 그림자 맵과 SSAO를 끄고 캐릭터/가까운 자연 소품의 단순 접지 음영을 묶어서 그린다. 낮은 표면은 경로와 큰 색 분포를 유지하며 미세 무늬·풀 바람 계산을 생략한다. 낮음의 캐릭터192/전체256 음영 한도, 거리/샘플 주기는 제작 수치이며 사용자 확정 수치가 아니다.
- 환경 방향: **랜덤 시간대는 폐기**한다. 시간 흐름/무작위 선택/실제 날씨 효과/맵 조명 변경은 이번 작업에 넣지 않는다. 실내 채광, 실외 시간대, 날씨, 잔류 바닥 상태를 분리한 [환경 분류](../art-environment/environment-categories.md)만 준비한다. 이후 맵에서 명시적으로 선택할 수 있는 데이터이며 현재 맵에 적용된 프리셋이 아니다.
- 상태 · 날짜: 사용자 요청 방향 구현, 시각적 최종 수락 전 · 2026-10-28. 실제 UI/렌더/검사는 [기록006](log/006-code-graphics-options.md), 환경 데이터 검사는 [환경 기록003](../art-environment/log/003-data-environment-categories.md).
- 근거: `game/scripts/Core/GameSettings.cs`, `UI/GraphicsOptions.cs`, `World/GraphicsQualityController.cs`, `game/content/data/environment_categories.json`. 네트워크 게임 시간이나 게임 규칙을 변경하지 않는다.

## M-38 공통 UI 스타일과 월드 상호작용

- 결정: 최신 무기 조준 UI의 밝은 중심·청회색/청색 빛·어두운 반투명 바탕을 기준으로 메뉴/HUD/설정/장비/진행 표시를 통일한다. 작은 발견 표식에서 실제 대상 하나의 행동/키 안내로 전환하고, 홀드/구조 진행·피격 중단·실제 완료를 표시한다. 위험·치료·집중·카드 등급 의미색은 유지한다.
- 이유: 사용자 2026-10-28 ‘추천안으로 진행하되…최근 적용된 총 조준점 변경 UI도 일관성 체크…전체적인 UI 퀄리티와 느낌이 일관성 유지’ 요청. 참고 영상의 표식→행동→진행 흐름과 기존 게임 UI를 연결한다.
- 상태·날짜: 사용자 승인 방향 구현, 외형 최종 수락 전 · 2026-10-28. 치수/시간/불투명도/거리 상한은 제작값이다.
- 기존 결정: M-33 최신 조준 형태·탄창 감소·전환 및 M-36 공격 불가 의미 유지. L-35 머리 위 바+하단 퍼센트 유지, 대상 옆 작은 진행 표시 연결. 게임 규칙 변경 없음.
