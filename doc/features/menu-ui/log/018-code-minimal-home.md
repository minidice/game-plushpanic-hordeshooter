# 018 · 담백한 메인 화면과 게임 시작 진입

관련: M-0, M-38. 작업일 2026-10-29.

## 요청·설계·범위

사용자는 덕코프의 시작/메뉴와 HUD/상호작용 양쪽의 담백함을 선호하며, 우선 메인 화면 추천안 적용을 요청했다. 승인된 추천안은 짧은 텍스트 목록과 캐릭터/배경 중심 화면이다. 기존 패널의 색만 바꾸는 안은 정보 밀도/경쟁을 해결하지 못하므로 적용하지 않았다. 상세 메뉴와 HUD까지 동시에 개편하는 안은 후속 범위로 남긴다.

구현 순서: 홈의 정보/동작 분리 → 같은 캐릭터 미리보기를 배경으로 재배치 → 진입·뒤로·언어 전환 검사 → 두 해상도 실제 렌더. 치수·배경 구조·카메라는 제작자 선택이며 사용자 확정 미술 수치가 아니다.

## 변경

- 홈 네 항목: 게임 시작 / 캐릭터 / 설정 / 종료. 게임 시작에서 싱글/멀티를 고른다. 단순 버튼 형태와 밝은 글자·왼쪽 선으로 포커스를 표시한다.
- 홈의 큰 패널, 종 설명, 능력치, 전체 조작표, 장르 부제를 숨겼다. 제목은 기존 게임 가칭을 사용한다. 새 로고/게임 이름을 확정하지 않는다.
- 메뉴 전용 세이프하우스 코너를 기존 `Mat` 도구로 구성했다. 실제 플레이맵/새 상호작용 구역은 아니다. 캐릭터/장비/외형 저장은 기존 자산과 인스턴스를 사용한다.
- 홈/게임 시작 선택에서 미리보기는 고정된 대기 자세. 상세 화면으로 전환하면 기존 미리보기 위치/카메라로 복귀한다. 커스터마이징의 달리기·사격 미리보기는 해당 페이지에서만 적용한다.
- 키보드 Enter, ESC, 버튼 뒤로, 멀티 선택 복귀 포커스, 언어 변경 후 재구성을 기존 `MenuCheck`에서 검증한다. 새 기능 전체용 검사 체계를 만들지 않는다.

## 실행한 검사

Windows / Godot 4.7.2 .NET. 최종 `dotnet build game/HordeShooter.csproj --nologo -v q`: 오류0·경고0.

| 검사 | 결과 | 산출물 |
|---|---|---|
| Godot headless editor import | 종료0, 오류/경고 없음. 새 C# UID 생성 | `game/output/menu-home-import.log` |
| MenuCheck 창 모드1280×720 | 54 통과, 종료0, 오류/종료 경고 없음 | `game/output/menu-home-minimal-1280.log` |
| MenuCheck 창 모드1600×900 | 54 통과, 종료0, 오류/종료 경고 없음 | `game/output/menu-home-minimal-1600.log` |

초기1600 실행은 뒤로 흐름 보완 전53검사 통과였으며, 위 최종54 결과와 구분한다. 테스트는 별도 설정/외형 파일을 사용한다. 실제 Enter 이벤트로 홈→선택→싱글 준비를 확인하고, 방 생성/이탈·설정 저장/언어 변경도 기존 검사 경로로 수행했다.

실행 명령: Godot 실행 파일에 `--path game --resolution 1280x720` 또는 `1600x900`, `res://tests/MenuCheck.tscn`을 전달한다. `Start-Game.ps1 -Test`를 이 전용 검사의 대체로 사용하지 않았다.

## 기록·제약

M-0/M-38의 바뀐 결정과 이전 표현을 보존하고 상위 색인/체크리스트/메뉴 규격을 갱신했다. 신규 제품 규칙이나 새 버그 ID를 만들지 않는다. 이슈 검토 결과 기능 오류 수리가 아닌 승인된 표현/진입 구조 변경이므로 기존 이슈의 상태 변경도 없다. 핵심 게임 방향·밸런스·멀티 통신 규칙은 변경하지 않았다.

상세 메뉴/로비/HUD의 같은 방향 후속 개편, 최종 로고·배경 미술 수락은 남아 있다. 패키지 내보내기/실제2PC/6인/초광폭 화면은 이번에 검증하지 않았다. 코드와 기록은 같은 후속 커밋의 범위로 관리하며 이번 요청에서는 main 병합·원격 푸시를 수행하지 않는다.
