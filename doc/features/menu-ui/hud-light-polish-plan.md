# HUD 빛 표현과 강조 정리

> 실행: `superpowers:executing-plans` 방식으로 현재 채팅에서 직접 진행한다.

## 설계

사용자 요청: 첨부한 링·게이지·키캡처럼 깔끔하고 고급스러운 느낌을 반영하며 별도 워크트리에서 시작한다. 이미지와 코드 중 제작 방식을 문의했다.

제작자 선택: 현재 원·막대 HUD는 코드 기반으로 유지한다. PNG 방식은 진행률 마스킹과 크기별 관리가 추가되고, 전용 셰이더는 이 범위에서 불필요하다. Godot 벡터 도형·StyleBoxFlat 그림자로 밝은 중심과 부드러운 청색/주황색 번짐을 만든다. 원본 이미지는 에셋으로 복사하지 않는다. 외형 최종 수락 전 제작안이다.

범위: 장전 링의 어두운 고리와 흰 중심, 하단 248×22px 게이지, 점프 게이지의 동일 빛 표현, 비선택 HUD 테두리 완화. 장전 중 탄약 경고는 작은 중립 문구로 낮추며 평상시 부족탄 경고는 유지한다. 새 아이콘·키캡 전체 재설계·메뉴 개편은 포함하지 않는다.

계약: M-33 진행률/완료/취소/교체/숨김, 무기 타이머, 도약 쿨다운은 유지. UI 치수·밝기는 제작값. 0%에서 채움 없음, 짧은 채움도 트랙 밖으로 튀지 않음. 전체 3D 화면의 bloom 설정은 바꾸지 않는다.

- [x] `ReloadUiCheck.cs`: 장전 중 경고 완화와 취소 후 부족탄 경고 복귀를 실제 HUD에서 검증한다. 변경 전 실패를 확인한다.
- [x] `HudWeaponAction.cs`: 공유 발광 호 그리기, 넓은 어두운 고리, 테두리 없는 게이지·빛 그림자. `HudDock.cs`: 점프 링 및 공통 판 테두리 완화. `HudEquipmentSlot.cs`: 선택 테두리만 절제. `Hud.cs`: 장전 중 글자 크기/색의 우선순위.

## 검토 초점

부분 진행의 둥근 모서리와 그림자가 실제 채움 길이를 왜곡하지 않는지, 밝은 바닥에서도 중심이 선명한지, 네 점과 링 빛이 붙지 않는지, 정상 부족탄 경고가 사라지지 않는지, 명중 표시가 계속 보이는지 확인한다. 시각 수치에는 구현을 그대로 복사하는 단위 검사를 만들지 않고 실제 렌더를 검토한다.
