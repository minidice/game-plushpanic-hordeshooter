# 멀티 2인 동기화 MVP 설계

> **상태**: MVP 구현 (2026-10-20). 9장 결정은 사용자가 추천대로 확정. `NetSyncCheck` 25개·`NetCodecCheck` 8개 통과, 창 2개 실행 확인. 실제 사람 조작감·인터넷 환경은 아직 확인 전(10장). [메뉴·멀티 계획](menu-multiplayer-plan.md) 5.4의 ② 단계, 결정 M-9·M-10·M-20.
> 범위는 **시나리오 Stage 1을 2명이 같이 클리어**하는 것까지다. 방 코드(③)·로비(④)·인원 보정(⑤)·중간 합류(⑥)·Steam(⑧)은 하지 않는다.

## 1. 목표와 완료 기준

| # | 완료 기준 | 확인 방법 |
|---|---|---|
| 1 | 같은 PC의 창 2개(127.0.0.1)로 방장 1 + 파티원 1이 Stage 1을 시작부터 세이프하우스 닫기까지 클리어 | 사람이 직접 플레이 + 자동 검사 `NetSyncCheck` |
| 2 | 두 화면에서 같은 적이 같은 자리에 있음: 보간 후 위치 차이 평균 0.3m 이하, 최대 1m 이하 | `NetSyncCheck`가 같은 시각의 양쪽 위치 비교 |
| 3 | 죽음·줍기·문·셔터·경보·쓰러짐/부활이 양쪽에서 같은 결과 | 사건 수·상태 비교 |
| 4 | 좀비 70마리일 때 대역폭과 끊김 측정 | 초당 바이트, 스냅샷 간격 기록 |
| 5 | 싱글 플레이와 기존 검사 전부 그대로 통과 | 기존 회귀 검사 |

## 2. 구조

- **방장 PC가 서버**다(M-9). 적 AI·디렉터·피해 판정·줍기·목표 진행은 모두 방장이 계산한다.
- 파티원은 **입력**을 보내고 **결과**를 받아 그린다. 지금 코드의 입력 함수(`SetControls`, `PressReload`, `PressHeal`, `PressThrow`, `PressCancel`, `PressCycle`, `PressRoll`, `PressSlot`, `HoldRevive`, 상호작용)가 그대로 네트워크 입력이 된다. AI 분대원도 같은 함수로 움직이므로, 방장 쪽 원격 플레이어는 "입력을 네트워크에서 받는 분대원"과 같은 방식으로 움직인다.
- **추천: 내 캐릭터 이동만은 내 PC가 먼저 계산한다(결정 필요, 9장 ①).** 입력만 보내고 방장 결과를 기다리면, 왕복 지연 + 보간 지연(약 100ms)만큼 내 캐릭터가 늦게 움직여 조작감이 나빠진다. 파티원이 자기 위치를 계산해 보내고, 방장은 크게 어긋날 때만 되돌린다(친구끼리 하는 코옵이므로 치트 방지는 하지 않는다). 피해·탄약·체력·줍기는 이 경우에도 방장이 정한다.
- 연결은 Godot `ENetMultiplayerPeer`(UDP). 출시 때는 연결 방식만 Steam으로 바꾼다(M-6).

## 4. 무엇을 보내나

### 4.1 입력 (파티원 → 방장, 매 물리 프레임, 신뢰성 없음·순서 보장)

| 항목 | 크기 |
|---|---|
| 입력 번호(순번) | 4B |
| 이동 방향 x,z (−1~1을 1B씩) | 2B |
| 조준점 x,z (cm 단위 int16) | 4B |
| 버튼 비트(사격·재장전·치료·투척·취소·구르기·상호작용·부활 누름) | 1B |
| 칸 선택·투척물 순환 | 1B |
| 내 위치·속도(추천안 ①일 때) | 8B |

약 30B × 60Hz ≈ 1.2KB/s(실측 1.1KB/s). 한 번 누르는 버튼(사격·재장전·치료·투척·취소·구르기·투척물 순환·칸 선택)은 **누른 횟수**를 계속 보내고, 방장은 아직 못 본 횟수만큼 한 번 실행한다. 입력 메시지가 사라져도 누름은 사라지지 않는다(I-73).

### 4.2 상태 스냅샷 (방장 → 파티원, 신뢰성 없음·순서 보장)

| 묶음 | 빈도 | 한 개 크기 | 70마리 기준 |
|---|---|---|---|
| 플레이어(각자): 위치·속도·조준·체력·상태 비트(구르기·장전·치료·쓰러짐·붙잡힘)·무기 ID·출혈 남은 시간 | 20Hz | 약 24B | 2명 ≈ 1KB/s |
| 적: ID 2B, x·z cm int16 4B, 높이 1B, 향하는 방향 1B, 상태 비트(깨어남·준비·기절·멈칫) 1B | 10Hz | 9B | 630B × 10 ≈ 6.3KB/s |
| 스테이지 시각·스냅샷 번호 | 각 스냅샷 | 8B | — |

파티원은 **약 100ms 뒤의 과거**를 그리면서 앞뒤 두 스냅샷 사이를 보간한다. 적 70마리 스냅샷은 743B. 더 많은 적(미리 깔린 무리 포함)으로 1,200B를 넘으면 지금은 ENet이 조각내 보낸다(조각 하나를 잃으면 그 스냅샷 전체를 잃음 — I-72). 합계 약 9KB/s 가정, 실측 8.3KB/s(1장 ④).

### 4.3 사건 (방장 → 파티원, 신뢰성 있음)

사건은 프레임마다 묶어 보내고 **사건마다 길이를 붙인다**. 파티원이 읽지 못하는 사건 하나는 건너뛰고 나머지를 적용한다(I-73).

| 사건 | 내용 |
|---|---|
| `World`(첫 번째는 환영) | 방장 캐릭터, 목표 단계, 문·셔터·세이프하우스 문·차 경보, 상호작용 대상 켜짐/보임, 남은 드럼통. 바뀔 때마다 다시 보냄. 테마·부활 옵션·외형은 아직 안 보냄(I-72) |
| `EnemySpawn` | 적 ID, 몬스터 ID, 위치, 반응 유형, 깨어남, 벽 위 등장이면 뛰는 방향 |
| `EnemyWindup` | 적 ID, 종류(근접·사격·토사·붙잡기·돌진), 대상 플레이어, 목표 지점 → 경고선·실루엣 공개(C-23) |
| `EnemyHit` | 적 ID, 맞은 지점·방향, 치명타 여부 U8(프로토콜 6). 피격 번쩍임·타격선·솜 파편, 현재 이벤트 묶음으로 전송 |
| `EnemyDeath` | 적 ID, 방향, 힘, 치명타 여부 → 각자 시체 물리 |
| `PlayerHit` | 플레이어, 피해, 방향 → 맞은 방향 호 |
| `Capture` / `Release` | 붙잡은 적, 붙잡힌 플레이어 |
| `Pickup` | 바닥 물건 ID, 가져간 플레이어, 결과(장착·업그레이드·보충·가득 참), 떨어진 무기 |
| `Interact` | 문·셔터 제어판·세이프하우스 스위치·탄약 더미 ID와 결과 |
| `Objective` | 목표 단계, 셔터 진행률 |
| `Throw` / `Explode` | 투척물 종류·시작 위치·속도 / 폭발 위치·반경·힘 |
| `Alarm` | 차 경보 시작·끝 |
| `Sound` | 위치 소리 중 꼭두각시가 스스로 내지 못하는 것(사격·신음·특수 몬스터 예고) |
| `StageEnd` | 클리어·전멸 |

### 4.4 ID 규칙

- **적**: 방장이 생성 순서대로 붙이는 정수(1부터). 파티원은 받은 ID로만 만든다.
- **바닥 물건·상호작용 대상·문**: 레벨을 같은 데이터·같은 순서로 만들므로 **생성 순번이 곧 ID**다(레이아웃은 seed 1, 보급·조우는 JSON). 교체로 떨어진 무기는 방장이 새 ID를 붙여 사건으로 알린다.
- **플레이어**: 피어 ID(방장 1, 파티원은 ENet이 준 번호).

## 6. 연결과 시작 (MVP)

- 메뉴의 "멀티"에 임시 버튼 두 개: **방 만들기**, **참가(주소 입력, 빈 칸에서 시작하고 마지막 주소를 기억, I-76)**. 방 코드는 ③ 단계에서.
- 2026-10-21부터 두 버튼은 **방(로비)** 을 연다(`Net/NetLobby`, M-21): 참가자·준비·방장 모드 선택 → 방장 [시작] → 방장 스테이지가 준비되면(`HostLive`) 파티원이 따라 들어감. 게임 중에 들어온 사람은 바로 합류.
- 명령줄로도 실행: `-- --host`(방을 열고 바로 시작), `-- --join=127.0.0.1`(메뉴가 그 방에 참가, 게임 중이면 바로 합류). 자동 검사가 이 길을 쓴다.
- 파티원이 들어오면 방장이 `StageStart`를 보내고, 두 PC가 같은 레벨을 만든 뒤 방장이 시작 신호를 보낸다.
- 데이터가 다르면 접속을 막는다: 파티원이 무기·투척물·몬스터 ID 지문(`NetIds.DataHash`)을 보내고 방장이 비교해 다르면 거절한다. 방장은 파티원 1명만 받는다(MVP).
- 방장이 나가면 방이 끝난다(M-3): 파티원은 안내 후 3초 뒤 메뉴로. 파티원이 나가면 그 캐릭터는 사라지고 전멸 판정을 다시 한다.
- 멀티에서 방장의 "다시 시작"은 **모두 함께 방으로**(연결 유지, 다시 준비), 파티원은 재시작할 수 없다(2026-10-21, M-21). [M]/[Esc]로 메뉴에 가면 연결을 닫고 싱글로 돌아간다(방장이면 방이 닫힘).

## 7. 검사 방법

| 검사 | 방식 | 확인 내용 |
|---|---|---|
| `NetCodecCheck` (헤드리스, 네트워크 없음) | 묶기 → 풀기 왕복 | 입력·플레이어·적 스냅샷·사건이 같은 값으로 돌아옴. 경계값(맵 끝 좌표, 적 0/70/200마리), 1,200B 나눔 |
| `NetSyncCheck` (헤드리스, 한 프로세스) | 방장과 파티원 스테이지를 **각각 자기 물리 세계를 가진 SubViewport**에 두고 127.0.0.1 ENet으로 연결. 대본대로 입력을 넣어 Stage 1 진행 | 1장의 완료 기준 1~4: 위치 차이, 죽음 수, 줍기·문·셔터·경보·쓰러짐/부활 결과, 초당 바이트, 클리어가 양쪽에서 같음 |
| 지연·손실 흉내 | `NetSyncCheck`의 전송 계층에 지연(100ms)·손실(5%) 넣기 옵션 | 보간이 끊기지 않고 사건이 빠지지 않음 |
| 창 2개 수동 확인 | 메뉴 → 멀티, 또는 `Start-Game.ps1 -NetHost` / `-NetJoin 127.0.0.1` | 조작감, 보간 떨림, 소리, 시야 단계 |
| 기존 회귀 | `Integration`, `SquadCheck`, `SpawnCheck`, `VisionTierCheck` 등 | 싱글이 그대로인지 |

자동 검사가 통과해도 실제 조작감·체감 지연은 사람이 확인한다. 친구 PC 간(인터넷) 확인은 ③ 단계에서 한다.

## 10. 구현 결과와 남은 한계 (2026-10-20)

**한 PC에서 빠르게**: `game/Start-Multi-Test.cmd` 더블클릭(= `Start-Game.ps1 -NetPair`) — 빌드 한 번, 방장 창이 뜨고 4초 뒤 참가 창이 자동으로 붙는다.

**다른 PC와(같은 공유기)**: 방장이 방을 만들면 화면 안내와 일시정지 화면에 `192.168.x.x` 같은 주소가 나온다. 다른 PC는 메뉴 → 멀티에서 그 주소로 참가. 처음 방을 만들 때 Windows 방화벽이 묻으면 **개인 네트워크 허용**. 다른 PC에도 같은 버전의 게임이 필요하다: 개발 PC에서 `game/Export-Game.cmd`를 실행하면 `build/HordeShooter-windows.zip`이 생긴다. 이 압축을 다른 PC에 풀고 `HordeShooter.exe`를 실행(Godot·.NET SDK 불필요, 폴더 안 파일은 함께 둘 것). 코드나 데이터가 바뀌면 두 PC 모두 다시 내보낸 같은 버전을 써야 한다(다르면 참가 거절). 인터넷 너머는 아래 방 목록.

**방 목록(2026-10-21, M-6)**: 방장이 방을 만들면 `https://lobby.minidice.net/hordeshooter/rooms`에 올라간다(`Net/RoomDirectory`, 15초마다 갱신, 인원·대기/게임 중 변화는 1초 안에 반영). 멀티 화면은 5초마다 목록을 받아 보여 주고, 누르면 방장에게 직접 접속한다: 같은 공인 주소(같은 공유기)면 서버가 준 방장 LAN 주소, 아니면 공인 주소. **버전** `NetLobby.Version` = `p<Protocol>-<데이터 지문>`이 다른 방은 "다른 버전"으로 잠겨 접속 자체를 하지 않고, 주소로 직접 들어와도 방장이 첫 인사에서 거절한다. 메시지 모양을 바꾸면 `NetLobby.Protocol`을 올린다. 다른 집에서 들어오려면 방장 공유기의 UDP 24680이 열려야 한다: 방장 게임이 UPnP로 자동 열기를 시도하고(`Net/PortOpener`) 방 화면에 결과를 보여 준다. 안 되면 공유기에서 포트포워딩을 한 번 해야 한다. 서버 계약은 Minidice `docs/LOBBY_SPEC.md`. `-- --lobby=URL`로 다른 목록 서버(로컬 검사)를 쓴다.

**실행**: 메뉴 → 멀티 → **방 만들기**(방장 창), 다른 창에서 주소(같은 PC면 `127.0.0.1`, 다른 PC면 방 화면의 `192.168.x.x` — `127.`로 시작하는 주소는 언제나 자기 PC) 입력 → **참가** → 방에서 파티원 [준비] → 방장 [시작]. 또는 `Start-Game.ps1 -NetHost` / `-NetJoin 127.0.0.1`, `Godot --path . -- --host` / `-- --join=주소`. UDP 24680. 접속에 실패하면 메뉴에 이유와 확인할 것(방 만들었는지·주소·방화벽)을 보여 준다. 목록에 방이 있으면 주소 입력 없이 방을 눌러 참가.

## 피격·처치 색 동기화 (2026-10-22, A-19·C-19)

일반 흰색/치명타 노란색을 파티원 화면에서도 구분하기 위해 `StageNet`의 `EnemyHit` 끝에 치명타 여부 U8(0/1), `EnemyDeath`의 힘 F32 뒤에 치명타 여부 U8(0/1)을 추가했다. `NetLobby.Protocol`은 5에서 **6**으로 올려 이전 빌드와의 혼합 참가를 차단한다. 방 목록/참가 버전은 기존 `NetLobby.Version` 경로를 따른다.

- `HitInfo.Crit`는 기존 판정 결과 그대로 전달한다. 이 변경은 원격 플레이어의 조준 집중 판정을 새로 구현하거나 피해량을 바꾸지 않는다.
- 같은 적의 같은 색 피격은 기존 80ms 이벤트 제한을 유지한다. 일반↔치명타 색이 바뀌면 제한 내라도 즉시 보낸다. 수신자는 피격 효과만 갱신하고 체력을 다시 깎지 않는다.
- 직접 명중이 체력을 0 이하로 깎으면 카드 명중 콜백 **전에** `CriticalDeath`를 저장한다. 이후 기존 특수 적의 `Die` 오버라이드와 풍선 Pop·시체 경로가 그 색을 공유한다. 수신은 `DieFromHit(direction, force, critical)`를 사용한다. 주변 카드 연쇄 피해까지 치명타로 바꾸지 않는다.
- 일반 피해·밀기·화상·직접 사망은 흰색이다. 원격 화상/밀기에서 원래 생략하던 피격 이벤트를 새로 추가하지 않는다. 기존 시야 숨김과 시체 공개 정책도 유지한다.
- 검사: `NetSyncCheck`의 실제 ENet 송수신에서 치명타 노란색, 다음 일반 피격의 흰색 복귀, 치명 처치 노란색 원을 확인한다. `NetCodecCheck`, `LobbyCheck`도 함께 실행한다. 실제 다른 PC·손실/지연 환경은 별도 검증 대상이다.

### 난전 카드 동기화의 팀 특별 카드 (2026-10-22, M-29 1단계)

- 방장이 파티원마다 보내는 난전 카드 동기화(`SurvivorRules.EncodeFor` → `StageNet.HostCards` → `ApplyCardSync`) 끝에 **팀 특별 카드 비트 U8**(`LabCards.SpecialMask`, 비트 n = `LabCards.Specials[n]`)을 더했다. 파티원은 `LabCards.SetSpecialsFromHost`로 받아 유리 대포의 최대 체력 절반을 자기 화면의 모든 생존자에 걸어 HUD 체력 막대가 방장과 같게 보인다(피해 계산은 그대로 방장). 특별 카드가 바뀌면 주기를 기다리지 않고 다시 보낸다.
- `NetLobby.Protocol`을 6에서 **7**로 올려 이전 빌드와 섞이지 않게 했다.
- 검사: `CardLabCheck`(특별 카드 비트), `OnslaughtNetCheck` · `NetSyncCheck` · `NetCodecCheck`(실제 송수신).

### 모두 멈춤 · 특별 카드 투표 (2026-10-22, M-29 2단계)

- 중간 보스가 쓰러지면 방장이 `SpecialVote.Begin` → `Stage.SetAllStop(true)`(트리 일시정지, 온라인도). 멈춘 동안 `SpecialVote` · `VoteWindow` · HUD · `StageNet`만 돈다(`ProcessMode.Always`).
- 방장 → 파티원: `StageNet.HostVote(byte[])`(신뢰 전송), 바뀔 때와 0.25초마다. 내용: 투표 번호 U16, 단계 U8(None이면 여기서 끝), 단계 남은 시간 F32, 투표 인원 · 투표한 수 U8, 카드별 도장 수, 이긴 카드(255 = 아직), 동률 카드 목록, 받는 사람이 투표자인지, **받는 사람 자신의 도장만**(255 = 없음), 카드 3장(`CardCatalog.Write`). 누가 어느 카드를 찍었는지는 보내지 않는다(무기명).
- 파티원 → 방장: `StageNet.ClientVote(serial, index)`. 방장은 투표 번호가 같고 투표자이고 아직 안 찍었을 때만 센다.
- 파티원은 단계가 None이 아닌 동기화를 받으면 멈추고, None을 받으면 풀린다. 이긴 카드는 방장에서만 적용(유리 대포의 체력 절반은 기존 특별 카드 비트로 파티원 화면에).
- `NetLobby.Protocol` 7 → **8**.
- 검사: `OnslaughtNetCheck`(실제 ENet). 한계 I-95(한 프로세스 검사, 멈춘 동안 소리 없음).
