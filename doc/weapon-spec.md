# 무기 데이터 규격 — 기본값·실데이터·특성

> **대상**: 사람과 AI 에이전트 모두. 무기를 추가하거나 수치를 바꿀 때 이 문서만 보면 됩니다.
> **데이터**: `game/content/data/`
> **로더**: `game/scripts/Weapons/WeaponDatabase.cs`
> **투척물·몬스터**는 `doc/throwable-monster-spec.md`, **이름(다국어)** 은 `doc/localization.md`를 보세요.
> **개편 1단계**(2026-10-21 구현): 타입별 이동속도·조준 칸, 3번 특수무기 칸, 우클릭/Ctrl 조준, 박격포 거치·회수, 레일건 충전은 아래 2·3·8장. 방향 전체는 [무기·모드·몬스터 개편 방향](mode-weapon-direction.md) 1~3장(C-24~C-27).

## 1. 파일 세 종류

| 파일 | 역할 | 형식 |
|---|---|---|
| `weapon_types.csv` | **분류 기본값.** 권총, 샷건, 돌격소총… 한 줄에 분류 하나 | CSV (엑셀로 열고 저장 가능, UTF-8) |
| `weapons.csv` | **실제 무기.** M4, AK47, 알라봉… **빈 칸은 분류 기본값을 그대로 사용** | CSV |
| `weapon_traits/<이름>.json` | **고유 특성.** 산탄, 폭발, 쌍권총, 근접 부채꼴, 점사, 투사체, 곡사처럼 표에 넣기 애매한 동작 | JSON (파일 하나 = 특성 하나) |

```
weapon_types.csv          weapons.csv                      weapon_traits/
type=assault_rifle  ◀──── m4,assault_rifle,M4,11,,,,       buckshot.json
  damage 10                  (빈 칸 → 분류 값)              rocket_warhead.json
  max_range 40 …          ak47,assault_rifle,AK47,7        dual_wield.json …
  traits = (없음)         m16,…,traits=burst_3 ───────────▶ burst_3.json
```

- CSV 첫 줄은 열 이름(영문)입니다. **`#`로 시작하는 줄은 주석**이고, 둘째 줄에 한글 설명을 넣어 두었습니다.
- 숫자는 소수점 `.`, 참거짓은 `true/false`(`1/0`, `y/n`도 가능), 무제한은 `inf`(`-`, `무제한`도 가능)입니다.
- **오타는 게임이 멈추지 않고 오류 목록으로 보고됩니다.** 예: `weapons.csv 5행 (m16): damage 값 'abc'는 숫자이(가) 아닙니다`. Godot 출력 창과 `./Start-Game.ps1 -Test`의 "weapon data loads without errors"에서 보입니다.

## 2. 열 목록 (분류·무기 공통)

| 열 | 의미 | 단위·값 |
|---|---|---|
| `type` | 분류 ID (weapons.csv에서는 어느 분류를 따를지) | weapon_types.csv의 type |
| `id` | 무기 ID (weapons.csv 전용, 코드·맵 배치에서 이 이름으로 찾음) | 영문 소문자 |
| `name` | **이름 키** (`name_weapon_<id>`). 실제 문구는 `content/lan/<언어>/weapon.csv` | |
| `slot` | 칸 | `1` 보조(근접·권총, **탄약 무제한**) / `2` 주무기 / `3` 특수무기(로켓런처·박격포·레일건, 탄약 더미로 충전 안 됨, C-25) |
| `category` | 분류(외형·발사음·화면 흔들림) | `melee pistol smg rifle lmg shotgun sniper heavy` |
| `fire_mode` | 발사 방식 | `melee` 휘두르기, `hitscan` 즉발 총알, `projectile` 날아가는 투사체, `lob` 곡사, `shout` 내 주변 밀쳐내기(꽥), `throw` 투척물 던지기(고무오리) |
| `automatic` | 누르고 있으면 연사 | `true` / `false`(클릭마다) |
| `damage` | 한 발 대미지. **산탄은 전탄 합계**, 로켓은 직격 대미지 | |
| `max_range_m` | 최대 사거리. 총알이 여기서 멈춤. 근접은 손이 닿는 거리 | m |
| `effective_range_m` | 유효 사거리. 여기까지 대미지 100%, 이후 최대 사거리까지 선형 감소 | m |
| `falloff_min` | 최대 사거리에서의 대미지 배율 | 0~1 |
| `fire_interval_ms` | 발사 간격 (근접은 휘두르는 간격) | ms |
| `reload_ms` | 탄창식 전체 재장전 시간 / 개별 장전식 첫 탄 삽입까지 시간 | ms |
| `reload_shell_ms` | 첫 탄 이후 한 발씩 추가 장전 간격. 0 또는 빈 값이면 탄창식 | ms |
| `mag_size` | 1탄창 총알 수 | |
| `max_mags` | 최대 탄창 수. 예비탄 최대치 = `mag_size × max_mags` | `inf` 무제한 |
| `start_mags` | 처음 주웠을 때 예비 탄창 수 | |
| `refillable` | 탄약 더미로 충전 가능 | `true/false` |
| `caliber` | 탄 종류(거점 배낭에서만 쓰임, M-25). 근접은 빈 칸 | `content/data/calibers.csv`의 id |
| `aim_view` | 조준할 때 화면이 커서 쪽으로 가는 정도(C-26). 소총 = 1(최대 26 m × 48%), 0 = 조준해도 그대로, 1을 넘으면 화면도 넓어져(넘은 만큼 × 0.8) 생존자가 화면 안에 남음 | 0~3. 샷건 0, 권총 · 기관단총 0.6, 경기관총 · 로켓 0.8, 소총 1, 레일건 1.3, 지정사수 1.6, 저격 1.7 |
| `pierce` | 한 발이 뚫고 지나가는 적 수(관통마다 대미지 ×0.8) | 1 = 관통 없음 |
| `spread_deg` `spread_per_shot_deg` `move_spread_deg` `max_spread_deg` | 퍼짐(조준원): **비조준** 기본, 발당 증가, 이동 중 추가, 최대 | 도 |
| `aim_spread_deg` `aim_time_s` | 다 조준했을 때 기본 퍼짐(≤ `spread_deg`), 비조준에서 거기까지 걸리는 시간(놓으면 두 배 빠름). 조준 중 발당 퍼짐은 절반, 이동 퍼짐 없음 (C-30) | 도, 초. 소총 6 → 1.2 · 0.45초 |
| `spread_recovery_dps` | 쏜 뒤 퍼짐이 줄어드는 속도 | 도/초. 기본 14~18 |
| `recoil_up` `recoil_side` `recoil_return` | **조준점 반동**: 한 발마다 화면 위로 / 좌우 ± 랜덤(1080 화면 픽셀), 멈추면 돌아오는 속도(픽셀/초). 최대 320 px (C-30) | M4 8 · 4 · 220, AK-47 11 · 9 |
| `recoil_power` | **반동 넉백 파워(쏜 사람).** 거리 대신 파워라 옵션으로 줄일 수 있음 (5장) | 권총 8, 샷건 60, 로켓 100 |
| `hit_power` | **피격 넉백 파워(맞은 적).** 몬스터 무게로 나뉨. 산탄은 맞은 펠릿 수만큼 나눠 들어감 | 소총 15(멈칫만), 샷건 90, 근접 60 |
| `traits` | 붙일 특성 이름, `;`로 구분. 무기 칸에서 `-이름`을 쓰면 분류에서 물려받은 특성을 뺌 | |
| `fire_sound` | 발사음 ID (doc/sound-spec.md). 빈 칸이면 category로 고름 | |
| `model` | 모델 경로(예: `res://assets/weapons/m4.glb`). 빈 칸이면 도형으로 만듦 | |
| `icon` | 아이콘 경로(예: `res://assets/icons/m4.png`). 하단 장비 HUD에 표시 | |
| `color` `accent_color` `length_m` | 도형 외형의 색과 길이 | |
| `noise_m` | 쏘거나 휘두를 때 이 반경 안의 대기형·경계형 몬스터가 깸 (`spawn-design.md` 2장) | 근접 4, 권총 14, 소총 20, 저격 26 |
| `move_speed_pct` | 이 무기를 들었을 때 이동속도 (8장) | % (기관단총 110, 경기관총·저격 85) |
| `aim_range_mult` | 조준 중 유효·최대 사거리 배율. 1 이상 | 볼트 저격 2, 돌격소총 1.5 |
| `aim_move_pct` | 조준 중 이동속도 (`move_speed_pct`에 곱함) | % (저격 30, 돌격소총 45) |
| `aim_focus_mult` | 조준 중 집중(치명타 준비)이 차는 속도 배율. 1 이상 | 볼트 저격 2.5 |
| `crit_mult` | 치명타 대미지 배율. 1 이상 | 기본 2.5, 볼트 저격 4, 지정사수 3 |

**합치는 규칙**: 무기 칸이 비어 있으면 분류 값을 씁니다. 분류에도 없으면 코드 기본값을 씁니다. `name, slot, category, fire_mode, damage, max_range_m, fire_interval_ms`는 둘 중 한 곳에 반드시 있어야 합니다.

## 3. 특성 (weapon_traits/*.json)

파일 이름이 특성 이름입니다. `kind`가 동작 종류이고, `description`은 사람용 메모입니다. 모르는 항목은 오류로 보고합니다.

| kind | 하는 일 | 항목 |
|---|---|---|
| `pellets` | **산탄.** 한 번에 여러 발이 원뿔로 퍼짐. `damage`·`hit_power`를 발 수로 나눔 → **다 맞으면 전부, 일부만 맞으면 그만큼만** | `count`, `spread_deg` |
| `explode_on_hit` | **타격 후 폭발.** 총알·로켓·포탄이 멈춘 자리에서 폭발 | `radius_m`, `damage`(폭발 대미지), `self_damage_share`(내가 맞을 때 비율), `knockback_power`(폭발 넉백) |
| `projectile` | 직선 투사체 (`fire_mode=projectile`에 필요) | `speed_mps`, `max_flight_ms` |
| `lob` | 조준점으로 곡사, 벽 너머 가능 (`fire_mode=lob`에 필요). 쏘기 전 거치·쏜 뒤 회수 동안 못 움직임 | `flight_ms`, `min_range_m`, `setup_ms`, `recover_ms` |
| `charge` | 방아쇠를 당기면 충전한 뒤 발사(레일건). 충전 중 조준선 표시, 끊기면 탄 반환 | `charge_ms` |
| `shout` | 내 주변 반경 안의 적을 밀쳐내고 피해(가운데일수록 셈, 겨눈 곳과 무관). `fire_mode=shout`에 필요(난전 꽥, 2026-10-21) | `radius_m`, `damage`, `knockback_power` |
| `throw` | 총알 대신 `throwables.csv`의 투척물을 조준점에 던짐. `fire_mode=throw`에 필요(난전 고무오리, 2026-10-21) | `throwable` |
| `burst` | 점사 | `count`, `interval_ms` |
| `melee_arc` | **근접.** 앞쪽 부채꼴 안의 적을 가까운 순서로 여러 마리 | `arc_deg`, `max_targets` |
| `dual_wield` | **쌍권총.** 같은 무기를 하나 더 주우면 쌍으로 바뀜 | `name_format_key`(언어 키, 기본 `fmt_weapon_dual`), `mag_multiplier`, `fire_interval_multiplier`, `spread_add_deg`, `recoil_multiplier` |

같은 kind의 특성이 둘이면 나중 것(무기 칸)이 이깁니다. 예: 더블배럴은 `-buckshot;buckshot_wide`로 9발 대신 14발 산탄을 씁니다.

### 쌍권총 처리

**쌍권총은 별도 무기가 아니라 "같은 권총 두 자루"입니다.** 권총 분류에 `dual_wield`가 붙어 있어서 모든 권총이 자동으로 쌍 버전을 가집니다.

- M1911을 들고 M1911을 또 주우면 **쌍 M1911**이 됩니다. 탄창 ×2, 발사 간격 ×0.6, 퍼짐 +1°, 반동 ×1.3이고, 수치는 `dual_wield.json`에서 바꿉니다.
- 글록을 들고 M1911을 주우면 쌍이 아니라 **교체**됩니다. 들고 있던 글록은 바닥에 떨어집니다.
- 특정 권총만 쌍을 막고 싶으면 그 무기의 `traits`에 `-dual_wield`를 씁니다.

### 근접 무기 처리

2026-10-20: 클릭 즉시 피해를 주지 않고, 준비 0.11초 → 0.17초 타격 → 0.23초 후속 동작 → 0.42초 복귀로 움직입니다. 오른손 파지점을 중심으로 무기와 팔이 함께 움직입니다. 피해는 타격 순간 한 번만 판정하며 거리·앞쪽 부채꼴·벽/소품 차폐를 다시 확인합니다. 기절·도약/회복 등 행동 차단·무기 교체·투척 조준·사망은 예약된 타격을 취소합니다. 최신 총기 수치와 조사 근거는 [전투 템포 조정](combat-pacing-research.md)을 기준으로 합니다.

**근접도 같은 표의 한 분류(`melee`)입니다.** 칸은 1번이라서 권총과 서로 교체됩니다(L4D2 방식).

| 열 | 근접에서의 의미 |
|---|---|
| `damage` | 한 번 휘두를 때 대미지 |
| `max_range_m` | 손이 닿는 거리 |
| `fire_interval_ms` | 휘두르는 간격 |
| `hit_power` | 맞은 적이 밀려나는 힘 |

부채꼴 각도와 한 번에 칠 수 있는 수는 `melee_arc` 특성에 있습니다. 탄약 관련 칸은 무시합니다. 새 근접 무기(야구방망이 등)는 weapons.csv에 `type=melee`로 한 줄 추가하면 됩니다.

## 4. 새 무기 추가 예

```csv
id,type,name,damage,...,traits,model,icon
scar,assault_rifle,SCAR-H,16,...,,res://assets/weapons/scar.glb,res://assets/icons/scar.png
```

1. `weapons.csv`에 한 줄을 추가합니다. 바꿀 칸만 채우고 나머지는 비워 둡니다.
2. 맵에 놓으려면 `StageOneLayout.cs`에 `Weapon(new Vector3(x, 0, z), "scar");` 한 줄을 추가합니다.
3. `./Start-Game.ps1 -Test`로 데이터 오류가 없는지 확인합니다.

## 5. 넉백 파워와 옵션

- 넉백은 **거리가 아니라 파워**입니다. 실제로 밀리는 속도 = `파워 × 0.08 m/s × 옵션 배율`이고, 땅에서 감속하므로 밀리는 거리는 대략 파워의 제곱에 비례합니다.
- 측정값: 권총(8) 약 1.5cm, 샷건(60) 약 1.1m, 로켓(100) 약 3m.
- 옵션 배율은 `GameSettings.RecoilScale`입니다(기본 1, 0이면 반동 넉백 없음). 메인 메뉴 **설정 → 사격 반동 밀림**(0~100%)이 이 값을 바꾸고 저장합니다.
- 적이 맞아서 밀리는 `hit_power`는 옵션의 영향을 받지 않습니다. 몬스터 무게로 나뉘고 짧은 멈칫도 걸립니다(`doc/throwable-monster-spec.md` 3장).

## 6. 재장전

R을 누르면 `reload_ms` 동안 장전합니다. 타이밍을 맞추는 액티브 리로드는 없앴습니다. 장전 중에는 이동 속도가 15% 줄고, 무기를 바꾸면 장전이 취소됩니다.

### 6.1 손·총 장전 모션 (2026-10-20)

현재 네 플레이어 종(거위·오리·라쿤·랫서판다)은 기존 손과 총을 움직이는 공통 절차적 모션을 사용한다. Blender 애니메이션이나 별도 골격은 추가하지 않는다.

| 방식 | 적용 범위 | 보이는 동작 |
|---|---|---|
| 탄창식 | 단일 권총·기관단총·소총·기관총·저격총의 hitscan 무기 | 총을 몸 앞에서 기울임 → 보조 손이 총 아래에서 허리 쪽으로 이동 → 탄창 쪽을 다시 만지고 짧게 총을 움직인 뒤 복귀 |
| 한 발 장전 | `ShellReloadTime > 0`인 hitscan 무기. 현재 R870·Benelli M4 | 총을 낮춰 기울이고 보조 손이 허리와 장전구 사이를 매 삽입 주기마다 왕복 |
| 이번 범위 밖 | 쌍권총·더블배럴·중화기 | 기존 장전 판정·기본 자세 유지. 전용 손 동작은 후속 작업 |

- `WeaponState.ReloadFraction`을 직접 샘플링한다. 첫 탄의 `reload_ms`와 후속 탄의 `reload_shell_ms`에 각각 맞추며 별도 애니메이션 타이머로 탄약을 넣지 않는다. 탄 수·장전 속도·사격 가능 시점은 변경하지 않았다.
- `WeaponController.Tick`의 탄 삽입·자동 장전·사격 취소 처리 **이후** 현재 상태를 자세에 전달한다. 장전 중 달리기 총 세우기를 억제하고, 실제 사격 시에는 먼저 장전 자세를 해제한 뒤 수평 총구로 발사한다.
- 일반 완료/취소는 약 0.083초 안에 모션 가중치를 복귀시킨다. 무기 교체·투척 전환·사망은 기존 파지로 초기화한다. 회피·구속·치료·기절 등 조작 차단 시 모션을 억제하며, 기존 장전 타이머의 진행/취소 규칙 자체는 바꾸지 않는다.
- 오른손은 손잡이를 유지하고, 왼손은 기존 `LeftGrip`의 손 메시를 이동시켜 쓴다. 매번 저장된 기본 변환에서 계산하므로 반복 장전으로 위치가 누적되지 않는다.
- 장전 접촉점은 총기 분류와 길이에 따른 기본값을 쓴다. 필요하면 무기 모델에 `ReloadContact` Node3D/Empty를 추가해 실제 탄창·장전구 접촉점을 지정한다. 임의의 새 무기에 손이 자동으로 정확히 맞는다는 보장은 없으므로 확대 확인이 필요하다.
- 현재는 **손으로 만지는 연출**이다. 탄창 메시를 실제로 빼고 끼우거나 산탄 실물을 손에 들지는 않는다. M249 역시 공통 동작이며 급탄 덮개를 여는 실총 동작은 아니다.

구현: `CharacterReloadPose.cs`, `CharacterWeaponGrip.cs`, `WeaponController.cs`. 검사: `ReloadPoseCheck`(네 종·기본형/체형 양끝·장비·손 연결·탄 보존·쉘 반복·자동 장전·중간 사격·차단/전환), `WeaponGripCheck`, `CombatPacingCheck`, `TailMeleeCheck`, `Integration`. 실제 렌더: `CaptureReloadPose` → `output/reload-{m4|r870}-{base|gear}-*.png`, `reload-gameplay-scale.png`, `reload-frames/*.png`(30fps 영상 인코딩용 프레임). `reload-preview.webm`은 이번 프레임을 별도로 인코딩한 로컬 비교 영상이다.

### 6.2 HUD의 탄약 부족·빈 탄창 표시 (현재 구현, 2026-10-20 확인)

**‘탄약 부족 [R]’는 현재 들고 있는 총의 탄창 잔탄 경고다. 예비탄이나 팀 전체 보급량을 판단하지 않는다.** 아래는 현행 코드의 기록이며, 최종 UX 기준으로 새로 확정하거나 동작을 변경한 것이 아니다.

근거: [Hud.cs](../game/scripts/UI/Hud.cs)의 `_Process`와 `DrawReticle`, [한국어 문구](../game/content/lan/kor/ui.csv), [영어 문구](../game/content/lan/eng/ui.csv).

```text
경고 기준 발수 = max(1, floor(현재 무기의 MagSize / 6))
탄창 부족 조건 = 근접 무기가 아님 AND Mag <= 경고 기준 발수
```

`MagSize`는 정수이므로 코드의 `/ 6`은 정수 나눗셈이다. 약 16.7% 기준이지만 반올림하지 않고, 작은 탄창에는 최소 1발 조건이 적용된다. 임계값은 `Hud.cs`에 직접 적혀 있으며 별도의 CSV/JSON 설정 키는 없다.

| 위치 / 상태 | 현재 동작 |
|---|---|
| 하단 탄약 표시 | 탄창 부족 조건이면 `UiTheme.Danger` 색. 장전 중에도 같은 잔탄 조건으로 색을 정함 |
| 조준점, 장전하지 않음, `1 <= Mag <= 기준` | `ui_hud_ammo_low`: **탄약 부족 [R]** / `Low ammo [R]` |
| 조준점, 장전하지 않음, `Mag == 0` | `ui_hud_mag_empty`: **탄창 비었음 [R]**. 부족 문구보다 우선 |
| 조준점, 장전 중 | 위 문구 대신 장전 진행 표시 |
| 근접 무기 | 탄창 부족 경고 대상 아님 |
| 사망·쓰러짐·비플레이 상태·일시정지 | 조준점 그리기를 생략하므로 해당 문구도 없음 |
| 투척 조준이며 착탄 미리보기가 있음 | 투척용 조준점만 그리고 총기 경고 문구는 생략 |

| 탄창 용량 | ‘탄약 부족’이 뜨는 잔탄(장전 중 제외) | 0발일 때 |
|---:|---|---|
| 60발 | 1~10발 | 탄창 비었음 |
| 50발 | 1~8발 | 탄창 비었음 |
| 40발 | 1~6발 | 탄창 비었음 |
| 15발 | 1~2발 | 탄창 비었음 |
| 10발 | 1발 | 탄창 비었음 |
| 2발 | 1발 | 탄창 비었음 |
| 1발 | **가득 찬 1발도 해당** | 탄창 비었음 |

예비탄이 많거나 무제한인 권총도 탄창이 적으면 표시한다. 반대로 탄창이 기준보다 많으면 예비탄 0발이어도 이 경고는 뜨지 않는다. 경고 조건은 실제 재장전 가능 여부를 확인하지 않으므로, 예비탄이 없어 R로 장전할 수 없어도 `[R]` 안내가 남을 수 있다. 이 두 표현상 한계와 1발 탄창 예외는 후속 UX 검토 대상이며 이번 문서 작업에서 고치지 않았다.

**AI 보급 판단과 구분**: [SquadBrain.cs](../game/scripts/Squad/SquadBrain.cs)의 `PickupWanted`는 충전 가능한 유한 예비탄 주무기에 대해 `ReserveMax > 0`이고 `Reserve < ReserveMax × ammo_low`일 때 탄약 보급 후보를 찾는다. [squad_rules.json](../game/content/data/squad_rules.json)의 `ammo_low`는 현재 `0.3`, 즉 **예비탄 최대치의 30% 미만**이며 정확히 30%는 포함하지 않는다. 실제 줍기는 거리·접근 가능성 등 추가 조건을 따른다. 이 설정은 플레이어 HUD 임계값이 아니다.

HUD에는 현재 모드별 임계값 분기가 없다. 여기서는 공용 코드의 현행 표시를 설명하며, [시나리오 레벨 디자인](scenario-level-design.md)의 보급 예산을 다른 모드에 적용하라는 뜻이 아니다. 시나리오 보급 평가는 이 문구의 등장 횟수만 세지 말고 탄창·예비탄·다음 보급까지의 소비를 따로 기록한다.

검토 방법: 코드 조건·언어 키·임계 발수 예시 대조. 게임 실행·실제 HUD 렌더 검증은 이번 문서 작업에서 수행하지 않았다. 후속 변경 시 기준 발수 바로 위/동일/아래, 0발, 예비탄 0/충분/무제한, 1발 탄창, 근접·장전·투척 전환을 함께 확인한다.

### 6.3 무기 발사·근접 시각 효과 (2026-10-22, A-19)

참고 영상의 **짧고 선명한 섬광·잔상** 방향으로, 2026-10-21 M4 1차 적용에 이어 2026-10-22 사용자 요청으로 다른 무기까지 확장했다. Blender 모델이나 외부 텍스처 없이 Godot 면·메시와 절차적 셰이더로 그린다. 아래 수치는 현재 **아트 조정값**이며 실제 탄속·무기 밸런스가 아니다.

| 분류 | 총구 지속(ms) | 총구 길이 × 폭(m) | 잔상 이동(m/s) | 잔상 최대 길이(m) | 잔상 면 폭(m) |
|---|---:|---:|---:|---:|---:|
| 권총·쌍권총 | 45 | 0.45 × 0.32 | 125 | 1.7 | 0.065 |
| 기관단총 | 35 | 0.50 × 0.30 | 150 | 2.0 | 0.055 |
| 소총(M4 포함) | 55 | 0.70 × 0.50 | 160 | 2.8 | 0.075 |
| 경기관총 | 45 | 0.80 × 0.50 | 175 | 3.0 | 0.075 |
| 산탄총 | 70 | 1.05 × 0.85 | 140 | 1.5 | 0.045 |
| 지정사수(`TypeId=dmr`) | 55 | 0.85 × 0.48 | 200 | 3.5 | 0.075 |
| 볼트 저격 | 65 | 1.05 × 0.55 | 220 | 4.5 | 0.090 |
| M82 | 80 | 1.30 × 0.70 | 240 | 5.0 | 0.110 |
| 레일건(충전 히트스캔) | 70 | 0.85 × 0.65 | 즉시 전체 빔 | 기존 판정 경로 | 0.200에서 감쇠 |
| 알라봉 | 85 | 1.05 × 0.70 | 실제 로켓 유지 | 별도 탄 잔상 없음 | — |
| 박격포 | 85 | 0.85 × 0.75 | 실제 곡사탄 유지 | 별도 탄 잔상 없음 | — |

- 일반 총구는 흰 중심·노란 가장자리의 앞 불꽃과 짧은 옆 불꽃. 총구 크기·빛은 빠르게 감쇠한다. 발사 1회당 반경 2.2 m의 그림자 없는 조명 **1개**만 켜고, 산탄은 첫 탄에만 섬광·조명을 붙여 여러 펠릿의 빛이 중첩되지 않게 한다. 기존 넓은 공용 총구 조명은 제거했다. 쌍권총은 실제로 발사한 좌우 총구를 번갈아 사용한다.
- 일반 탄 잔상은 첫 표시부터 머리가 최대 0.9 m 앞에서 출발하고 실제 명중 끝점에서 잘린다. 가까운 거리·0에 가까운 거리에서도 끝점을 넘기지 않는다. 로컬 치명타는 폭 ×1.27 및 밝기 강조. 레일건은 청백색 전체 빔이 0.18초 동안 폭·밝기를 줄이며 사라진다. 각 빔의 감쇠 재질은 독립적이다.
- 근접은 중심이 빈 청백색 초승달 잔상이다. 48분할의 끝이 가늘어지는 띠(정규화 반경 약 0.83~1)에 무기의 사거리·각도를 적용한다. 오른쪽에서 왼쪽으로 진행하고 0.16초 뒤 소멸한다. 로컬은 기존 0.17초 타격 시점에 생성하며 준비·후속 자세와 피해 타이밍은 유지한다.
- 알라봉·박격포는 발사 섬광만 추가하고 실제 투사체·폭발을 유지한다. 꽥·고무오리는 기존 고유 연출을 유지하며 총기용 섬광·탄 잔상을 붙이지 않는다. 피격·사망은 [캐릭터 규격 8.1](character-model-spec.md#damage-effects)에서 같은 방향으로 적용했고, 체력 UI 개편은 별도 후속 범위다.
- 모든 새 효과는 월드 깊이 검사를 유지한다. 명중·피해·탄약·사거리·퍼짐·반동·발사 간격·소리는 기존 로직대로 처리하며, 시각 효과가 충돌이나 지연 피해를 만들지 않는다. 로컬/AI 및 `ShowNetShot` 수신 경로에 연결했고 패킷은 변경하지 않았다.
- **기존 멀티 제약**: 발사 `Shot` 패킷에는 치명타 표시가 없어 수신 화면의 탄 잔상은 일반 밝기다. 피격 대상의 몸·선·사망 원 색상은 별도 `EnemyHit`/`EnemyDeath` 이벤트의 치명타 표시로 동기화한다(프로토콜 6). 근접 `Shot` 이벤트는 준비 시작에 전송되고 수신 화면은 즉시 잔상을 그리므로 로컬의 0.17초 타격 표시와 어긋날 수 있다. 이 타이밍 계약은 이번 외형 변경에서 수정하지 않았고, 다른 PC에서의 실측·취소 동기화는 미검증이다. 6인 장시간 렌더 부하도 별도 검증이 필요하다.
- 코드: [WeaponShotEffect.cs](../game/scripts/Effects/WeaponShotEffect.cs), [weapon_shot.gdshader](../game/shaders/weapon_shot.gdshader), [MeleeSwingEffect.cs](../game/scripts/Effects/MeleeSwingEffect.cs), [melee_sweep.gdshader](../game/shaders/melee_sweep.gdshader), [WeaponController.cs](../game/scripts/Weapons/WeaponController.cs).
- 재검사: `WeaponEffectsCheck.tscn`(헤드리스 + 창 모드, 전 무기 표시·로컬 산탄/점사/쌍권총/근접/특수), `RifleEffectsCheck.tscn`(즉시 피해·끝점 제한·연사 소멸), `TailMeleeCheck.tscn`, `CombatPacingCheck.tscn`, `WeaponHandlingCheck.tscn`, `NetSyncCheck.tscn`, `Integration.tscn`. `WeaponEffectsCheck` 창 모드는 `output/weapon-fx-*.png`를 만든다. 고정한 표시 시간과 합성한 명중 끝점으로 비교하는 실제 엔진 렌더이며 플레이 녹화는 아니다. M4 1차의 `output/rifle-fx-*.png`, `rifle-fx-frames/` 출력도 유지한다.

### 6.4 장전/충전 진행 UI (M-33)

2026-10-27 구현. [영상 관찰·설계](features/menu-ui/reload-ui-design.md), [작업·검사 기록](features/menu-ui/log/001-code-reload-progress-ui.md).

- 장전 시 일반 조준 눈금/가운데 점/외곽 퍼짐 눈금/조준선은 약0.16초에 제자리에서 사라진다. 고정 반경19px 진행 링이 나타나고, 종료 시 약0.20초에 복귀한다. 링 주변 장식 네 점은 표시하지 않는다(2026-10-27 의미 없는 장식 제거). 집중 호는 겹쳐 그리지 않으며 실제 명중 표시는 유지한다.
- 하단 장비 도크 위: 248×22px 둥근 반투명 트랙, 선명한 청백색 채움과 청색 그림자, `장전 중 · N%`/`발사 준비 · N%`/`재충전 중 · N%`(14px). 상태이상 아이콘은 게이지가 보일 때 70px 위로 이동해 겹침을 피한다. 상호작용/상태 문구 위치는 유지한다. 탄약 영역의 장전/재충전 문구는18px 중립색으로 낮추고 평상시28px 탄약 숫자와 부족탄 빨간 경고를 유지한다.
- 같은 `WeaponActionFeedback.Progress`가 링·막대·퍼센트를 구동한다. 장전은 `ReloadFraction`, 레일건/박격포 준비는 `WindupProgress`, 난전 특수무기는 `1-CooldownLeft/ShotCooldown`. 진행률 자체에는 지연 보간을 적용하지 않는다.
- 진행 중 숫자는 최대99%. 정상 완료만100%로 퇴장하며 취소는 마지막 값으로 사라진다. `WeaponState.ReloadCompleted`는 최종 탄 삽입 시 설정하고 다음 장전/취소 때 지운다. 완료 틱에 바로 사격해서 탄수가 그대로여도 완료를 놓치지 않는다. 탄창이 가득 차지 않아도 예비탄 소진으로 장전이 끝나면100%다.
- 한 발씩 장전은 각 삽입 주기가0→100%이고 다음 탄에서0으로 돌아간다. 중간 사격/교체의 기존 규칙은 유지한다. 무기 교체 시 이전 UI 상태는 즉시 초기화한다.
- 사망/쓰러짐/일시정지/전체 정지/배낭/카드창/투척 조준 중에는 이 진행 UI를 숨긴다. UI가 무기 타이머나 사격 가능 시점을 바꾸지 않는다.
- 리소스: `HudWeaponAction.cs`의 Godot 벡터 도형과 공유 `StyleBoxFlat`(`ActionTrack`, `ActionFill`). 별도 PNG/GLB/셰이더/외부 의존성 없음. 트랙 알파0.62, 채움0.98, 링 고리0.48(두께11px), 링 중심0.98(두께3.2px), 채움 그림자 크기10px·알파0.65. 링 번짐은10겹의 넓은 저알파 호와5px 색 호로 만든다. 점프 게이지는 같은 함수의 주황 번짐을 쓴다. 전체3D bloom은 바꾸지 않는다. 모두 최종 UI 수락 전 제작값이며 [외형 보강 기록](features/menu-ui/log/002-code-hud-light-polish.md), [장식 제거·조준 정리 기록](features/menu-ui/log/003-code-reticle-clarity.md)에 검사와 제약을 남긴다.

## 7. 손잡이와 팔 연결 (2026-10-20)

게임용 무기는 `WeaponVisual.Built`의 `RightGrip`/`LeftGrip`으로 손 위치를 제공한다. `CharacterRig.BindWeaponGrip`은 모델의 정적인 `leftArm`/`rightArm`을 숨기고, 어깨에서 손잡이까지 짧고 납작한 날개·앞발을 연결한다. 일반 총은 몸 오른쪽에서 한 손으로 들며 반대 날개는 몸 옆에 둔다. 쌍권총과 중화기는 양손을 쓴다. 이동/반동/시각적 변형/도약 뒤에 연결을 갱신한다. 무기가 숨겨진 투척 조준 중에는 이 날개·앞발도 숨긴다.

일반 총을 들고 달리면 총구를 위로 들어 올리고 빈 날개를 옆으로 벌린다. 발사 입력이 들어오면 총구를 즉시 수평으로 내린 뒤 발사 처리를 한다. 메뉴의 서 있기/달리기/사격 자세 버튼으로 비교할 수 있다.

무기 GLB에 `GripRight`, `GripLeft` Node3D(Blender Empty)를 추가하면 그 위치를 우선 사용한다. 없으면 현재 총기 생성 도구의 손잡이·앞손잡이 위치와 길이에 맞춘 분류별 기본값을 사용한다. 쌍권총은 각 총의 독립 손잡이를 사용하고, 근접 무기는 한 손만 연결한다. 손과 아래팔은 캐릭터의 커스텀 색을 따른다. 바닥에 놓인 무기에는 손이 생성되지 않는다.

이 방식은 현행 뼈 없는 캐릭터 구조의 절차적 자세다. 손·총 장전 동작은 6.1절까지 구현했고, 개별 손가락 조작·실제 탄창 메시 교체·임의 길이/체형에 맞춘 두 관절 IK는 별도 작업이다. 현재 네 종의 지원 체형 범위에 맞춰 검사한다. 모델의 팔 위치를 바꿀 경우 `CharacterWeaponGrip.Connect`의 어깨 기준도 맞춰야 한다.

검사: `res://tests/WeaponGripCheck.tscn` (4종 × 7무기, 반동/도약, 숨김, 쌍권총), 시각 검증: `res://tests/CaptureWeaponGrip.tscn` → `output/weapon-grip-*.png`.

## 9. 폭발 외형 공통 데이터 (2026-10-24, A-19)
